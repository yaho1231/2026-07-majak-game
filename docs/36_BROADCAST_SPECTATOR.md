# 36. 대회 중계 관전 시스템 — 기능 조사와 계획

작성 2026-08-19. **아직 아무것도 구현하지 않았다** — 무엇을 만들지 고르기 위한 목록이다.
사용자가 번호를 고르면 그때 붙인다.

목표: 지금의 «관리자 관전»(방 코드로 들어가 전 손패를 보는 화면)을 **대회 중계에
쓸 수 있는 도구**로 올린다. 해설자가 판을 읽을 수 있어야 하고, 운영자가 판을 세우고
말을 걸 수 있어야 하며, 완전정보 화면이 부정행위 통로가 되지 않아야 한다.

## 2. 중계로 쓰면 바로 걸리는 곳

- 하단 시점이 **현재 오야로 고정**이라 보고 싶은 좌석을 못 고른다 ([App.tsx:11098](../packages/client/src/App.tsx#L11098)).
- 오름패 **남은 장수는 하단 좌석 하나만** 계산한다 — 나머지 셋은 패만 뜨고 두께를 모른다
  (`remainingCounter(view, me.id)`, [App.tsx:11118](../packages/client/src/App.tsx#L11118)).
- 관전 UI가 `👁 관전 중 — 방 XXXX` 띠 한 줄뿐이다 ([App.tsx:11215](../packages/client/src/App.tsx#L11215)).
- 대국자는 자기 판이 중계되는지 모른다. 관전 접속 감사 로그도 없다.
- 일시정지가 없다. 지금 판을 멈추는 유일한 손잡이는 **강제 종료**뿐이다.

## 4. 권하는 순서

1. **D1 + A1 + A3** — 하루치. 화면이 즉시 중계처럼 보인다.
2. **B1 일시정지** — 제일 무겁지만 운영에 없으면 곤란하다.
3. **C1 딜레이 + C3 감사 로그** — 부정행위 통로를 막는다.
4. **A5 증강 패널 + A6 이벤트 로그** — 해설 재료.

## 5. 진행 기록

### 1차 — D1 + A1 + A3 (2026-08-19, ✅)

- **D1 아래 자리 고르기** — 관전 띠에 `오야 / 차례 / 좌석 고정` 단추. 기본은 예전
  그대로 오야를 따라간다. 띠는 `pointer-events: none`을 유지하고 단추 묶음만
  되살려, 카메라를 옮기는 손잡이가 판을 가리지 않게 했다.
- **A1 좌석별 오름패** —
  - 코어: 관전 뷰(`SPECTATOR_ID`)가 **네 좌석 모두** 후리텐·일발·형식텐파이·
    역없는 대기를 받는다. 예전에는 `pid === viewerId`에 걸려 전부 비어 있었다
    (`buildRoundView`). 합류 직후 첫 뷰에도 `yaku`를 실어 깜빡임을 없앴다.
  - 클라: 남은 장수를 **그 좌석 기준**으로 다시 센다. 판 전체가 쓰는 셈은 하단
    좌석 하나 기준이라, 남의 오름패 옆에 붙이면 «남의 손패는 빼고 하단 좌석의
    손패는 넣은» 아무의 것도 아닌 숫자가 된다.
  - 차례가 온 좌석(14장)도 오름패가 꺼지지 않는다 — 떨어져 쥔 쯔모패를 빼고 잰다.
  - 계산해서 아는 오름패는 「간파」가 아니라 **「오름패」**로 적고 색을 가른다.
- **A3 샹텐 뱃지** — 텐파이가 아닌 좌석에 `N샹텐`. 14장이면 한 장 버린 뒤의 최선.

검증: `npm test` 전체 통과(회귀 가드 추가 — `packages/core/test/PlayerView.test.ts`,
`packages/client/test/broadcastSpectator.test.ts`), 타입체크 4종 에러 0.

**아직 실제 대국을 띄워 눈으로 본 것은 아니다** — 정적 가드와 빌드까지다.

## 6. 정해야 할 것

- 일시정지 중 **봇**은 어떻게 두나 — 함께 세운다(권장) vs 그냥 진행.
- 딜레이를 켜면 관전자 화면과 대국자 화면이 어긋난다. 해설과 현장 소리를 어떻게 맞출지.
- 관전 권한을 계정 속성으로 둘지, 대회(방) 단위 초대로 둘지.
