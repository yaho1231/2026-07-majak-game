  렌더한 **뒤에야** 홀드를 보낸다 — 그래서 홀드는 구조적으로 언제나 늦었고, 늦게 온 홀드는 이미

  좌석으로 나갈 때마다 서버가 스스로 `TUTORIAL_HOLD_GRACE_MS`(700ms) 유예를 걸고, 클라이언트의

  **결과**: `holdRace` 계측이 **0ms 17구간 / 60ms 46구간 모두 샌 구간 0개**(고치기 전 각각 5/9, 7/14).

## RoomManager.test.ts 플레이크 — 예전 기록이 틀렸다 (2026-08-08 정정)

이 문서는 오랫동안 **"파일 단독 실행에서는 항상 통과한다"**고 적어 두었다. **사실이 아니다.**
단독 실행에서도 49건 중 1~5건이 `waitFor timeout` / `Test timed out`으로 터지고, **터지는
집합은 매번 다르다.** 코드 변경이 전혀 없는 커밋(`b2f868c`)에서도 재현된다. 이 잘못된 문장 탓에
"단독으로 돌려 보고 통과하면 내 변경 탓이 아니다"라는 판별법이 헛돌았다.

실측(2026-08-08, `c391192`, 8코어 맥, 단독 실행 6~8회 반복):

| 상황 | 결과 |
|---|---|
| 수정 전, 단독 반복 6회 | 2회 실패 (1건씩, 매번 다른 테스트) |
| 수정 후, 단독 반복 6회 | **0회 실패** (실행 시간 116~356초로 흔들려도 통과) |
| 사람 1 + 봇 3 반장전 **한 판의 실제 비용** | 유휴에 가까울 때 **13~17초** |
| 같은 판, 다른 vitest가 함께 도는 동안(로드 18 / 8코어) | **31~45초** |
| 그때 걸려 있던 `waitFor` 예산 | **20초** (일부 30·40초) |

### 원인 두 가지 (둘 다 고쳤다)

1. **테스트가 서버를 안 껐다** — `RoomManager.test.ts`의 `afterEach`가 임시 디렉터리와 DB만
   정리하고 `RoomManager`는 그대로 두었다. 판 도중에 끝나는 테스트(관전·재접속·킥 등)가 남긴
   봇 반장전이 **같은 이벤트 루프 안에서 계속 돌아**, 뒤 테스트의 CPU를 나눠 가졌다.
   계측으로 확인: 죽은 테스트가 도는 동안 **남의 진행 중 게임이 1개 살아 있었다.**
   → `afterEach`에서 `shutdown()` + `stop()`.

2. **예산이 원가에 너무 붙어 있었다** — 한 판이 13~17초인데 예산이 20초였다. 유휴 상태에서도
   여유가 20%뿐이라 조금만 부하가 붙으면 넘어갔고, 어느 판이 먼저 넘어갈지는 무작위였다
   (= 실패 집합이 매번 다른 이유). → `HANCHAN_MS = 90초` 상수 하나로 모았다. 이건 "느려도
   봐준다"가 아니라 한 판의 실제 원가다. 정말로 멈춘 판은 여전히 실패한다.
   (`국 사이 대기` 테스트의 의미는 그대로다 — ack가 없으면 국마다 30초 × 최소 7국 = 210초가
   넘으므로 90초 예산으로도 ack 배선을 증명한다.)

### 배제한 것들

- **다른 브랜치·다른 코드 탓이 아니다.** 변경이 전혀 없는 `b2f868c`에서도 재현된다.
- **`.claude/` 워크트리를 긁는 문제가 아니다.** `vitest.config.ts`가 이미 제외한다.
- **테스트 간 상태 공유(DB·임시 디렉터리) 탓이 아니다.** 하니스마다 `:memory:` DB와 새
   `mkdtemp` 디렉터리를 쓴다. 실패는 항상 타임아웃이지 단정 실패가 아니다.
- **서버 코드의 데드락이 아니다.** 실패한 판도 예산만 늘리면 끝까지 간다(같은 테스트가 다음
   실행에서 15초에 통과한다).
- **남는 변수 하나: 머신 부하.** 이 맥에서는 다른 세션의 `npm test`가 동시에 돌면 로드가
   8코어에 18까지 오른다. 그건 테스트가 고칠 수 있는 문제가 아니다.
   확인법: `ps -Ao pcpu,comm -r | head` (프로세스 이름이 `node (vitest N)`이라 `pgrep -f bin/vitest`로는 안 잡힌다).

## 게이트 기준

실패 수·타입 에러 수가 위 수치보다 **늘었으면 병합 금지**. 위 Sandbox 플레이크 1건은 예외.

실패가 나면 **먼저 그 파일만 단독으로 다시 돌린다.** 다만 `RoomManager.test.ts`는 단독
통과가 무죄 증명이 **아니다**(위 정정 참고) — 같은 실패가 두 번 연속 같은 테스트에서 나야
결함으로 본다.

## 측정 환경 함정 (중요)

이 기준선은 한때 "87 실패 / 타입 에러 8"로 잘못 기록돼 있었다. 둘 다 **측정 환경 문제였고 코드에는 문제가 없었다.** 같은 함정에 다시 빠지지 않도록 기록해 둔다.

1. **vitest가 워크트리까지 긁었다.** 설정 파일이 없어 기본 exclude에 `.claude/`가 빠져 있었고, `.claude/worktrees/` 아래 사본 10개의 테스트를 전부 실행했다 — 테스트 파일 99 → 981개, 165초 → 879초. 사본들이 같은 임시 디렉터리 이름을 동시에 써서 `ENOTEMPTY`로 무관한 파일이 줄줄이 실패했다. → 루트 `vitest.config.ts`에서 `**/.claude/**` 제외.
2. **워크트리에서 잰 타입체크는 낡은 코드를 봤다.** 워크트리에 `node_modules`가 없어 `@majak/core`가 상위 `<저장소 루트>/node_modules/@majak/core` 심볼릭링크로 해석됐고, 그 시점 메인 체크아웃은 `c45dbab`(구 커밋)에 서 있었다. 그래서 `RoundSettledPayload.dealerContinues` 처럼 **실제로 존재하는** 필드가 "없다"고 나왔다.

교훈: **메인 체크아웃은 항상 master에 두고, 측정은 메인 체크아웃에서 한다.** 메인 체크아웃은 서버가 서빙하는 코드이기도 하므로 다른 브랜치로 옮기면 배포까지 함께 어긋난다.

## 갱신 방법

메인 체크아웃에서 `npm test` 와 `npm run typecheck:*` 를 다시 돌리고 이 문서를 덮어쓴다.
