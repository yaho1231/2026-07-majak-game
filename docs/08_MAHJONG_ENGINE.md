# 08_MAHJONG_ENGINE
Version : 1.0
Status : Active
Last Updated : 2026-07-15

리치마작 도메인 로직: 패 분해, 텐파이, 화료 판정, 역, 부·판, 점수.
구현: `packages/core/src/mahjong/scoring/`

모든 함수는 **순수 함수**이고, 패의 **현재 kind·attrs만** 본다 (Issue 002 원칙).
GameState를 직접 알지 못한다 — Game Flow(11)가 상태에서 입력을 뽑아 호출한다.

# 1. 파일 구성

| 파일 | 역할 |
|------|------|
| `decompose.ts` | 손패 → 분해(4멘쯔1작두 / 치토이 / 국사) 전체 열거 |
| `waits.ts` | 텐파이 여부·대기패 계산 |
| `WinContext.ts` | 화료 문맥(WinContext)과 채점 변형(ScoringVariant) 생성 |
| `YakuRegistry.ts` | 역의 **등록형** 관리 (추가·제거 가능) |
| `standardYaku.ts` | 01_GAME_RULES의 표준 역 전체 — 등록 API의 첫 사용자 |
| `fu.ts` | 부 계산 |
| `score.ts` | 판·부 → 점수 (지불 분배 포함) |
| `dora.ts` | 도라 표시패 → 도라, 도라 수 계산 |
| `evaluate.ts` | 전체 조립: 최고 해석 선택 → 역·판·부 확정 |

# 2. 분해와 채점 변형 (ScoringVariant)

같은 손패라도 해석이 여러 개다 (`111222333m` = 암각 3개 or 순자 3개).
**모든 분해를 열거하고, 화료패가 어느 묶음을 완성했는지 조합까지 곱해**
변형(Variant)을 만든 뒤, 각각 채점해서 최고를 채택한다.

변형이 답하는 것:

- 대기 형태: 양면 / 간짱 / 변짱 / 단기 / 샹퐁 (핑후·부 계산에 필요)
- 암각 여부: **론으로 완성된 커쯔는 명각 취급** (산안커·스안커·부 계산의 핵심)
- 멘젠 여부: 부로 없음 (안깡은 멘젠 유지)

비교 순서: `역만 수 > 판 > 부`. 역만이 하나라도 성립한 변형에서는 일반 역을 세지 않는다.

# 3. 역 시스템 — 역도 등록형이다

```ts
interface YakuDef {
  id: string;            // "tanyao"
  name: string;          // "탕야오"
  closedHan: number;     // 멘젠 판수
  openHan: number | null;// 부로 시 판수. null = 부로 시 성립 불가
  isYakuman?: boolean;
  check(variant, ctx): boolean;   // 순수 함수
}
yakuRegistry.register(def);       // 표준 역도, 증강의 새 역도 같은 문으로
yakuRegistry.remove("tanyao");    // 제거 후 교체 등록 = 역 조건 변경
```

- **표준 역 40여 개가 이 API의 첫 사용자다** — 증강이 쓸 문과 같은 문을 쓴다.
- "울어서 국사무쌍(역만 아님)" 증강 = 기존 def를 remove하고 완화된 def를 register.
- 배타 관계는 check 안에서 구조적으로 처리한다
  (량페코 성립 시 이페코 false, 준찬타 성립 시 찬타 false 등).
- 도라는 역이 아니다 — 역이 1판 이상일 때만 별도로 가산된다.

## 표준 역 구현 메모 (01_GAME_RULES의 목록 기준)

- 역패는 종류별 개별 def (장풍·자풍·백·발·중) — 연풍패는 자연히 2판이 된다.
- 찬타·준찬타는 순자 1개 이상을 요구한다 (혼노두와의 중복 방지, 통례).
- 혼일색은 자패 1장 이상을 요구한다 (청일색과 배타).
- 더블리치는 리치를 대체한다 (동시 성립 없음).
- 역만: 더블 없음, 복합 합산 (01 §6 확정).

# 4. 부 계산 (fu.ts)

표준 규칙 그대로: 기본 20 + 멘젠론 10 + 쯔모 2(핑후 제외) + 멘쯔·작두·대기 가산,
치토이 25 고정, 부로 핑후형 론 30 보정, 10부 올림.
작두가 연풍패면 +4 (자풍+장풍 각 +2).

# 5. 점수 (score.ts)

`base = 부 × 2^(2+판)`, 만관 이상은 01 §7의 표. 절상 없음, 셈수 역만 있음.
지불: 론 = 방총자 전액(친 ×6, 자 ×4), 쯔모 = 분담(친 화료 ×2씩, 자 화료 친×2 자×1),
100점 올림. 본장·공탁은 여기서 다루지 않는다 (11의 몫).

# 6. 도라 (dora.ts)

표시패의 **다음 패**가 도라 (9→1, 북→동, 중→백 순환). 적도라는 attrs.red 수만큼.
우라도라는 리치 화료 시에만. 모두 evaluate에서 판에 합산된다.

# 7. 확장 시나리오 점검

| 증강 아이디어 | 구현 | 엔진 수정 |
|---------------|------|-----------|
| 새로운 역 추가 | `yakuRegistry.register` | 없음 |
| 역 조건 제거/완화 | `remove` 후 교체 등록 | 없음 |
| 판수 변경 (탕야오 2판) | def 교체 (또는 Rule화 예정) | 없음 |
| 5번째 패로 대기 | waits의 universe 파라미터에 kind 추가 | 없음 |
| 점수 배율 증강 | score 결과에 Effect가 가산 이벤트 | 없음 |

## 알려진 한계 (필요 시 개선)

- 역별 판수가 def 상수라서 "특정 역만 판수 변경"은 def 교체가 필요하다.
  빈도가 높아지면 판수를 RuleRegistry로 승격한다 (`yaku.<id>.han`).
- 후리텐 판정은 여기가 아니라 Game Flow(11)에서 버림 기록으로 검사한다.
