# 24. 증강 연출 랩 (FX Lab) — 프로토타입

증강 하나하나에 어울리는 웹 연출을 **실제로 돌려보고 고르기 위한** 독립 페이지다.
게임 클라이언트(`packages/client/src/App.tsx`)와 완전히 분리된 정적 파일들로만 이루어져
번들에 들어가지 않는다. 실패해도 게임에 영향이 없고, 마음에 드는 연출만 골라
클라이언트로 옮기면 된다.

## 파일

전부 `packages/client/public/` 아래에 있다.

| 파일 | 역할 |
| --- | --- |
| `fx-lab.html` | 무대 마크업 + 공용 SVG 필터(`#fInk` `#fGoo` `#fFog` `#fVein`) |
| `fx-lab.css` | 무대·패·카드 스타일 (게임과 같은 색 언어) |
| `fx-core.js` | 런타임: 좌표계, WAAPI 래퍼, 캔버스 루프, 합성음, 이징 상수, 공용 조각 |
| `fx-registry.js` | 연출 레지스트리 (`EFFECTS` / `def`) |
| `fx-effects-1.js` | 1차 배치 16종 |
| `fx-effects-2.js` | 2차 배치 A — 정보 · 감시 6종 |
| `fx-effects-3.js` | 2차 배치 B — 물리 · 변환 6종 |
| `fx-effects-4.js` | 3차 배치 — 모달을 없애는 연출 10종 |
| `fx-lab.js` | UI 배선 (목록·재생·속도) |

**연출을 추가할 때**는 새 `fx-effects-N.js` 를 만들어 `def({...})` 로 등록하고 `fx-lab.js` 의
import 목록에 한 줄 넣으면 된다. UI 코드는 건드리지 않는다 — 배치가 계속 늘어날 예정이라
레지스트리를 따로 뒀다. 새 기법군을 쓰면 `fx-lab.js` 의 `FAM_ORDER` 에만 추가한다.

패 이미지는 게임과 같은 `public/tiles/*.png` 를 그대로 쓴다.

## 랩을 고친 뒤에는 에셋 버전을 올린다 (필수)

공개 서버는 Cloudflare 뒤에 있고 **CF 가 `.css`/`.js` 를 브라우저 캐시 4시간
(`max-age=14400`)으로 덮어쓴다** — 오리진이 `no-cache` 를 보내도 소용없다. Vite 가 만드는
`assets/index-<해시>.js` 는 파일명에 해시가 있어 괜찮지만, 랩 파일들은 손으로 쓴 정적
파일이라 이름이 고정이다. 그래서 배포 후 다시 방문하면 **새 HTML + 낡은 CSS** 가 섞여
레이아웃이 깨진 것처럼 보인다(실제로 한 번 겪었다).

`fx-lab.html` 은 CF 가 캐시하지 않으므로(`cf-cache-status: DYNAMIC`) 그 안의 에셋 URL에
`?v=N` 을 붙여 두고 N 을 올린다. 손으로 고치지 말고 스크립트를 쓴다:

```bash
bash packages/client/public/fx-bump-version.sh
```

**버전이 섞이면 안 된다.** 브라우저는 `/fx-core.js?v=5` 와 `?v=6` 을 서로 다른 모듈로 보고
두 번 로드한다 — 캔버스 루프와 애니메이션 집합이 두 벌 생겨 조용히 오작동한다.
스크립트가 모든 참조를 한 번에 바꾸고 통일됐는지 검사한다.

## 실행

클라이언트 dev 서버가 떠 있으면 <http://localhost:5173/fx-lab.html> 로 바로 열린다.

```bash
npm run dev:client
```

정적 파일뿐이라 `node_modules` 없는 워크트리에서도 아무 파일 서버로 열 수 있다.

```bash
python3 -m http.server 5188 --directory packages/client/public
```

조작: 왼쪽에서 연출 클릭 · `Space` 다시 재생 · `↑↓` 이전/다음 · **속도를 0.25× 로 낮추면
기법이 눈에 보인다**(연출을 고를 때 이게 제일 유용하다).

## 시각 언어는 게임 토큰을 그대로 쓴다

색·반경·그림자·이징은 `src/styles.css` 의 `:root` 디자인 토큰(#13 리스킨)을 그대로 옮겨
적었다 — 먹녹 펠트 램프, 황동 4단, 세이지 텍스트, 증강 보라(`--aug`), 반경 4/8/12,
펠트 색조 섞은 그림자. **랩과 게임의 시각 언어가 다르면 여기서 내린 판단이 게임으로
옮겨가지 않는다.** 중앙 인포도 게임과 같이 떠 있는 카드가 아니라 파인 홈이다.

모션은 한 군데만 갈라진다. 리스킨이 UI 크롬의 바운스 오버슈트를 걷어냈으므로 랩도
패널·라벨·프레임·카드는 `EASE`(지수형 감속)만 쓴다. 반면 **패가 물리적으로 부딪히는
순간**(타패 슬램, 분열 스냅, 발굴 상승)에는 스쿼시를 남겼다 — 게임의 `tile-in` 도 그렇게
한다. UI 가 튀면 싸구려로 보이지만, 물체가 안 튀면 무게가 없어 보인다.
WAAPI easing 문자열에는 CSS 변수를 못 쓰므로 `fx-core.js` 에 `EASE`/`EASE_QUART`/
`EASE_IMPACT` 상수로 들고 있다 — 토큰 값이 바뀌면 여기도 같이 고쳐야 한다.

## 설계 결정 두 가지

**1000×625 고정 좌표계.** 무대는 항상 1000×625 이고 화면 맞춤은 `.stage` 의 `scale()`
로만 한다. 캔버스 입자 물리와 CSS 위치가 같은 단위를 쓰게 하려는 것 — 이게 없으면
입자 궤적이 화면 크기마다 달라진다. 요소 좌표는 `sRect()` 로 실측해서 쓴다.

**모든 애니메이션은 WAAPI(`element.animate`).** 살아있는 애니메이션을 집합으로 들고
있다가 `playbackRate` 를 일괄 적용해 슬로우모션을 만든다. CSS `@keyframes` 로는 이게
안 된다. 연출 사이 초기화는 `resetStage()` 가 무대를 통째로 다시 세워서 정리 버그를
원천 차단한다.

### 2차 배치 — 정보 · 감시 (투시·스파이 계열)

1차 배치에서 **밥상 뒤엎기 · 개벽 · 투시 · 스파이**가 좋다는 피드백을 받았다. 그 넷은 두 축으로
갈린다 — 판을 실제로 건드리는 쪽과, 무엇을 알게 됐는지가 남는 쪽. 2차 배치는 그 두 축만 파고든다.

| 증강 | 연출 | 기법 |
| --- | --- | --- |
| 지뢰 탐지 | 손패마다 위험도 막대·수치가 뜨고 위험원까지 선이 이어진다 | **데이터 오버레이** — 스펙터클 없이 정보만으로 긴장을 만든다 |
| 선언 간파 | 리치한 상대의 대기패가 홀로그램으로 떠오른다 | 주사선+시안 틴트 **홀로그램 재질** + 캔버스 **볼류메트릭 광주** |
| 이면투시 | 도라 표시패를 뒤집어 이면을 보고 되돌려 놓는다 | **backface-visibility** 양면 카드 (가짜 플립은 중간에 들킨다) |
| 예지 | 앞으로 뽑을 패 5장이 시간 레일에 늘어선다 | CSS **offset-path** + 서리유리(`backdrop-filter`) 고스트 |
| 밑장빼기 | 패산 밑에서 한 장을 빼내 손에 숨긴다 | **고스트 잔상 모션블러** (사본을 시차로 지운다) |
| 무르기 | 버린 패가 되감겨 손으로 돌아온다 | 같은 애니메이션의 **playbackRate 를 음수로** — 진짜 되감기 |

### 3차 배치 — 모달을 없애는 연출 (선택 · 인터랙션)

지금 클라이언트에서 이 증강들은 전부 **전체화면 선택창(`createPortal` 모달)** 을 띄운다.
`App.tsx` 의 `MODAL_PICK_TYPES` 와, 전용 UI 로 빠져 일반 메뉴에서 제외된 옵션들이 그 목록이다.
발동하면 판이 사라지고 팝업이 뜬다 — 마작을 하다가 대화상자를 만나는 셈이다.

이 배치의 주제는 하나다: **판 위에서 고르게 한다.** 고르는 대상이 패라면 실제 그 패를 짚게
하고, 고른 결과를 같은 화면에서 바로 보여준다. 그래서 10종이 서로 다른 연출이면서도 같은
선택 언어(`pickSweep` — 후보에 테두리, 훑다가 내려앉기, 점선→실선 확정)를 공유한다.
**새 인터랙션을 10개 배우게 하면 안 된다.**

| 증강 | 지금 (모달) | 판 위로 옮기면 |
| --- | --- | --- |
| 단색 세계 | 색 3지선다 창 | 손패 위 물감 단지 3개 + **미리보기 틴트**로 결과를 먼저 보여준다 |
| 붉은 손길 | 1~9 숫자 창 | 손패 아래 숫자 다이얼 + 해당 패가 **미리 떠오른다**(몇 장인지 세지 않아도 보인다) |
| 왕패의 주인 | 왕패 14 × 손패 13 격자 창 | 왕패를 그 자리에서 열고 **연결선으로 묶어 교차**시킨다 |
| 정적의 손 | 바닥패 목록 창 | 네 바닥이 후보가 되고 **소리를 끊는다** — 없는 것으로 만드는 연출 |
| 예지 · 순서 | 드래그 재배열 창 | 4장을 들어올려 **하가·대면·상가·나 슬롯**에 얹는다(위치가 곧 누구의 쯔모) |
| 이면 바꿔치기 | 왕패 자리 선택 창 | 왕패가 부채처럼 벌어지고 두 장이 **호를 그려 자리를 바꾼다** |
| 등가교환 | 3+3 선택 창 | 상대 손패를 펼쳐 보여주고 중앙 **저울**이 기울다 균형을 잡는다 |
| 미래를 보는 자 | 3장 중 버릴 것 선택 창 | 3장이 **뜯겨 나가는 것을 먼저** 보여주고 그 다음에 고르게 한다 |
| 절벽 위에 피어난 꽃 | 영상패 4지선다 창 | 앞 4장이 **꽃잎처럼 벌어지고**, 두 번째 깡에 그 자리에서 만개 |
| 왕패 열람 | (모달 아님 · 상시 표시) | **한 번 열고 조용해진다** — 대조 사례로 넣었다 |

마지막 '왕패 열람'은 일부러 심심하게 만들었다. 상시 표시되는 정보에 강한 연출을 붙이면
국이 끝날 때까지 방해가 된다 — **강한 연출이 늘 답은 아니라는 걸** 같은 화면에서 비교해
보려고 넣은 항목이다.

랩에서는 클릭 대신 후보를 훑다가 하나에 내려앉는 것으로 '고르는 동작'을 재생한다.
실제 클라이언트로 옮기면 그 자리에 사용자 클릭이 들어간다.

## 연출을 고를 때 본 것

프로토타입을 돌려보며 반복해서 확인된 것들 — 클라이언트로 옮길 때도 같이 가져갈 만하다.

- **연출과 상태 변화를 같은 타임라인에 붙인다.** 염색은 번짐이 도착한 타일의 이미지를
  실제로 교체하고, 분열은 끝나면 손패가 정말 14장이 된다. 화면만 번쩍이고 상태가 그대로면
  "무슨 일이 일어났는지" 가 몸에 남지 않는다.
- **강한 연출은 길이가 아니라 단계로 무게를 만든다.** 거신병은 예고(재) → 등장 → 충전 →
  발사 → 여운 5단이다. 같은 시간을 한 덩어리로 쓰면 그냥 시끄럽다.
- **정보 비대칭은 색으로 말한다.** 시간 정지는 판 전체를 회색으로 만들고 내 손패만
  마스크로 구멍을 뚫어 색을 남긴다. 규칙 설명 없이 "나만 움직인다" 가 전달된다.
- **감지는 순차적이어야 정보가 된다.** 천리안은 스윕이 좌석 각도를 지날 때 핑이 뜬다.
  동시에 다 뜨면 정보가 아니라 장식이다.
- **대칭 도형은 뒤집어도 안 뒤집힌 것처럼 보인다.** 모래시계는 위·아래 캡 폭을 다르게
  둬서 회전을 눈에 보이게 만들었다.
- **수십 장을 움직일 땐 DOM 을 버리고 캔버스로 넘긴다.** 밥상 뒤엎기·개벽이 그렇다.
  개별 DOM 트랜스폼으로는 60fps 가 안 나온다.
- **캔버스 궤적은 '프레임 수'가 아니라 '길이'로 잡는다.** 진짜 용의 몸통을 프레임 기준으로
  두면 슬로우모션에서 머리가 프레임당 덜 움직여 몸통이 뭉툭한 토막이 됐다.
- **정보는 순차적으로 줘야 정보다.** 지뢰 탐지는 좌→우로 한 장씩 판정이 올라온다. 13장이
  한꺼번에 뜨면 읽지 않고 넘긴다.
- **가장 오래 쓰이는 연출은 판단을 바꾸는 연출이다.** 지뢰 탐지·예지처럼 다음 한 수가
  달라지는 것들은 100번째에도 본다. 스펙터클은 세 번째부터 스킵하고 싶어진다.
- **되돌릴 수 없는 선택은 누르기 전에 결과가 보여야 한다.** 단색 세계의 미리보기 틴트,
  붉은 손길의 '몇 장이 바뀌는지'가 그것이다. 모달은 이걸 구조적으로 못 한다 — 판을 가리고
  있으니 결과를 보여줄 데가 없다.
- **선택지가 여러 개면 선택 언어는 하나여야 한다.** 3차 배치 10종이 같은 `pickSweep`
  (테두리 → 훑기 → 점선이 실선으로)을 공유한다. 연출마다 다른 인터랙션을 만들면 연출이
  아니라 학습 부담이 된다.
- **상시 정보에는 연출을 아껴야 한다.** 왕패 열람은 한 번 열고 조용해진다. 국이 끝날 때까지
  화면에 남아 있을 것에 강한 연출을 붙이면 그건 연출이 아니라 소음이다.

## 클라이언트로 옮길 때

`packages/client/src/styles.css` 에는 이미 70여 개 `@keyframes` 와 컷인·리치·역만 연출이
있다. 랩의 연출 중 **기존 어휘로 안 되는 것**만 옮기면 된다 — 캔버스 입자(밥상 뒤엎기,
개벽, 거신병, 일확천금), SVG 필터(염색, 분열, 박무), `clip-path` 파편·밴드(무장해제, 투시),
`backdrop-filter` 마스크(시간 정지).

옮길 때 랩과 달라지는 점:

- 좌표는 `sRect()` 대신 React `ref` + `getBoundingClientRect` 로 잡는다. 실측은 유지해야
  한다 — 하드코딩하면 모바일 레이아웃에서 조용히 깨진다.
- 캔버스 루프는 하나만 두고 연출들이 draw hook 을 등록하는 구조(`fx-core.js` 와 동일)가
  React 에서도 그대로 쓸 수 있다. 연출마다 캔버스를 만들면 안 된다.
- 합성음은 `src/sfx.ts` 에 이미 훨씬 잘 만들어진 게 있으니 랩의 신스는 버리고 그쪽에
  연출별 큐를 추가한다.
- 슬로우모션 배율은 랩 전용이다. 대신 설정의 연출 on/off 와 `prefers-reduced-motion`
  대응이 필요하다.
