## 1. [높음] 프록시 헤더로 루프백을 위장하면 방어가 통째로 꺼진다 — [완료]

**발견**. `RoomManager`의 원격 남용 방어 4종(IP당 동시 연결 16 · 메시지 토큰버킷
80/40tps · 인증 30회/분 · 방 생성 20개/10분)이 전부 `isLoopbackIp(conn.ip)`로
면제됐다. 그런데 `conn.ip`는 프록시 뒤에서 **헤더로부터 복원한 문자열**이다
(`clientIpOf`, `CF-Connecting-IP` 또는 `X-Forwarded-For` 마지막 홉).

**공격**. 복원된 값이 `127.0.0.1`이 되게 만들 수 있는 경로가 하나라도 있으면, 그 연결은
서버의 모든 남용 방어 **바깥**에 선다 — 무제한 연결, 무제한 메시지, 무제한 비밀번호
시도. Cloudflare는 `CF-Connecting-IP`를 덮어써 주므로 표준 경로는 막혀 있지만, 이 방어는
"프록시가 헤더를 반드시 덮어쓴다"는 전제 **하나**에 전부를 걸고 있었다. `TRUST_PROXY=xff`
모드, 프록시 설정 실수, 터널을 우회한 직접 접근 중 무엇이든 하나면 전제가 깨진다.
게다가 실패 방식이 조용하다 — 로그도, 오류도 없이 방어만 사라진다.

**조치**. 면제를 IP 문자열이 아니라 **소켓**이 결정하게 바꿨다. `clientIpOf`가
`{ip, local}`을 돌려주고, `local`은 *소켓 상대가 진짜 루프백이고 프록시 헤더를 쓰지
않았을 때만* 참이다. 헤더에서 복원한 IP는 아무리 루프백처럼 보여도 `local: false`다.
`RoomManager.handleConnection(ws, ip, exempt)`이 이 값을 받아 `conn.exempt`로 들고 다닌다.
회귀 테스트: `Security.test.ts` — "프록시 헤더로 127.0.0.1을 위장해도 토큰버킷이 걸린다".

## 2. [높음] 관리자 코드가 영구·재사용·매 부팅 로그 출력 — [완료]

**발견**. 관리자 코드는 48비트 랜덤이지만 **한 번 만들어지면 영원히 유효**했고, 서버가
부팅할 때마다 콘솔에 찍혔으며(`npm run serve:logs`에 그대로 남는다), 몇 번이고 재사용할
수 있었다.

**공격**. 코드가 실린 로그 한 줄·스크린샷 하나·백업 파일 하나면 끝이다. 회원가입 폼에
그 코드를 넣는 것만으로 누구든 관리자가 된다. 관리자 권한은 이 서비스에서 사실상 마스터
키다 — 전 계정 목록·삭제, **모든** 리플레이 열람, 진행 중인 남의 대국 관전(관전 뷰는
전원의 손패·패산·도라가 다 보이는 완전정보다). 즉 "실시간 치트"까지 열린다.

**조치**.
- 코드 길이 48비트 → **128비트**.
- **쓰이는 즉시 회전**(`register`가 승급에 성공한 뒤 `rotateAdminCode`). 유출된 값은
  이미 쓰였다면 죽은 값이다. 실패한 가입(닉네임 중복 등)으로는 소모되지 않는다.
- ~~부팅 로그는 **관리자 계정이 아직 없을 때만** 코드를 찍는다(`db.hasAdmin()`).~~
  → **2026-08-24 되돌림**(운영자 결정): 회전 때문에 현재 코드를 확인할 길이 로그뿐인데,
  첫 관리자가 생긴 뒤로는 영영 숨겨져 관리자를 하나 더 만들 수 없었다. 지금은 매 부팅
  찍는다 — 로그 파일 자체를 비밀로 다루는 것이 전제다.
- `ADMIN_CODE` 환경변수로 고정 가능 — 이 경우 DB에도 로그에도 남기지 않는다.
- 비교는 상수 시간(`safeEqual`).

**운영 조치 필요**: 지금까지의 로그에 남은 코드는 이미 유출로 간주하는 편이 안전하다.
관리자 계정이 이미 있다면 그 코드는 회전됐거나 더는 출력되지 않지만, 확실히 하려면
`ADMIN_CODE`로 새 값을 정해 띄우고 필요한 승급을 마친 뒤 다시 비우면 된다.

## 3. [중간] IPv6 주소를 갈아타면 IP당 상한이 무의미해진다 — [완료]

**발견**. 모든 상한이 IP **주소 문자열**을 키로 셌다.

**공격**. IPv6 사용자는 보통 `/64`(2⁶⁴개 주소)를 통째로 받는다. 접속마다 주소를 바꾸면
"IP당 동시 연결 16"·"IP당 인증 30회/분"·"IP당 방 20개/10분"이 전부 우회되고, 전역 300
연결 슬롯도 혼자 비울 수 있다(정상 사용자 전원 접속 거부 = DoS).

**조치**. `abuseKeyOf()` — IPv4는 주소 그대로, IPv4-mapped는 IPv4로, IPv6는 축약을 편 뒤
**앞 4그룹(/64)** 으로 묶는다. 모든 상한이 이 키로 센다.

## 4. [중간] 미인증 연결이 `logout`으로 유예를 무한 연장 — [완료]

**발견**. 인증 없이 소켓만 붙들고 있는 스쿼팅은 `UNAUTH_TIMEOUT_MS`(30초)로 막고 있었는데,
`logout` 핸들러가 **무조건** 그 타이머를 되걸었다(`armAuthDeadline`).

**공격**. 인증하지 않고 29초마다 `{"type":"logout"}` 한 줄만 보내면 연결이 영원히 유지된다.
IP당 16개 × N개 IP로 전역 300 슬롯을 인증 없이 점유할 수 있다.

**조치**. `conn.user === null`이면 `logout`은 아무것도 하지 않고 반환한다.

## 5. [중간] HTTP 계층에는 아무 상한이 없었다 — [완료]

**발견**. 연결 상한·하트비트는 **WebSocket으로 업그레이드한** 연결에만 적용된다. 평범한
TCP/HTTP 연결에는 동시 소켓 상한도, 헤더 대기 시간 제한도 없었다.

**공격**. 업그레이드하지 않고 HTTP 헤더를 한 글자씩 흘려보내며 소켓 수천 개를 붙들면
(slowloris) 파일 디스크립터가 마르고, WS 방어에는 잡히지 않은 채 서버가 새 접속을 받지
못한다.

**조치**. `maxConnections`(기본 512) · `headersTimeout` 10s · `requestTimeout` 20s ·
`keepAliveTimeout` 15s · `clientError`에서 소켓 파기.

## 6. [중간] 신규 연결 속도 제한 없음 — [완료]

**발견**. 동시 개수만 제한하고 **초당 신규 연결 수**는 제한하지 않았다.

**공격**. 열고 즉시 닫기를 반복하면 상한에 한 번도 걸리지 않으면서 핸드셰이크·세션
객체·타이머 생성 비용을 무한히 태울 수 있다.

**조치**. upgrade 단계에서 버킷당 `CONN_RATE_MAX`(기본 40회/10초). 초과 시 101을 내주기
전에 `429`로 끊는다. 진짜 루프백은 면제.

## 7. [중간] 회원가입 응답 시간으로 계정 열거 — [완료]

**발견**. `register`가 닉네임 중복이면 **scrypt를 돌리기 전에** 즉시 반환했다.

**공격**. 오류 문구를 읽지 않아도(문구는 UX상 필요하다) 응답 시간만으로 계정 존재 여부를
훑을 수 있다 — 중복은 1ms 미만, 신규는 scrypt 비용(수십 ms). 열거한 닉네임 목록은 그대로
비밀번호 대입 대상이 된다. (로그인 쪽은 이미 더미 scrypt로 막혀 있었다.)

**조치**. 중복 검사보다 scrypt를 **먼저** 돌려 두 경로의 비용을 같게 했다. 겸사겸사
중복 검사와 INSERT 사이 경합(UNIQUE 위반이 `INTERNAL`로 새던 것)도 평범한 실패로 바꿨다.

## 8. [중간] 고급 설정의 서버 주소로 세션 토큰이 따라간다 — [완료]

**발견**. 클라이언트는 접속 즉시 저장된 세션 토큰을 `tokenLogin`으로 보낸다. 접속 주소는
고급 설정의 수동 입력값(`localStorage`)이고, 스킴 검증도 없었다.

**공격**. "이 주소로 바꾸면 더 빨라요" 한 마디(혹은 확장 프로그램·붙여넣기 스니펫)로
`wss://evil.example`이 들어가면, 다음 접속에서 세션 토큰이 그대로 공격자 서버에 도착한다 =
계정 탈취.

**조치**. 토큰을 **발급한 서버 주소와 함께** 저장하고, 주소가 일치할 때만 되돌려 보낸다.
(발급처가 다르면 어차피 그 서버에서 쓸 수 없는 값이라 잃는 기능이 없다.) 수동 서버
주소는 `ws:`/`wss:`만 받는다 — 저장 시점과 읽는 시점 양쪽에서 거른다.

## 9. [낮음] 프레임 상한·압축 — [완료]

512KB × 40프레임/초 = 초당 20MB를 `JSON.parse`에 태울 수 있었다. 실사용 최대는 수 KB라
`maxPayload`를 **64KB**로 내리고, `permessage-deflate`를 명시적으로 껐다(압축 해제는
보내는 쪽이 싸게 만들 수 있는 비대칭 비용이다).

## 10. [낮음] 정적 파일 서버 — [완료]

경로 탈출은 이미 `startsWith(CLIENT_DIST + sep)`로 막혀 있었으나, 방어가 몇 가지 우연에
기대고 있었다. 전부 명시적으로 닫았다:
- **GET/HEAD만** 허용(그 외 405 + 본문 배출). 예전에는 POST에도 파일을 그대로 내주고
  본문은 소켓에 남았다.
- 퍼센트 인코딩을 **먼저 디코드**한 뒤 정규화, NUL 바이트 차단, 잘못된 인코딩은 400.
- `realpath`로 **심볼릭 링크 탈출**까지 dist 안에 가둔다.
- 응답이 끊기면 읽기 스트림도 닫는다(fd 누수).
- `Strict-Transport-Security`, CSP에 `form-action 'none'` 추가.

## 11. [낮음] 비밀 비교가 상수 시간이 아님 — [완료]

가입 코드(`SIGNUP_CODE`)와 관리자 코드를 `!==`로 비교했다. 원격에서 재기는 어렵지만
"앞에서 몇 글자가 맞았는지"가 응답 시간에 실리는 것은 사실이다. `safeEqual`(sha256 →
`timingSafeEqual`)로 길이 차이까지 감춰 비교한다.

## 12. [보류 · 결정 필요] 솔로 대국 무효 투표로 성적을 세탁할 수 있다

**발견**. `voteAbort`는 "지금 남아 있는 **사람** 전원 동의"로 성립한다. 봇과 이탈한
좌석은 자동 동의로 친다.

**공격**. 사람 1명 + 봇 3명 방에서는 `needed === 1` — **혼자서 언제든 판을 무효로 만들 수
있다.** 무효 판은 정산·순위·통계·리플레이를 전혀 남기지 않으므로, 지고 있을 때만 무효를
누르면 리더보드에는 이긴 판만 쌓인다. 창을 닫는 이탈은 봇이 이어 두고 순위가 그대로
기록되므로, 성적 관리 측면에서 무효 쪽이 **엄격히 더 유리**하다.

**왜 코드로 먼저 고치지 않았나**. 세 가지 해법이 전부 게임 설계 결정이라서다:
1. 사람 2명 이상일 때만 무효 허용 — 솔로는 이탈로만 끝나고 그 판은 기록된다.
   (혼자 연습하다 그만두는 흔한 경우에도 순위가 남는다.)
2. 무효 판도 "참가 기록"은 남긴다 — 순위는 없지만 판 수는 센다.
3. 솔로(봇 3) 대국을 리더보드 집계에서 분리한다 — 사실 이게 통계적으로도 맞다.

셋 중 무엇을 택할지는 "리더보드가 무엇을 재는 표인가"에 달렸다. 결정해 주면 바로 넣는다.

## 13. [보류 · 기능] 비밀번호 변경·세션 일괄 무효화가 없다

토큰이 샜다고 판단해도 사용자가 스스로 무효화할 방법이 없다(관리자의 계정 삭제만 세션을
끊는다). 권장: 비밀번호 변경 + 변경 시 전 세션 무효화 + "다른 기기 로그아웃".

## 뚫으려다 실패한 것들 (= 이미 튼튼한 자리)

다음 감사가 같은 자리를 다시 파지 않도록 남긴다.

- **SQL 인젝션** — 모든 쿼리가 파라미터 바인딩이고, 문자열 조립이 한 군데도 없다.
  `Number.isInteger` 가드가 정수 파라미터 앞에 붙어 있다.
- **XSS** — 클라이언트 `src/`에 `dangerouslySetInnerHTML`·`innerHTML`이 없다. 제보 제목·
  본문·닉네임은 전부 React 자식 노드로 들어가 자동 이스케이프된다. (`public/`의 fx-lab·
  sfx-lab은 개발자 도구 페이지이고 내용이 정적이다.)
- **완전정보 치트** — `buildPlayerView`가 **뷰어별로** Zone 가시성을 계산하고, 규칙에
  없는 Zone kind는 `hidden`으로 폴백한다(안전 기본값). 손패·패산은 서버에서 아예 지워져
  나가므로 클라이언트를 뜯어도 나오지 않는다. `SPECTATOR_ID` 전체공개 뷰는 관리자 관전과
  증강 테스트 방에서만 붙고, **본인이 참가 중인 방은 관전이 거부**된다.
- **액션 위조** — 클라이언트 `action`은 서버가 그 좌석에 제시한 옵션과 `type` + payload
  직렬화가 정확히 일치할 때만 수락된다. 남의 좌석 결정은 `pending` 맵에 그 좌석이 있을
  때만 매칭되므로(=봇 조종 중인 샌드박스), 일반 대국에서는 본인 좌석뿐이다.
- **방 코드 무차별 대입** — 32⁶ ≈ 10.7억, 토큰버킷이 초당 40회로 묶는다. 현실적이지 않다.
- **제보 게시판 권람 범위** — 공개 범위가 조회 쿼리 자체에 박혀 있어(`WHERE user_id = ?`)
  상위 계층이 필터를 빠뜨려도 남의 글이 실리지 않는다.
- **프로토타입 오염** — 예약 닉네임(`__proto__`·`constructor`·…) 차단 + `StatsStore`가
  프로토타입 키에 `null`을 반환한다(회귀 테스트 있음).
- **리플레이 접근** — `replayGet`은 참가자 본인 또는 관리자만. 경로는 DB가 준 값이라
  사용자 입력이 파일 경로에 닿지 않는다.
- **계정 삭제 후 권한 잔존** — `evictUser`가 열린 소켓을 즉시 축출한다.
