# 33. 클라이언트 셸 — 판 밖 화면의 시각 규약 (2026-08-19)

> **범위** — 게임 테이블을 **뺀** 모든 화면: 첫 화면(로그인 전) · 홈 · 증강 도감 · 규칙·도움말 · 제보 게시판 · 증강 파워 티어표 · 대기실 · 로딩 카드.
> **판 위(대국 화면)는 이 문서의 대상이 아니다.** 거기는 [18_UI_REDESIGN_BRIEF.md](18_UI_REDESIGN_BRIEF.md)의 두 레이어 규약(평시 Calm Riichi / 순간 Neon Surge)이 그대로 유효하다.
> **관계** — 이 문서는 18번 §1.1 "평시 레이어"가 판 밖 화면에서 구체적으로 어떤 모양이어야 하는지를 못 박는다. 18번을 바꾸지 않고 **좁힌다**.

## 0. 왜 고쳤나

사용자 지시(2026-08-19): **"좀 더 AI 느낌이 안 나게."**

문제는 못생긴 것이 아니라 **아무 제품에나 붙는 모양**이라는 것이었다. 첫 화면을 열었을 때 이것이 마작 게임의 클라이언트인지, SaaS 랜딩인지, 뉴스레터 가입 페이지인지 알 수 없었다. 구체적으로 여덟 가지였다:

| 걷어낸 것 | 왜 |
|---|---|
| 44px 금색 워드마크 + 가운데 정렬 히어로 | 제품을 특정하지 않는 "브랜드 세우기". 클라이언트의 이름표는 작게 왼쪽 위에 붙는다 |
| 균등 3칸 피처 카드 그리드 | 셋이 무슨 관계인지(= 같은 더미에서 뽑히는 보기 셋) 모양이 말해 주지 않는다 |
| "다양한 증강을 **즐겨보세요**" | 아무것도 알려주지 않으면서 광고처럼만 읽히는 문장 |
| 이모지 아이콘 (🎓 ▶ 📘 📖 📢 📊 🧪 👑 …) | 기기마다 다른 그림·다른 기준선이 와서 줄이 흔들린다 |
| 12px 둥근 모서리 + 부드러운 그림자 | "떠 있는 카드"는 문서의 문법이지 창의 문법이 아니다 |
| 위→아래 어두워지는 배경 그라데이션 | 내용과 무관한 연출. 스크롤하면 지면 색이 계속 변했다 |
| 알약(999px) 버튼·탭 | 알약은 **고를 수 있는 값**(필터·태그)의 문법이다. 동작 버튼·화면 탭에 쓰면 뜻이 어긋난다 |
| 버튼 아래 변명하는 설명 문단 | 버튼이 스스로 말하지 못한다는 뜻이다. 라벨과 부가 정보로 나눠 넣는다 |

## 1. 규칙 넷

이 넷만 지키면 나머지는 따라온다. CSS 의 `클라이언트 셸` 섹션(`styles.css`) 머리에 같은 내용이 있다.

1. **면이 아니라 선으로 나눈다.** 카드를 띄우지 말고 패널을 붙인다.
2. **모서리는 3px**(`--r-panel`) / 작은 것은 2px(`--r-chip`). 알약은 **상태 배지에만** 남긴다(관리자 · 상시/액티브 · 수집 현황).
3. **수치는 고정폭**(`--mono` + `tabular-nums`). 판수·승률·방 코드·버전처럼 자리가 흔들리면 안 되는 것.
4. **라벨은 한 급**(13px/1.2px). 제목을 키워서 위계를 만들지 않는다 — 위계는 **패널 머리의 황동 눈금 굵기**가 만든다(주 패널 4px, 나머지 3px).

### 1.1 색

팔레트는 **바꾸지 않았다**. 먹빛 녹색 펠트 + 황동 하나 + 증강 보라는 그대로다(그 부분은 문제가 아니었다). 판 밖 전용으로 더한 것만:

| 토큰 | 값 | 쓰임 |
|---|---|---|
| `--chrome-fill` | `#0c1511` | 패널 채움 (펠트보다 어둡게 — 창이 판 위에 얹힌 것처럼) |
| `--chrome-head` | `#131f19` | 패널 머리 · 상태 줄 |
| `--chrome-line` | `rgba(236,228,210,.13)` | 판 밖 화면의 **유일한** 선 색 |
| `--chrome-lit` | `rgba(236,228,210,.055)` | 위쪽 1px 하이라이트 — 이거 하나로 사각형이 금속판이 된다 |
| `--field-fill` | `#070d0a` | 입력칸 바닥 (패널보다 한 단 깊게 = 적어 넣는 자리) |

대비는 새 채움 위에서 오히려 올라갔다: `--ink-4`(2차 라벨) 기준 **6.16:1**, 주 버튼 글자(`#1a1408` on `--brass`) **4.61:1**. 둘 다 WCAG AA 통과.

### 1.2 표식 (이모지 대체)

`.mk-*` — CSS 로 그린다. `currentColor` 를 따라가므로 버튼 색이 바뀌면 표식도 같이 바뀐다.

| 클래스 | 그림 | 쓰임 |
|---|---|---|
| `.mk-doc` | 가로줄 셋 | 규칙 · 도움말 |
| `.mk-grid` | 2×2 칸 | 증강 도감 |
| `.mk-steps` | 오르는 계단 셋 | 튜토리얼 |
| `.mk-play` | 삼각형 | 바로 시작 |
| `.mk-plus` | 십자 | 방 만들기 |
| `.mk-again` | 열린 원 | 재접속 · 새로 고침 |
| `.mk-gear` | 톱니 | 설정 |

> ⚠ **규칙과 도감은 반드시 다른 표식**이어야 한다. 한때 둘 다 같은 '책' 모양이었는데 11px 로 줄면 구별이 안 되어, 상단 바에 같은 단추가 두 개 있는 것처럼 보였다(375px 실측).

> ⚠ `CATEGORY_META.icon`(계열 이모지)은 **그대로 뒀다** — 판 위(액티브 버튼·드래프트 카드)에서 같은 값을 쓰는데 거기는 이번 정리 대상이 아니다. 도감 칩에서만 렌더를 뺐다.

## 2. 구조

### 2.1 상태 줄 (`.site-bar`)

로그인 **전후로 같은 창틀**이다. 다르면 같은 클라이언트로 읽히지 않는다.

```
[이능마작] [증강 리치마작] ················ [● 서버 연결됨] │ [● 증강 117종] │ [규칙]
```

- 첫 화면: 연결 상태 + 증강 종수(**서버가 준 `serverInfo.augmentKinds`만** — 문장에 숫자를 박지 않는다)
- 홈: 규칙 · 도감 · 닉네임 · 설정 · 로그아웃
- 도감/규칙/티어표: 뒤로 · 화면 이름 · 수집 현황 · 화면 안 탭

### 2.2 첫 화면 — 마케팅 랜딩이 아니라 **접속 화면**

```
┌ 공지 ─────────────────────────────────────────────┐   ← 있을 때만
├ 상태 줄 ──────────────────────────────────────────┤
│ 이능마작                    │ [계정 없이 시작]      │
│ 표준 리치마작 4인전입니다…   │  ▸ 튜토리얼   5~10분  │
│ ┌ 사양표 ────────────┐      │  ▸ 바로 한 판  봇 3명 │
│ │ 규칙   리치마작·4인 │      ├──────────────────────┤
│ │ 길이   동풍전·반장전│      │ [로그인] [회원가입]   │
│ │ 증강   117종 …      │      │  닉네임 / 비밀번호    │
│ └────────────────────┘      │  [ 로그인 ]           │
│ ┌ 증강 예시 ── 3/117 ┐      │                       │
│ │ 01 사방치기 …       │      │                       │
└──────────────────────┴──────────────────────────────┘
```

- 들어가는 문을 **한 자리로 모았다**. 예전에는 튜토리얼·체험·규칙 버튼 셋이 로그인 칸과 따로 떨어져 화면 가운데 서 있어서, 처음 온 사람이 어느 쪽이 정문인지 못 골랐다.
- 증강 예시는 균등 3칸 카드 → **번호 붙은 목록**. 실제 패 에셋을 그대로 쓴다(광고용 그림을 따로 만들면 화면과 다른 것을 약속하게 된다).
- 780px 아래에서 한 단으로 쌓인다. DOM 순서가 곧 읽는 순서라 `order` 뒤집기가 없다.

### 2.3 패널

여백을 갖는 방식이 두 갈래다 — **이걸 헷갈리면 머리가 패널 밖으로 삐져나온다.**

| | 여백을 갖는 곳 | 머리 마진 |
|---|---|---|
| `.panel` | `.panel-body` (틀 자체는 여백 0) | 없음 — 그냥 놓으면 끝까지 닿는다 |
| `.home-card` | 자기 자신 (안의 내용이 제각각이라 본문 감싸개가 없다) | `--panel-pad-*` 만큼 **음수 마진** |

## 3. 두 번 물린 함정 (가드 테스트 있음)

`packages/client/test/clientShell.test.ts` 가 지킨다. 둘 다 **깨져도 콘솔은 조용하다.**

### 3.1 `.site-bar` 가 눌린다 → `flex: none`

상태 줄은 세로 flex 컨테이너(`.home`·`.codex`)의 첫 자식이라 기본 `flex-shrink: 1` 을 갖는다. 좁은 화면에서 내용이 두 줄로 접히면 컨테이너가 이 줄을 `min-height: 40px` 까지 눌러 버리고, 안의 44px 단추들이 아래 도구줄 위로 **넘쳐 겹쳤다**(375px 실측: 내용 60px → 상자 40px).

### 3.2 첫 화면이 가운데로 쪼그라든다 → `place-items: normal`

`.lobby` 가 `display: grid; place-items: center` 다. `.lobby-landing` 이 display 를 block/flex 로 되돌려도 **`place-items` 는 남는데**, Chrome 123+ 는 블록 컨테이너에서도 `justify-items` 를 적용한다 — 블록 자식이 shrink-to-fit 되어 가운데로 몰린다(1280px 실측: 상태 줄이 439px 로 쪼그라들었다).

예전 랜딩은 자식마다 `width: min(…)` + `margin: 0 auto` 가 박혀 있어서 이 동작이 **드러나지 않았다**. 폭을 풀자마자 나왔다.

## 3.5 대기실 — 2차 (같은 날)

1차에서는 대기실의 **창틀만** 패널 기하로 맞추고 안은 그대로 뒀다. 그 결과 한 화면에 판 위의 문법과 판 밖의 문법이 섞여 남았다 (사용자 지적: *"대기실도 애매하게 남아있어"*).

| 남아 있던 것 | 왜 문제였나 | 어떻게 |
|---|---|---|
| 카드 위에 뜬 `.icon-btn` 넷 (설정·나가기·도감·규칙) | `position: absolute` — 판 위 전용 문법이다. 판이 없는 화면에서 단추가 허공에 뜬다 | 창의 **타이틀바**(`.wr-head`)로 내림. `.icon-btn` 을 쓰지 않는다 |
| 정형구(대화) 단추 | `.waitroom-card .emote-bar { top: 64px }` 로 얹혀 **방 코드 상자를 가렸다** | 머리줄 안으로. 펼침 목록만 절대배치 |
| 점선 두른 방 코드 상자 + 26px 금색 글로우 | 점선 = "임시로 그려 둔 것". 글로우는 이 화면 유일한 발광 | 파인 바닥 + 고정폭 값 + `복사` 칩 |
| `<div onClick>` 이던 방 코드 | 키보드로 닿지 않고, 누를 것으로 안 읽혔다 | `<button type="button">` |
| 둥근 상자로 흩어진 좌석 넷 | 서로 무관한 카드 넷으로 보였다 | 테두리 하나 안에 헤어라인. 내 자리는 **왼쪽 눈금** |
| 빈 자리의 점선 테두리 | 위와 같은 이유 | 톤만 내림 |
| `.wr-start`·`.wr-ready` 세로 그라디언트 | 판 밖의 주 동작은 전부 평평한 채움이다(`.btn-key`) | 평평하게. 글자색도 `#2a2109`(4.00:1) → `#1a1408`(4.61:1) 로 올림 |
| 판 길이·봇 난이도의 둥근 상자 | 나란한 보기 = 세그먼트지, 따로 노는 버튼들이 아니다 | `--r-chip` 세그먼트, 고른 쪽만 황동 |

### 설정 표식은 톱니가 아니다

24점 톱니 폴리곤(`.mk-gear`)은 11~14px 로 줄면 그냥 얼룩이 됐다. 이 크기에서 형태가 살아남는 것은 **굵은 직선 몇 개**뿐이다. 가로줄 셋은 이미 규칙(`.mk-doc`)이 쓰므로, 설정은 **세로 막대 + 손잡이**(`.mk-sliders`)로 간다 — 두 표식이 90도 어긋나 나란히 있어도 갈린다.

> ⚠ `.mk-sliders` 는 좌표를 px 로 잡으므로 **크기를 고정**한다. 부모가 11px 로 줄이면 손잡이가 잘린다.

### 그대로 둔 것

꿀팁의 🔒 🕐 ♻ 🎲 는 **판 위 이름표에 실제로 뜨는 배지**다(`App.tsx` 의 pill 렌더). 설명이 화면과 같은 그림을 가리켜야 하므로 남긴다 — 판 위를 정리할 때 함께 간다.

## 4. 손대지 않은 것

- **대국 화면 전체** — 패·바닥·이름표·액션 바·컷인·연출. 모서리 토큰도 `--r-sm/md/lg` 를 그대로 쓴다. 판 위의 `.icon-btn` 줄(도감·규칙·설정·나가기)도 그대로다 — 대기실만 자기 머리줄로 떼어 왔다.
- **팔레트** — 펠트·황동·증강 보라.
- **정보 구조** — 어느 화면에 무엇이 있는지는 그대로다. 옮긴 것은 첫 화면의 시작 버튼 셋뿐이다.
- **`prefers-reduced-motion` 블록** — 그대로 유효하다(새로 더한 전이는 전부 120ms 안쪽의 색 변화뿐이라 모션 축에 걸리지 않는다).
