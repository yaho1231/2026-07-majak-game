## 3. 서버 — 측정과 최적화

### 3-1. «전» 측정 (qa-lab/round5/perf/report.md, 실제 ws + deflate, 실전 속도)
| 방 | ping p50/p95/p99 | loop p99/max | 거절/INVALID |
|---|---|---|---|
| 16 | 1/6/13 | 21/28 | 0/0 |
| 64 | 2/8/11 | 104/139 | 0/0 |
| 128 | 4/8/10 | 104/160 | 0/0 |
| 200 (상한) | 5/14/78 | 33/81 | 0/0 |

loop max는 전부 «방 준비 직후 동시 시작» 1초째. 프로파일: CPU 70%+가 엔진(화료형 판정 23%·뷰 20%·봇 29%),
stringify+send 2.6%, deflate 0.5%, SiteDb 0.4%. **계획의 S-1(sweep upsert)·S-2(deflate)·S-8(matching)은
측정에서 문제가 아니었다** — 손대지 않았다.

실제로 문제였던 것과 고친 것(«후» 수치, 골든 5+1 동일):

| S-6 스레드풀 4 공유 — 로그인 20/s 폭주 중 | loop p99 181ms · action p99 247 | 18~21 · 34~67 (`UV_THREADPOOL_SIZE=16`, 기동 스크립트) |
