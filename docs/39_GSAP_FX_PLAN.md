## 확인하는 법

```bash
# ⚠ 반드시 **이 워크트리에서** 띄운다. 5173 은 다른 세션이 잡고 있을 수 있다
#   (실제로 그래서 한동안 남의 체크아웃을 보며 "왜 내 CSS가 안 먹지" 했다).
cd packages/client && npx vite --port 5179 --strictPort
```
- 게임: <http://localhost:5179/>
- **연출 점검 페이지: <http://localhost:5179/fx-showcase.html>** ← 모든 연출을 여기서 본다

포트가 **517x** 여야 클라이언트가 `ws://localhost:3001` 을 자동으로 본다(`App.tsx` 의
`serverUrl`). 대국까지 해 보려면 테스트 서버도 함께 띄운다 — **운영은 3011 이라 안 겹친다**:

```bash
cd packages/server && PORT=3001 DB_PATH=/tmp/majak-test.db npm run dev
```

⚠ 브라우저에 예전 서버 주소가 저장돼 있으면 계속 "재연결 중"만 뜬다:
`localStorage.removeItem("majak.serverUrl")` 후 새로고침.

**master 에 병합하지 않는다.** 사용자가 직접 확인하고 "본서버에 올려도 되겠다"고 판단한 뒤에 한다.

## 지키는 선 (사용자 지시 + 기존 저장소 원칙)

1. **차분한 기본값 + 설정으로 조절.** 100판째 플레이어에게 통과의례가 되지 않는 선이 기본값이다.
2. **매 순 일어나는 일은 짧게.** 타패·쯔모는 120ms 안쪽. 드문 사건(화료·역만·증강)에만 예산을 쓴다.
3. **판단을 가리지 않는다.** 연출이 패·점수·타이머를 덮으면 그건 연출이 아니라 방해다.
4. `screenFx` off · `prefers-reduced-motion` 은 **움직임만** 없앤다. 정보·소리·진동은 남는다.
5. **되돌림까지가 연출이다.** 전부 `gsap.context` 안에서 만들고 국이 바뀌면 revert.
6. 기존 CSS `@keyframes` 89종은 **옮기지 않는다.** 새로 만드는 것과 정확도가 필요한 것만 GSAP.

### 2026-08-21 · 0단계 + 1단계 착수

**만든 것**
- `src/fx/` — `motion`(토큰) · `setup`(플러그인·이징 등록) · `settings`(창구) ·
  `core`(장식/전달 구분, `spawnFx` 정리 보험) · `coords`(좌표) · `effects/{board,tiles}` ·
  `catalog`/`demos`(점검 목록)
- 점검 페이지 `/fx-showcase.html` — 별도 Vite 진입점, 연출 14종 등록
- 게임 배선: 흔들림(CustomWiggle) · 설정 창구 · 손패 정렬 FLIP

**테스트 서버 (운영과 분리)**
```bash
cd packages/server && PORT=3001 DB_PATH=<임시경로> npm run dev
```
운영 서버는 **3011** 에서 따로 돈다(건드리지 않았다). dev 클라이언트는 3001 을 본다.

**여기서 잡은 버그 (전부 점검하다 나온 것)**
1. `stage` useMemo 가 ref 부착 전에 한 번 돌고 `null` 을 기억 → **연출이 에러도 없이
   아무것도 안 했다.**
2. 탭이 숨겨진 동안 고스트·파문이 남는다 → `spawnFx` 에 시간 기반 제거 보험.
3. **Flip 이 손패에 px 크기를 영구히 박았다** (`width: 65.3px; min-width: …`).
   우리 패 크기는 컨테이너 쿼리 + UI 배율에서 나오므로 이게 박히면 반응형이 죽는다.
   → `scale: true`(크기를 width 가 아니라 scaleX/Y 로 다룬다) + 끝나든 끊기든 `clearProps`.
4. **Flip 의 자동 id(`auto-N`)가 자식 순서로 매겨져 렌더마다 어긋났다** → A 패의 옛
   상태가 B 패에 적용. 손패에 `data-flip-id={t${id}}` 를 박아 정체성을 고정.
5. FLIP 을 **순서만 바뀐 경우로 제한**(`isPureReorder`). 장수가 바뀌는 변화(뽑기·버리기·
   후로)는 각자 전용 연출이 있고, FLIP 을 걸면 사라진 요소 상태가 남은 요소에 옮겨붙는다.
6. 쇼케이스의 `reflowHand` 는 `flushSync` 가 필요했다 — React setState 는 비동기라
   그냥 부르면 아직 안 바뀐 DOM 을 두고 Flip 을 건다.

**환경 메모 (다음 세션도 겪는다)**
- 브라우저 창이 숨겨져 있으면 `innerWidth/Height` 가 0 이라 **컨테이너 쿼리가 무너져
  패가 2px 가 된다.** 내가 만든 버그로 오인하기 쉽다 — `resize_window` 로 크기를 준 뒤 잰다.
- 숨겨진 창에서는 rAF 가 조여져 애니메이션이 중간에 언다. 검증은
  `gsap.globalTimeline.getChildren(false).forEach(t => t.progress(1))` 로 **끝까지 감아서** 한다.

**아직 확인 못 한 것**
- 게임 안에서 **드래그 재정렬** FLIP (합성 포인터 이벤트로는 드래그가 안 잡혔다). QA 단계에서.

### 2026-08-22 · 2·4·5단계

**가장 큰 발견은 새 연출이 아니라 감사에서 나왔다.**

`transition` 66곳이 전부 브라우저 기본 `ease` 였고, 거의 같은 오버슈트 곡선이 다섯
종류로 흩어져 있었다. **개별 연출이 부족한 게 아니라 모션에 한 목소리가 없었다** —
"AI 가 만든 사이트 느낌"의 정체가 대체로 이것이다. 게다가 `--ease` 토큰은 **이미
있었는데 안 쓰이고 있었다.**

한 번 헛디뎠다: 없는 줄 알고 `--e-out` 을 새로 만들었다가, 고치려던 문제를 하나 더
만든 것을 깨닫고 있던 이름으로 합쳤다. **토큰을 더하기 전에 있는지부터 본다.**

**한 것**
- `prodSpeed` 결함 수정 — CSS `animation-duration` 은 배수로 못 곱하므로 Web Animations
  API 로 `playbackRate` 를 바꾼다. 실측 1× → 1 · 0.6× → 1.67 · 0.35× → 2.86.
- 점검 페이지가 `styles.css` 를 그대로 쓴다 — 흉내 낸 컷인으로 판단하면 그 판단이
  게임으로 안 옮겨간다. 연출 21종 등록.
- 모션 토큰 통일(위).

**물러난 것 — 잘 도는 것은 옮기지 않는다**
- **타패 비행.** 손패 자리에서 바닥으로 날아오게 만들었다가 물렸다. 바닥에는 이미
  `tile-in`(내리꽂혀 착지 스쿼시)이 있고, **CSS 애니메이션이 인라인 transform 을
  덮어쓴다.** 게다가 바로 위 주석이 "`.rt-latest` 에 animation 을 덮어쓰지 말 것"이라고
  못 박고 있었다. 새로 만들기 전에 **이미 있는지부터 본다** — 이 저장소에는 키프레임이
  89개 있다.
- **결과·점수(3단계).** rAF 카운트업 + `yaku-stamp` 가 이미 있고 잘 돈다.

**환경 — 다음 세션도 겪는다**
- 5173 은 **다른 세션의 워크트리**가 잡고 있을 수 있다. 이 작업은 **5179** 를 쓴다
  (517x 여야 클라이언트가 ws 3001 을 자동으로 본다).
- 브라우저 창이 숨겨져 있으면 `innerWidth` 가 0 이라 컨테이너 쿼리가 무너져 패가 2px 이
  된다. 내가 만든 버그로 오인하기 쉽다 — `resize_window` 로 크기를 준 뒤 잰다.
- 숨겨진 창에서는 rAF 가 멈춘다. 검증은 `gsap.globalTimeline.getChildren(false)
  .forEach(t => t.progress(1))` 로 끝까지 감아서 한다. `getAnimations()` 도 스타일 계산
  뒤에야 값을 주므로 강제 리플로 + 타이머 폴백이 필요하다.
