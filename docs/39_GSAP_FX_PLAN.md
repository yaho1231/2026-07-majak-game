> **토큰이 초기화되면 이 문서부터 읽고 이어서 한다.** 브랜치 `claude/gsap-fx`.
> 사용자 지시(2026-08-21): GSAP으로 진행 · **운영 서버는 건드리지 않는다**(로컬 dev로만 확인) ·

> 갈 정도는 지양** · 모든 연출을 볼 수 있는 **점검 페이지** · 마지막에 **서브에이전트 QA**.

## 확인하는 법

```bash
# ⚠ 반드시 **이 워크트리에서** 띄운다. 5173 은 다른 세션이 잡고 있을 수 있다
#   (실제로 그래서 한동안 남의 체크아웃을 보며 "왜 내 CSS가 안 먹지" 했다).
cd packages/client && npx vite --port 5179 --strictPort
```
- 게임: <http://localhost:5179/>
- **연출 점검 페이지: <http://localhost:5179/fx-showcase.html>** ← 모든 연출을 여기서 본다

포트가 **517x** 여야 클라이언트가 `ws://localhost:3001` 을 자동으로 본다(`App.tsx` 의
`serverUrl`). 대국까지 해 보려면 테스트 서버도 함께 띄운다 — **운영은 3011 이라 안 겹친다**:

```bash
cd packages/server && PORT=3001 DB_PATH=/tmp/majak-test.db npm run dev
```

⚠ 브라우저에 예전 서버 주소가 저장돼 있으면 계속 "재연결 중"만 뜬다:
`localStorage.removeItem("majak.serverUrl")` 후 새로고침.

**master 에 병합하지 않는다.** 사용자가 직접 확인하고 "본서버에 올려도 되겠다"고 판단한 뒤에 한다.

## 지키는 선 (사용자 지시 + 기존 저장소 원칙)

1. **차분한 기본값 + 설정으로 조절.** 100판째 플레이어에게 통과의례가 되지 않는 선이 기본값이다.
2. **매 순 일어나는 일은 짧게.** 타패·쯔모는 120ms 안쪽. 드문 사건(화료·역만·증강)에만 예산을 쓴다.
3. **판단을 가리지 않는다.** 연출이 패·점수·타이머를 덮으면 그건 연출이 아니라 방해다.
4. `screenFx` off · `prefers-reduced-motion` 은 **움직임만** 없앤다. 정보·소리·진동은 남는다.
5. **되돌림까지가 연출이다.** 전부 `gsap.context` 안에서 만들고 국이 바뀌면 revert.
6. 기존 CSS `@keyframes` 89종은 **옮기지 않는다.** 새로 만드는 것과 정확도가 필요한 것만 GSAP.

### 2026-08-21 · 0단계 + 1단계 착수

**만든 것**
- `src/fx/` — `motion`(토큰) · `setup`(플러그인·이징 등록) · `settings`(창구) ·
  `core`(장식/전달 구분, `spawnFx` 정리 보험) · `coords`(좌표) · `effects/{board,tiles}` ·
  `catalog`/`demos`(점검 목록)
- 점검 페이지 `/fx-showcase.html` — 별도 Vite 진입점, 연출 14종 등록
- 게임 배선: 흔들림(CustomWiggle) · 설정 창구 · 손패 정렬 FLIP

**테스트 서버 (운영과 분리)**
```bash
cd packages/server && PORT=3001 DB_PATH=<임시경로> npm run dev
```
운영 서버는 **3011** 에서 따로 돈다(건드리지 않았다). dev 클라이언트는 3001 을 본다.

**여기서 잡은 버그 (전부 점검하다 나온 것)**
1. `stage` useMemo 가 ref 부착 전에 한 번 돌고 `null` 을 기억 → **연출이 에러도 없이
   아무것도 안 했다.**
2. 탭이 숨겨진 동안 고스트·파문이 남는다 → `spawnFx` 에 시간 기반 제거 보험.
3. **Flip 이 손패에 px 크기를 영구히 박았다** (`width: 65.3px; min-width: …`).
   우리 패 크기는 컨테이너 쿼리 + UI 배율에서 나오므로 이게 박히면 반응형이 죽는다.
   → `scale: true`(크기를 width 가 아니라 scaleX/Y 로 다룬다) + 끝나든 끊기든 `clearProps`.
4. **Flip 의 자동 id(`auto-N`)가 자식 순서로 매겨져 렌더마다 어긋났다** → A 패의 옛
   상태가 B 패에 적용. 손패에 `data-flip-id={t${id}}` 를 박아 정체성을 고정.
5. FLIP 을 **순서만 바뀐 경우로 제한**(`isPureReorder`). 장수가 바뀌는 변화(뽑기·버리기·
   후로)는 각자 전용 연출이 있고, FLIP 을 걸면 사라진 요소 상태가 남은 요소에 옮겨붙는다.
6. 쇼케이스의 `reflowHand` 는 `flushSync` 가 필요했다 — React setState 는 비동기라
   그냥 부르면 아직 안 바뀐 DOM 을 두고 Flip 을 건다.

**환경 메모 (다음 세션도 겪는다)**
- 브라우저 창이 숨겨져 있으면 `innerWidth/Height` 가 0 이라 **컨테이너 쿼리가 무너져
  패가 2px 가 된다.** 내가 만든 버그로 오인하기 쉽다 — `resize_window` 로 크기를 준 뒤 잰다.
- 숨겨진 창에서는 rAF 가 조여져 애니메이션이 중간에 언다. 검증은
  `gsap.globalTimeline.getChildren(false).forEach(t => t.progress(1))` 로 **끝까지 감아서** 한다.

**아직 확인 못 한 것**
- 게임 안에서 **드래그 재정렬** FLIP (합성 포인터 이벤트로는 드래그가 안 잡혔다). QA 단계에서.

### 2026-08-22 · 2·4·5단계

**가장 큰 발견은 새 연출이 아니라 감사에서 나왔다.**

`transition` 66곳이 전부 브라우저 기본 `ease` 였고, 거의 같은 오버슈트 곡선이 다섯
종류로 흩어져 있었다. **개별 연출이 부족한 게 아니라 모션에 한 목소리가 없었다** —
"AI 가 만든 사이트 느낌"의 정체가 대체로 이것이다. 게다가 `--ease` 토큰은 **이미
있었는데 안 쓰이고 있었다.**

한 번 헛디뎠다: 없는 줄 알고 `--e-out` 을 새로 만들었다가, 고치려던 문제를 하나 더
만든 것을 깨닫고 있던 이름으로 합쳤다. **토큰을 더하기 전에 있는지부터 본다.**

**한 것**
- `prodSpeed` 결함 수정 — CSS `animation-duration` 은 배수로 못 곱하므로 Web Animations
  API 로 `playbackRate` 를 바꾼다. 실측 1× → 1 · 0.6× → 1.67 · 0.35× → 2.86.
- 점검 페이지가 `styles.css` 를 그대로 쓴다 — 흉내 낸 컷인으로 판단하면 그 판단이
  게임으로 안 옮겨간다. 연출 21종 등록.
- 모션 토큰 통일(위).

**물러난 것 — 잘 도는 것은 옮기지 않는다**
- **타패 비행.** 손패 자리에서 바닥으로 날아오게 만들었다가 물렸다. 바닥에는 이미
  `tile-in`(내리꽂혀 착지 스쿼시)이 있고, **CSS 애니메이션이 인라인 transform 을
  덮어쓴다.** 게다가 바로 위 주석이 "`.rt-latest` 에 animation 을 덮어쓰지 말 것"이라고
  못 박고 있었다. 새로 만들기 전에 **이미 있는지부터 본다** — 이 저장소에는 키프레임이
  89개 있다.
- **결과·점수(3단계).** rAF 카운트업 + `yaku-stamp` 가 이미 있고 잘 돈다.

**환경 — 다음 세션도 겪는다**
- 5173 은 **다른 세션의 워크트리**가 잡고 있을 수 있다. 이 작업은 **5179** 를 쓴다
  (517x 여야 클라이언트가 ws 3001 을 자동으로 본다).
- 브라우저 창이 숨겨져 있으면 `innerWidth` 가 0 이라 컨테이너 쿼리가 무너져 패가 2px 이
  된다. 내가 만든 버그로 오인하기 쉽다 — `resize_window` 로 크기를 준 뒤 잰다.
- 숨겨진 창에서는 rAF 가 멈춘다. 검증은 `gsap.globalTimeline.getChildren(false)
  .forEach(t => t.progress(1))` 로 끝까지 감아서 한다. `getAnimations()` 도 스타일 계산
  뒤에야 값을 주므로 강제 리플로 + 타이머 폴백이 필요하다.

### 2026-08-22 · 6단계 QA (서브에이전트 4명)

CSS 회귀 · fx 모듈 · App 통합 · 접근성 네 관점으로 동시에 감사했다. 수정은 파일 충돌을
피하려고 전부 메인에서 적용했다.

**치명 1건 — 빌드가 깨져 있었다.** 흔들림 CSS 를 지울 때 `@keyframes shake-4` 를 닫던
`}` 가 최상위에 남아 `vite build` 가 `Invalid empty selector` 로 실패했다. dev 서버는
minify 를 안 타서 통과했고 `npm test` 도 타입체크도 CSS 를 안 본다 — **어느 검사에도
안 걸렸다.** 브라우저는 그 `}` 를 다음 규칙의 셀렉터 시작으로 먹어 `.icon-btn` 을
통째로 죽였다.
→ `cssSyntaxGuard.test.ts` 신설. **빌드를 검증 루틴에 넣는다**(테스트·타입체크만으로는 못 잡는다).

**중대 — 같은 결함이 두 명에게 각각 잡혔다: 손패 FLIP 이 설정을 안 봤다.**
`screenFx` 도 `prefers-reduced-motion` 도 **양쪽 다 안 보는 유일한 연출**이었다.
예전엔 순간이동이라 CSS 에 가드를 걸 대상 자체가 없었고, 새로 만든 GSAP 쪽도 빠뜨렸다.
→ 검사를 `runHandFlip` **안**으로 넣고(호출부가 기억하지 않아도 되게), `fx/effects/*` 의
모든 export 가 설정 창구를 지나는지 보는 `fxGuards.test.ts` 를 신설했다.

**중대 — 내가 만든 회귀: 연출 속도가 *퇴장* 애니메이션까지 빠르게 했다.**
`--prod-ttl` 은 `prod-out` 의 지연인데, 그 요소의 재생 속도를 올려 놓고 실시간 값을
넣어 길이가 **두 번** 줄었다. 0.35× 에서 컷인이 0.2초 만에 사라지고 **빈 화면을 0.3초 더
보게 됐다**(체류의 61%). 2단계에서 고쳤다는 증상이 형태만 바꿔 되돌아온 것이다.
→ `--prod-ttl` 은 **애니메이션 시간축** 값이므로 배수로 나눠 넣는다. 여섯 조합 전부
빈 화면 0ms 로 검산했고, 기존 가드를 **풀지 않고 불변식을 하나 늘려** 잠갔다.

**중대 — StrictMode 에서 FLIP 이 항상 취소됐다.** 배열 **식별자**로 비교해서, 두 번째
렌더 패스가 1패스의 캡처를 null 로 덮었다. dev 에서만 안 도는 형태라 확인 경로가 dev
하나뿐인 이 작업에서는 치명적으로 헷갈린다. → **내용**으로 비교하고 국 경계를 키에 넣었다.

**그 밖에 고친 것**: 컷인 `innerHTML` 에 이름이 이스케이프 없이 들어가던 것(배선 전에
막았다) · 리치 무대의 비네트·섬광을 끌 수 없던 것 · 고스트가 UI 배율 아래서 수백 px
어긋나던 것 · 임팩트 지연이 속도를 안 받아 글자와 흔들림이 150ms 어긋나던 것 ·
`reduced` 초기값이 `false` 라 첫 렌더에 뚫려 있던 것 · 섬광 상한 주석과 코드 불일치 ·
파문 제거 보험이 길이와 무관하게 3초 고정이던 것 · 죽은 코드(`fxTimeline`·`prodTimeScale`·
`flyTo`) · 손패 Flip 을 모듈 전역에서 `WeakMap` 으로.

**구조 개선**: `isPureReorder` 를 `fx/reorder.ts` 로 분리했다 — `setup.ts` 가 import
시점에 이징을 등록하는데 그게 Node 에서 터져서 **순수 함수인데 단위 테스트를 못 붙였다**
(`productionQueue.ts` 가 App 에서 빠져나온 것과 같은 이유). 등록도 try/catch 로 감쌌다 —
이징 하나 때문에 화면이 통째로 안 뜨면 안 된다.

**점검 페이지에 「동작 줄이기 흉내」 스위치를 넣었다.** 정작 접근성을 검증해야 할
페이지에서 그것만 검증할 수 없었다 — 위 중대 두 건이 점검 페이지로는 발견할 방법이
없던 이유다. 실측으로 확인: 켜면 FLIP transform 0개 · 흔들림 없음 · **끝 상태는 즉시 도착**.

**신설 가드 3종**: `cssSyntaxGuard`(문법·토큰·기본 ease) · `fxGuards`(설정 창구 통과) ·
`fxPureReorder`(순수 로직). 셋 다 **버그를 되살려 실제로 실패하는 것까지 확인**했다 —
통과만 하는 가드는 가드가 아니다.

**남은 것 (판단이 필요해 미뤘다)**
- `ringAt`/`attention` 을 게임에 배선할 때 "끄면 대체 표시가 있는가"를 같이 정해야 한다.
  지금은 장식으로 분류돼 있는데, 용도가 "어디서 일어났는가"를 가리키는 것이면 정보다.
- `.hand-tile` 의 `transition: transform 0.12s` 가 FLIP 과 같은 속성을 두고 싸울 수 있다
  (의심). 드래그용 `own-hand-nofx` 가 이미 있으니 FLIP 경로에도 붙이는 것을 검토.
- 이 브랜치는 `origin/master` 보다 뒤에 있다. **병합 전 rebase** 해야 diff 를 읽는
  다음 사람이 "되돌린 줄" 오해를 안 한다.

### 2026-08-22 · 연출 강도 재조정 (사용자 피드백)

> "화면 흔들림이 너무 강해. 전체적으로 볼 때마다 어지러워. 그냥 아주 조금만 넣어도
> 충분하고, 대부분의 연출은 리치·론·쯔모·역만·증강발동 이런 국에 몇 번 없는 중요한
> 부분에만 넣고 기본적인 쯔모·타패·정렬·후로 같은 거에는 쓸데없는 연출을 좀 줄여"

**무엇을 잘못했나.** 흔들림을 GSAP 으로 옮길 때 옛 CSS 키프레임의 변위를 **그대로**
가져왔다("체감을 바꾸지 않으려고"). 그런데 그 값은 애초에 과했고, 나는 그것을
점검 페이지에서 **한 번씩 눌러 보며** 판단했다. 한 번 볼 때 적당한 세기와 한 국에
여러 번 겪을 때 견딜 수 있는 세기는 다르다 — **연출을 만드는 사람은 앞의 것만 본다.**

**측정하다 알게 된 것:** `amp` 는 실제 변위의 **절반**이다. `fromTo(x: -amp → 0)` 에
CustomWiggle 을 걸면 이징이 그 구간을 넘어 진동해 최대 변위가 `amp × 1.95` 가 된다.
처음 줄일 때 이걸 모르고 잡아서 실제로는 16% 밖에 안 줄었다. **눈금이 보이는 대로가
아니었다** — 점검 페이지에서 실측하고 나서야 알았다.

| 단계 | 예전 변위 | 지금(실측) | 감소 | 쓰는 곳 |
| --- | ---: | ---: | ---: | --- |
| 1 | 14px→ 2px | **0.95px** | 53% | 깡 |
| 2 | 5px | **1.95px** | 61% | 리치 · 증강 발동 |
| 3 | 9px | **3.89px** | 57% | 론 |
| 4 | 14px | **5.90px** | 58% | 역만 |

지속시간도 0.62 → 0.34초, 진동 8 → 5회로 함께 줄였다. **어지러움은 진폭 하나가 아니라
진폭 × 진동 횟수 × 지속시간이 같이 만든다.**

**자주 일어나는 일에서 걷어낸 것**
- **폰·치 — 흔들림 제거.** 한 국에 여러 번이라 그때마다 떨면 국이 도는 내내 화면이 흔들린다.
- **유국 — 흔들림 제거.** 아무도 화료하지 않은 사건이다. 유국 역만도 4단 → 2단.
- **타패 착지** — `translateY(-16px) scale(1.45)` → `-6px scale(1.12)`, 0.28 → 0.2초.
  한 국에 70순이 넘는다. 한 번은 시원해도 국 내내 보면 판이 계속 튀는 것으로 읽힌다.
- **쯔모** — 패 폭의 0.55배 옆에서 들어오던 것을 0.22배로, 0.19 → 0.15초.
- **손패 정렬 FLIP** — 0.42 → 0.26초, 스태거 총량 0.22 → 0.12초.

**예산을 가드로 못 박았다** (`fxGuards.test.ts`). 진폭 상한·폰치 무흔들림·유국 무흔들림·
매 순 동작의 길이 상한. 진폭을 다시 올려 **가드가 실제로 실패하는 것까지 확인**했다.
다음 사람이(또는 내가) 슬금슬금 올리는 것을 막는다.

**점검 페이지도 함께 고쳤다** — 후로 데모가 흔들리고 있었다. 점검 페이지가 게임과 다른
말을 하면 거기서 내린 판단이 게임으로 안 옮겨간다.
