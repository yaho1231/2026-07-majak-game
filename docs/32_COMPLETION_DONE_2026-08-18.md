## 1. 운영 — 조용한 실패를 없앤다 (§A)

이 묶음의 공통 주제는 하나다. **아무도 모르게 실패하고 있었다.**

### 1-1. 백업이 하나도 없었다 → `scripts/backup.sh`

- **무엇이 문제였나**: `replays/` 26MB·466판, `majak.db` + WAL 4.1MB가 복제본 0개로
  맥 디스크 하나에 있었다. 디스크가 죽으면 계정도 전적도 리플레이도 그대로 끝이다.
- **어떻게**: `sqlite3 .backup`으로 스냅샷 → `PRAGMA integrity_check` + 테이블 수 확인 →
  저널을 DELETE로 바꾸고 gzip(0600) → `replays/` 증분 미러 → 세대 14개 보관.
- **왜 그렇게**:
  - `cp majak.db`를 **쓰면 안 된다**. WAL 모드라 최근 커밋이 `-wal`에만 있고, 그대로 복사하면
    **손상된 스냅샷**이 만들어진다. 그 사실은 복구가 필요한 날에야 알게 된다.
  - **검사하지 않은 백업은 백업이 아니다.** 빈 파일도 `integrity_check`는 ok를 준다 —
    그래서 테이블 개수까지 본다.
  - 미러에 `--delete`를 **쓰지 않는다**. 원본에서 실수로 지운 것이 사본에서도 사라지면
    백업의 의미가 없다.
  - 보관본은 저널 모드를 DELETE로 바꿔 **곁파일 없이 혼자 완결**되게 한다. 복구할 때
    `-wal`/`-shm`을 찾아다닐 일이 없다.
- **확인**: 실제 운영 DB로 스냅샷·검증·2회차 증분·깨진 백업 탐지까지 실행.
  같은 디스크에 백업하면 경고가 뜨는 것도 확인(외장/NAS 권장).

### 1-2·1-3. "등록됐다"와 "돈다"는 다른 사건이었다

- **무엇이 문제였나**: 감시자가 문서상 설치돼 있었는데 `launchctl` 조회는 실패했고
  `.majak/watchdog.log`는 **파일 자체가 없었다** — 한 번도 돈 적이 없다는 뜻이다.
  원인은 macOS TCC: 저장소가 `~/Documents` 아래라 launchd가 띄운 프로세스의 파일 접근이
  막힌다. 등록은 성공하고 동작은 0회다.
- **어떻게**: `deploy/launchd.sh`로 등록 절차를 공통화하면서 **등록 직후 강제 실행 +
  종료코드 확인**을 절차에 넣었다. `npm run agents`도 등록 여부가 아니라 마지막 실행의
  종료코드를 본다. 근본 해결용으로 `deploy/relocate.sh`(저장소를 보호 디렉터리 밖으로)를 만들었다.
- **왜 부팅 전용 에이전트를 따로 두지 않았나**: 감시자가 이미 `RunAtLoad`다 — 로그인 직후
  한 번 돌면서 서버가 없으면 세운다. 그게 곧 재부팅 후 자동 기동 경로다. 별도 에이전트를
  두면 둘이 동시에 서버를 세우려 들며 서로를 밟는다.
- **남은 것**: TCC는 코드로 못 넘는다. 저장소를 옮기거나 `/bin/bash`에 전체 디스크 접근을
  주는 것 둘 중 하나가 필요하고, 둘 다 사람이 해야 한다(§7).

### 1-5. 빌드가 깨지면 서버가 내려간 채로 남았다

`restart`가 stop → 빌드 → start 순서였다. 빌드가 깨진 커밋을 배포하면 `start`가 `exit 1`
하는데 그 시점에 서버는 이미 죽어 있다. **빌드 먼저, 성공했을 때만 교체**로 뒤집었다.
한 줄 순서 바꾸기로 "빌드 실패 = 다운"이 사라진다.

### 1-6 + 2-9. 감시자가 포기해도 아무도 몰랐다

- 감시자는 재시작을 포기할 때 "손이 필요하다"를 **파일에 쓰고 정상 종료**했다. 그 파일을
  보는 사람도, 메일도, 웹훅도 없었다.
- `scripts/notify.sh`: `.majak/alerts.log` + macOS 알림 센터는 **항상**,
  `NOTIFY_WEBHOOK_URL`이 있으면 웹훅까지. 감시자 포기·복구 실패·복구 성공·백업 실패에 연결.
  복구 **성공**도 알리는 이유: 자동 복구는 원인을 없애지 않는다. 왜 누웠는지는 사람이 봐야 한다.
- `/healthz`는 예외를 삼키면서도 `ok:true`를 냈다. 게임 루프가 반쯤 죽은 좀비 상태에서도
  감시자는 정상으로 보고 개입하지 않았다. 이제 예외 횟수·마지막 발생을 세어 싣고,
  5분 안에 5번을 넘으면 `ok:false` + HTTP 500이다.
  **임계치를 보수적으로 잡은 이유**: 어쩌다 튄 예외 하나로 서버를 갈아 끼우면 사람이
  겪는 손해(진행 중 대국 전멸)가 더 크다.

### 1-7. 세션 토큰이 든 DB가 0644였다

`majak.env`는 0600으로 조이면서 정작 **세션 토큰 평문**과 비밀번호 해시가 든 DB는 열려
있었다. `SiteDb`가 부팅 때 본체와 `-wal`/`-shm`을 조인다(곁파일은 `journal_mode = WAL`이
실행된 **뒤에** 생기므로 두 번 조인다).

### 1-8. 의존성

`npm audit fix` — nanoid(high)·postcss(moderate) 제거. 남은 5건은 vite/vitest 메이저
업이 필요해 별건으로 둔다(§7).

## 2. 유저가 실제로 잃던 것 (§A·B·C)

### 2-1. 렌더 예외 = 영구 흰 화면

- **무엇이 문제였나**: 에러 바운더리가 하나도 없어서 하위 렌더 한 곳이 던지면 트리 전체가
  언마운트되고 `#root`가 비었다. 더 나쁜 건 **일회성이 아니라는 것**이다 — 새로고침하면
  재접속 → 서버가 같은 뷰를 다시 밀어 줌 → 같은 자리에서 또 터진다. 그 판이 끝날 때까지
  못 들어왔다.
- **그래서 이 화면의 핵심은 "다시 불러오기"가 아니다.** 복구 수단을 셋 주되 **잃는 것이
  적은 순서**로 세웠다: 다시 그리기(잃는 것 없음) · 방에서 나가기(`lastRoomCode`만 지움) ·
  처음부터(전부). 각각 무엇을 잃는지 아래 한 줄에 적는다.
- 오류 내용 복사 버튼으로 제보에 붙일 텍스트를 만들어 준다.
- **확인**: 브라우저에서 실제로 예외를 던져 화면·스택 토글까지 확인한 뒤 되돌렸다.

### 2-8. 쿠키 차단 브라우저에서 부팅이 터졌다

`localStorage` **접근 자체가** `SecurityError`를 던지는 환경이 있는데, 그걸 렌더 본문에서
부르는 자리가 있었다. `safeStorage`로 감싸고(실패 시 세션 메모리로 대체) 직접 호출 26곳을
없앴다. 저장이 안 되는 브라우저에서도 게임은 돌아야 한다 — 잃는 것은 자동 로그인과 설정 유지뿐이다.

### 2-3. 클라이언트가 ping을 한 번도 안 보냈다

- 프로토콜에 있고 서버도 답하는데 송신이 **0건**이었다. 모바일 NAT 만료처럼 TCP가 조용히
  죽으면 최대 60초간 `connected`인 채로 허공에 액션을 쐈다 — "눌렀는데 아무 일도 안
  일어남"의 정체다.
- 10초 주기 + 8초 마감 → 최대 18초에 알아채고 **우리가 먼저 끊는다**. 그러면 기존 재연결
  경로(지수 백오프)가 이어받는다. **새 복구 경로를 만들지 않은 것이 요점이다.**
- ⚠️ **처음 구현에서 `pong` 처리를 빠뜨려 멀쩡한 연결을 20초마다 끊었다.** 서버 로그에
  끊김/재접속 반복이 그대로 남았고 브라우저 실측에서 잡혔다. 회귀 가드를 붙였다 —
  하트비트를 넣는다는 것은 곧 그 답을 처리한다는 뜻이다.

### 2-4. 재접속 뒤 유령 프롬프트

내 차례에 끊기면 서버의 `promptCancel`은 죽은 소켓으로 나가 사라진다. 클라가 옛 프롬프트를
안 지워 지나간 선택 UI가 그대로 떠 있었고, 누르면 **"화면을 새로 받아 주세요"** — 그런데
화면을 새로 받는 방법이 프로토콜에 없었다. 사용자가 할 수 없는 일을 지시하는 문장이었다.

이제 `joined`를 "지금 떠 있는 건 전부 낡았다"는 신호로 보고 비운다. 서버는 `joined`를
**복원 전송보다 먼저** 보내도록 순서를 바꿨다 — 안 그러면 방금 복원한 프롬프트가 지워진다.

### 2-2. 끊기면 자리를 영영 잃었다

- **무엇이 문제였나**: 유예 8회 연속(2~3분)이면 이탈로 확정되는데 `joinRoom`이
  `!isAbandoned`로 걸러서 **돌아올 길이 없었다.** 좌석은 봇처럼 자동 진행돼 판은 완주되고
  그 사람 이름으로 순위·전적까지 남았다. 지하철 한 번이면 반장전 하나가 통째로 날아갔다.
- **어떻게**: 이탈에 사유를 붙였다 — `left`(스스로 나감) · `evicted`(계정 삭제) ·
  `timeout`(끊김). **timeout만 돌아올 수 있다.** 앞의 둘은 그게 본인의 결정이거나
  돌아올 계정이 없다.
- **왜 이게 옳은가**: `GRACE_TIMEOUTS_BEFORE_ABANDON`의 주석이 줄곧 *"재접속은 계속
  가능하다"* 고 적고 있었다. 의도는 처음부터 이쪽이었고 **구현만 어긋나 있었다.**
- 곁들여 `"진행 중이던 게임이 종료되었습니다"`라던 오안내도 고쳤다 — `ROOM_PLAYING`은
  대개 게임이 **아직 돌고 있다**는 뜻이다.

## 3. 첫 방문자를 잃던 지점 (§A·B·C)

### 3-2. 아이콘도 공유 이미지도 없었다

- 저장소 전체에 `favicon`·`og:image`·`manifest`가 **0건**이었다. 탭에 기본 문서 아이콘이
  뜨고, 카톡·디스코드에 링크를 붙이면 이미지 없는 카드가 나갔다.
- `packages/client/brand/`에 SVG 원본을 두고 `scripts/gen-brand-assets.sh`가 macOS 기본
  도구(`qlmanage`·`sips`)만으로 전 사이즈를 만든다 — **설치 없이 누구나 재생성**할 수 있다.
- 공유 카드는 **실제 게임 타일 에셋**을 박아 만든다(`brand/og.build.mjs`). 광고용 그림을
  따로 만들면 화면과 다른 것을 약속하게 된다.
- `favicon.ico`도 넣었다 — 없으면 링크 태그를 안 보는 도구가 루트에서 찾다가 SPA 폴백의
  **HTML을 200으로** 받고 깨진 아이콘을 표시한다.
- 곁들여: canonical·`og:url`, robots.txt + 랩 2종 `noindex`, `<noscript>` + 부팅 스플래시,
  `color-scheme: dark`, 트위터 카드를 `summary_large_image`로.
  description의 "104종"(실제 113)은 **숫자를 뺐다** — 테스트가 다시 못 박지 못하게 막는다.

### 3-3. 게스트 첫 판이 봇 최선이었다

대기실을 안 거쳐 고를 화면조차 없는 사람의 첫 판이 skill 1.0 봇 셋이었다. 체험만
`normal`(0.7)로 낮췄다. **`easy`(0.35)까지 내리지 않은 이유**: 마작을 아는 사람이 이
게임을 보러 왔을 때 봇이 헛수를 두면 게임 자체가 얕아 보인다. 방을 직접 만들면 기본은
그대로 `hard`다.

### 3-8·3-9. 퍼널의 끊긴 한 클릭

- 체험 뒤 "계정 만들고 계속하기"를 누른 사람이 **로그인 폼**을 보고 다시 "회원가입"을
  눌러야 했다.
- 규칙·도감 단추가 랜딩·홈·게임 중·게스트 종료 화면엔 전부 있는데 **대기실에만 없었다.**
  친구를 기다리는 그 시간이 규칙을 읽기 가장 좋은 시간이다.

### 3-4. 랜딩이 텍스트 두 줄이었다

이 게임의 유일한 차별점("규칙을 바꾸는 증강")이 **클릭 전에는 한 문장으로만** 전달됐다.
실제 증강 셋(사방치기·단색 세계·함구령)을 실제 패 그림으로 보여 준다 — 도움말과 **같은
컴포넌트·같은 에셋**이라 화면과 다른 것을 약속하지 않는다.

곁들여 `autoFocus`를 뺐다: 포커스된 칸을 브라우저가 화면 안으로 끌어오면서 제목과 시작
버튼을 위로 밀어냈다(실측 `scrollTop 142`). 처음 온 사람이 가장 먼저 봐야 할 것은
로그인 칸이 아니다.

### 3-5. 친구를 부르는 일이 세 단계였다

복사되는 건 여섯 글자뿐이라 받는 사람이 사이트를 찾고, 코드 칸을 찾고, 옮겨 적어야 했다.
이제 **초대 링크**(`?room=CODE`)를 복사하고, 링크로 들어오면 로그인 직후 그 방에 앉는다.
코드는 형식 검사를 거치고(남이 만든 링크다) 한 번 쓰면 주소창에서 지운다 — 남겨 두면
새로고침마다 그 방으로 끌려가고, 방이 사라진 뒤에는 매번 실패 토스트만 본다.

### 5-1. 빈 상태가 거짓말을 했다

홈 목록이 `[]`로 시작해 로그인 직후 **"저장된 리플레이가 없습니다"**가 떴다가 갑자기
채워졌다. 사용자에게 그건 로딩이 아니라 거짓말 한 번이다. `null`(모른다)과 `[]`(없다)를
구분하고, 세 상태를 `ListCard` 한 곳에서 정한다. 정말 빈 카드에는 다음 한 걸음을 덧붙였다.

## 4. 건넬 말과 잘못 짚은 손가락 (§C)

### 4-9. 대화 수단이 0이었다

- 4인 대전인데 "감사합니다" 한 마디가 없어 외부 음성채팅이 사실상 필수였다.
- **자유 채팅을 열지 않은 이유**: 욕설·인신공격을 걸러야 하는데 그건 이 규모의 운영이
  감당할 일이 아니다. 고정 문구 8종은 그 사이의 답이다 — 사교는 되고 모더레이션은 필요 없다.
- 목록에 **재촉·조롱을 넣지 않았다.** 고정 문구의 장점은 나쁜 말을 애초에 만들 수 없다는
  것인데, "빨리 두세요"를 넣으면 그 장점을 스스로 버린다.
- 서버가 목록에 없는 값을 거르고(자유 채팅으로 가는 문을 열지 않는다), 같은 방에만 나가고,
  10초 5회로 도배를 막는다. 관전자도 본다 — 안 그러면 관전은 소리 없는 화면이 된다.

### 5-2. 한 번 잘못 짚으면 그대로 나갔다

- 375px 폰에서 패 하나는 **폭 26px에 간격 2px**인데 원탭 즉시 타패였다. 리치 선언에는
  2단계 게이트가 있는데 평범한 타패에는 아무 장치도 없었다.
- **두 번 눌러 버리기**: 첫 탭은 패를 들어 올리고(“한 번 더” 배지), 두 번째에 나간다.
  다른 패를 누르면 그쪽으로 옮겨 간다. 순이 바뀌면 내린다 — 지난 순의 선택이 남아 있으면
  무심코 한 번 누른 것이 곧바로 타패가 된다.
- **터치 기기에서만 기본 켜짐**(마우스는 정확하므로 데스크톱의 한 번 클릭 감각은 그대로).
- 탭 목표는 **세로로만** 넓혔다. 가로로 넓히면 간격이 2px뿐이라 옆 패의 목표와 겹치고,
  겹치면 "엉뚱한 패가 나간다"가 오히려 늘어난다.

## 5. 성능 — 첫 화면 794 KB → 171 KB (§D)

### 무엇이 문제였나

로그인 화면 하나를 그리는 데 **증강 구현 117개(1.2MB)와 서버 전용 엔진**
(`HanchanController`·`standardActions` 등)을 전부 받아 파싱했다. 원인은 두 줄이었다:

1. `AUGMENT_KINDS = contentAugments.length` — 종수를 세려고 배열을 참조했다.
2. `replayRebuild`의 정적 import — 이쪽이 실제 앵커였다.

**트리셰이킹으로는 못 뺀다.** 배열이 참조되면 117개가 전부 살아야 하고, `defineAugment`가
검증 실패 시 `throw`하는 부수효과 함수라 롤업이 각 모듈을 순수로 판정하지도 못한다.

### 어떻게

- 종수는 서버가 `serverInfo`로 알려 준다. **인증 전에** 오는 값이라 랜딩에서 규칙을 펼친
  사람에게도 올바른 숫자가 보인다(카탈로그와 같은 출처라 어긋나지 않는다).
- `replayRebuild`는 **동적 import**. 판을 되짚으려면 그때 그 증강이 실제로 있어야 하므로
  의존 자체는 옳다 — 옳지 않았던 건 그게 **첫 화면에** 있던 것이다. 경계를 옮겼다.
- `core`·`content`에 `sideEffects: false`.
- 정적 자산을 **gzip**한다(이미 압축된 png·woff2 제외, 1KB 미만 제외, `Vary: Accept-Encoding`).
  Caddyfile 예시에도 `encode zstd gzip`을 넣었다 — 배포 경로가 둘이라(Caddy / 터널 직결)
  한쪽에만 두면 다른 쪽에서 압축이 통째로 빠진다. 실제로 빠져 있었다.

### 실측 (브라우저 Resource Timing, 프로덕션 빌드 + 실서버)

| | 전 | 후 |
|---|---|---|

| 리플레이 청크 | (첫 화면에 포함) | 368,075 B — **리플레이를 여는 사람만** |

**덤**: `{error ?? "재구성 중…"}`이 살아났다. 재구성이 동기라 `null`인 순간이 없어
**절대 렌더되지 않던** 문구였는데(감사 §5-17), 이제 청크를 받는 동안 실제로 보인다.
