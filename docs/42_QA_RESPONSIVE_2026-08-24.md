# 창 크기 자동 맞춤 — 손잡이를 없애고 배치를 창에 맞춘다 (2026-08-24)

사용자 보고: 「인터넷 자체 줌 기본 · 인게임 퍼센트 기본」인 1850×860 창에서 판이 깨진다.
직접 −를 눌러 60%까지 줄이면 깔끔해진다. **그 −/+ 자체를 없애고 어느 창에서든 그 깔끔한
그림이 나오게 해 달라.**

브라우저(크로뮴)로 실제 판을 돌리며 잰 것만 적는다. 재는 도구는
[`qa-lab/layout/probe.js`](../qa-lab/layout/probe.js) — 겹치면 안 되는 그룹끼리 실제 사각형이
얼마나 물리는지, 화면 밖으로 나갔는지, 상자를 넘쳤는지를 한 번에 돌려준다.

## 0. 결론

- 화면의 −/+ 손잡이(`.ui-zoom`)와 Alt +/− 단축키, 저장 키(`majak.uiZoom`)를 전부 없앴다.
- 배율은 이제 **창 하나에서 나온다**: `clamp(min(w/1920, h/1080), 0.75, 2)`.
- 데스크톱 15개 창 크기에서 **겹침 0건**. 고친 것 4건(§2), 남긴 것 3건(§4).

## 1. 왜 깨졌나 — 세로 예산이 전부 고정 px 였다

판의 세로는 이렇게 나뉜다(레이아웃 px, 1850×860 실측):

```
위 띠 76 + 숨통 32 + 아래 띠 267(손패 162 + 오름패 줄 75 + 줄 간격·여백 30)
→ 남는 세로 = H − 375 = 중앙 보드의 세로(--board × 0.9)
→ 중앙 패널 = --board × 0.348
```

세 몫이 **전부 고정 px** 라, 창이 짧아질수록 이들이 세로를 다 먹고 보드만 쪼그라든다.
패널을 강제로 줄여 가며 실측한 임계값:

| 패널(레이아웃 px) | 상태 |
|---|---|
| 276 | 여유. 국 표시·도라·네 방향 점수판이 각자 자리에 있다 |
| ~190 | 빠듯하지만 겹치지 않는다 |
| **152** | **깨진다** — 위쪽 점수판이 "東3국" 위로, 아래쪽이 도라 줄 위로 얹힌다 (= 사용자 보고 화면) |

사람이 −를 누르면 **띠까지 함께 줄어들어** 보드가 살아났다. 즉 사용자가 손으로 반응형을
하고 있었다. 그래서 그 계산을 코드로 옮겼다.

### 2-1. 배율 식

```
scale = clamp(min(창너비 / 1920, 창높이 / 1080), 0.75, 2.0)   ← 소수 둘째 자리로 «버림»
```

`min()` 이라 **가상 뷰포트(= 창 / scale)가 어느 쪽도 1920×1080 아래로 안 내려간다.**
곧 16:9 창은 1366×768이든 4K든 가상 1920×1080으로 수렴해 **같은 그림이 크기만 다르게** 선다.
버림인 이유: 반올림하면 1512×982에서 가상 폭이 1913px 로 6px 모자란다.

하한 0.75는 글자(15px → 11.25px)가 읽히는 선, 상한 2.0은 4K가 원판을 정확히 두 배로
그리는 값이자 WCAG 1.4.4가 요구하는 확대 폭이다.

배율로 다 못 푸는 구간(하한에 걸리는 아주 납작한 창)은 `styles.css` 의
`@container ui (max-height: 900px / 760px)` 안전망이 오름패 줄·손패·숨통을 함께 줄여 받는다.

## 6. 후속 — 왜 첫 배포로 안 고쳐졌나 (같은 날, 사용자 재보고)

배포 뒤에도 사용자 화면은 그대로 깨져 있었다. 같은 창(1827×852)에서 `--ui-scale` 이
0.78이 아니라 **1** 이었다. 원인은 새 배율 식이 아니라 그 앞의 조기 반환이었다:

```js
if (userZoomedIn()) return 1;   // ← 자동 맞춤을 통째로 끈다
```

`userZoomedIn()` 은 "이 사람은 브라우저 확대를 쓴다"를 **localStorage
(`majak.browserZoomed`)에 저장**했다. WCAG 1.4.4 를 지키려던 장치인데, 실제로는 덫이었다:

- Ctrl/⌘ **+** 를 한 번이라도 누르면 붙는다.
- 축소해 둔 채 연 페이지에서 Ctrl+0 을 눌러도 붙는다(부팅 시점 dpr 이 기준선이므로 «올라간» 것으로 읽힌다).
- 창을 Retina 모니터로 옮겨도 붙는다.
- 한 번 붙으면 **다음 세션에도 그대로 살아나** 창이 무엇이든 배율이 1로 굳는다.

재현(실측): `localStorage.setItem("majak.browserZoomed","1")` → 새로고침 →
1827×852 에서 `--ui-scale` 이 0.75 → **1** 로 바뀌고 사용자 화면과 똑같이 깨진다.

### 고친 방식 — 끄지 말고 곱한다

```
zoomFactor = clamp(dpr / 부팅 때 dpr, 0.5, 2)      // 이 세션에서 사람이 누른 확대
scale      = clamp(fit(창) × zoomFactor, 0.75, 2)
```

브라우저 확대 z 는 CSS 픽셀 창을 정확히 1/z 로 줄인다 → 맞춤이 배율을 1/z 로 낮춰
**요구한 확대를 정확히 상쇄**했던 것이 문제의 뿌리였다. z 를 도로 곱하면 상쇄가 풀리고,
화면에 보이는 크기가 정확히 z 배가 된다. **저장은 하지 않는다** — 부팅하면 언제나
배수 1(= 순수 자동 맞춤)이라 어떤 경로로도 굳지 않는다.

실측(1827×852 기준 창을 z 만큼 줄이고 dpr 을 z 배로 올려 흉내):

| 브라우저 확대 | 창(CSS px) | 곱하기 없이 | 지금 | 화면에서 |
|---|---|---|---|---|
| 100% | 1827×852 | 0.78 | **0.78** | 기준 |
| 150% | 1218×568 | 0.75 (요구가 깎인다) | **0.78** | 정확히 150% |
| 200% | 913×426 | 0.75 (요구가 깎인다) | **0.78** | 정확히 200% |

이미 표식이 붙어 있는 사람이 있으므로 `majak.browserZoomed` 는 부팅 때 **지운다**
(`majak.uiScale`·`majak.uiZoom` 과 같은 자리). 실측으로 세 키 모두 지워지는 것을 확인했다.

### 6-1. 그 대가 (기록해 둔다)

확대를 켜 **둔 채** 페이지를 열면 부팅 시점 dpr 이 기준선이라 그 확대는 자동 맞춤에
상쇄된다. 판을 연 뒤 한 번 더 누르면 그대로 듣는다. «판이 깨진 채 굳는» 예전 동작보다는
이쪽이 낫다고 보고 고른 거래다.
