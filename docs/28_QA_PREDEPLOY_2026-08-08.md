## 1. BLOCKER

### B-1. 일반 후로 뒤에 우는 국사무쌍을 부르면 그 국이 수학적으로 화료 불가 [확인]
`packages/content/src/augments/open_kokushi.ts:121-156`

`kokushi_pon` 의 validate 는 요구패 중복만 막고, **이미 일반 멘쯔를 가진 사람**은 막지 않는다.
백을 퐁한 뒤 국사 퐁을 부르면 그 순간 `kokushiOnly=true`(`helpers.ts:199`)가 되어 표준·치또이
분해가 꺼지는데, 멜드 국사 분기는 `K === meldCount*3`(`decompose.ts:915`)을 요구한다.
일반 멘쯔가 하나 섞이면 K=3·meldCount=2 라 **영원히 안 맞는다**.
직접 실행 확인: `decompose(hand, 2, {kokushiOnly:true, kokushiMeldKinds:[1m,1p,1s]})` → `[]`.
결과: 화료도 텐파이도 불가, 그 국 노텐 확정. **봇도 이 경로를 밟는다** (`:195-206`).

### B-2. 끊긴 사람이 있으면 대국을 영원히 중단시킬 수 없다 [확인 — 실서버 재현]
`packages/server/src/RoomManager.ts:2226-2229`

`humans` 가 `!a.isAbandoned` 만 보고 `isConnected()` 를 안 본다. 소켓이 죽은 좌석은 정족수에
계속 세지지만 표를 낼 수 없다. 그리고 **연결 끊김이 `abandoned` 로 승격되는 경로가 없다** —
명시적 `leaveRoom`(`:1041`)이나 `evictUser`(`:2111`)뿐이다.

실서버 재현: 사람 2 + 봇 2, H2 `ws.terminate()`, H1 이 `voteAbort:agree` →
`{votes:1, needed:2}` 가 45초·4회 반복 동안 그대로. `gameAborted` 없음.
남은 사람은 아래 B-3 때문에 **1/3 속도로 도는 판**에 갇혀 브라우저를 닫는 것 말고 탈출구가 없다.

### B-3. 끊긴 좌석의 모든 결정이 끝까지 5초씩 걸린다 [확인 — 실측]
`packages/server/src/HumanAgent.ts:34, 400-403` (`DISCONNECT_GRACE_MS = 5_000`)

에스컬레이션이 없다. 2번째 턴도 200번째 턴도 5초를 꽉 채운다.
실측: 45초 창에서 5.01초 정지 6회. **국 길이 24.5초 → 72.5초 (약 3배)**.
`sweepIdleRooms`(`RoomManager.ts:601-616`)는 컨트롤러가 살아 있는 `playing` 방을 **명시적으로
건너뛴다**. QA 서버에서 시험 방 14개가 접속 0인 채로 각각 10분 넘게 남아 천천히 소진됐다
(14 → 11 이 5분). 방향: 연속 grace 타임아웃 N회 뒤 `agent.abandon()`.

### B-4. 게임 루프에 예외 그물이 없다 — 봇 하나가 던지면 사람의 반장전이 삭제된다 [확인]
`packages/core/src/match/HanchanController.ts:764, 842, 963`

`runRound`/`runDraft`/`runLoop`/`broadcastViews` 에 `try/catch` 가 **0개**. 모든 throw 가
`RoomManager.ts:2949` 로 올라가 `GAME_CRASHED` 를 보내고 **방을 삭제**한다.
반응·드래프트 창은 `Promise.all` 이라 첫 rejection 에서 단락되어 나머지 세 좌석의 진행 중 결정까지
날린다. `BotAgent` 가 내부 그물을 셋이나 두고 있는 이유가 이 바깥층에 하나도 없기 때문이다.
게다가 "마지막 안전망" `decideSafely`(`BotAgent.ts:406→421`) 의 catch **자체가 던진다**
(`fallbackOption([])`, 재현됨).

### B-5. 봇 결정에 타임아웃이 없다 — 영구 소프트락 [미확인, 경로는 확정]

해결되지 않는 봇 프로미스 하나면 방이 영구히 `playing` 으로 남고, 좀비 스위퍼는 그 방을
건너뛴다. **재시작 없이 오래 켜 두는 조건에서 이게 정확히 그 시나리오다.**

### B-6. 백프레셔 가드가 잘못된 함수에 붙어 있다 — 메모리 고갈
`packages/server/src/HumanAgent.ts:605-609`

## 5. 확인한 결과 **문제없는** 것

배포 판단에 필요하니 명시한다. 전부 추측이 아니라 코드를 따라가 확인했다.

**보안 — 대체로 매우 단단하다.**
- 정보 은닉이 **구조적으로** 안전하다. `buildPlayerView` 가 유일한 통로이고 미지의 존은 `hidden` 으로
  **닫히는 쪽으로 실패**한다. 감춰야 할 패는 플래그가 아니라 **와이어에 아예 없다**
  (`collectVisibleTileIds`). 뒷도라는 국 종료 시점 호출자 인자로만 실린다. PRNG 시드는 어떤 뷰에도 없다.
  관전 전권 뷰는 관리자 게이트 2곳뿐이고 자기 방 자가관전은 거부된다.
- SQL 인젝션 없음 — `SiteDb.ts` 전체에 문자열 보간 0건, 전부 바인딩, 동적 `ORDER BY` 없음.
- 경로 탐색 없음 — 사용자 문자열이 파일 경로에 닿지 않는다. 정적 서버는 디코드→정규화→prefix→`realpathSync`.
- XSS 없음 — 클라 전체에 `dangerouslySetInnerHTML`·`innerHTML`·`eval` 0건, `href` 속성 자체가 없다.
- 인증: scrypt + 개별 salt + `timingSafeEqual` + 미지 사용자 더미 해시 + 등록 타이밍 오라클 차단,
  세션 256bit·TTL·10개 상한, 예약어에 `__proto__` 포함, 게스트 이름에 금지문자 사용.
- **실서버 공격 시험 전부 방어** — 남의 좌석 대행(위조 `seat` 는 자기 좌석으로 되돌아옴), 제시되지
  않은 액션·증강, 범위 밖/음수/객체 tileId, 5000원소 배열, 비JSON 프레임: 전부 거부되고
  매 시도 후 `/healthz ok:true`.

**게임 로직**
- 콜 우선순위 정확 — 론 > 펑/대명깡 > 치, 동률은 방총자와의 거리(도착 순서 아님). 삼가화 유국.
- 점수 계산 다수 실측 일치 — 치또이 25부, 핑후 멘젠 쯔모 20부/론 30부, 안커·밍커, 깡 4종 부수,
  연풍패 +4, 샨퐁 론의 산안커 실패·쯔모 성공, 이페코/료페코 배타, 국사 13면(×2)·순정구련(×2),
  역만 중첩(×5), 카조에 13판=32000, 노텐 벌부 전 조합, 기리아게 만관 없음.
- 드래프트 정합 — 32,000 + 24,000 회 시뮬에서 짧은 제시 0, 빈 제시 0, 이미 보유 0, conflict 위반 0,
  같은 스테이지 좌석 간 중복 0, 게임 내 중복 0. 소프트락 없음. 확률에 음수·NaN·0 불가.
- 카탈로그 무결 — 117종, 중복 id·이름 0, 빈 설명 0, 전원 티어·계열 보유, 없는 conflict id 0,
  자기 conflict 0, 클라/서버의 유령 id 0. **뽑을 수 없는 증강 없음.**

  `GameState`/wall import 없음. 4,000회 퍼징에서 목록 밖 선택 0, throw 0.
