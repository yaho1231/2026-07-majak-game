## H-1. [높음] 미인증 연결이 전역 연결 슬롯을 통째로 점유한다

**발견**. 두 상수가 서로를 모른 채 움직였다.

- `MAX_CONNECTIONS = 300` — 전역 동시 WS 연결 상한. **인증 여부를 구분하지 않는다.**
- `UNAUTH_TIMEOUT_MS` — 미인증 유예. 예전엔 30초였는데, "로그인 화면에 앉아 있기만 해도
  30초마다 끊김/재연결이 반복된다"는 정당한 이유로 **10분**으로 올랐다
  ([RoomManager.ts:377](../packages/server/src/RoomManager.ts#L377)).

그래서 미인증 스쿼팅의 비용이 20배 싸졌는데, 그걸 받아 주는 전역 슬롯은 그대로다.

**공격**. IPv6 `/64` 버킷 19개(= `/48` 하나면 65536개 중 19개)에서 각각 16개씩 연결을 열고
아무것도 보내지 않는다. 10분마다 다시 열기만 하면 된다. 신규 연결 속도 제한
(`CONN_RATE_MAX` 40회/10초/버킷)에도 걸리지 않는다 — 버킷당 16개씩 열 뿐이다.

전역 300칸이 차면 `handleConnection`이 **누구에게든** 1013 "server busy"를 돌려준다.
잃는 것은 신규 접속만이 아니다:

- 진행 중인 반장전에서 잠깐 끊긴 사람이 **재접속할 슬롯이 없다** → 8회 유예 초과로
  이탈 확정 → 그 판이 봇 자동 진행으로 흘러간다.
- 방장이 새로고침하면 방으로 못 돌아온다.

즉 한 번 채우면 서버가 40분짜리 판들을 스스로 태운다.

**조치(제안)**.
1. 미인증 연결 전용 상한을 따로 둔다 — 예: `MAX_UNAUTH_CONNECTIONS = MAX_CONNECTIONS * 0.4`.
   `conn.user === null`인 연결 수를 세어 그 이상이면 새 미인증 연결을 거절한다.
2. 전역 상한 근처에서는 **미인증 연결부터 축출**한다(가장 오래된 미인증 연결을 끊고 자리를 내준다).
   인증된 사람의 재접속이 익명 소켓에 밀리지 않게 하는 것이 핵심이다.
3. `/healthz`에 `unauthConnections`를 추가해 이 상황이 눈에 보이게 한다(L-1과 함께 처리).

## H-2. [높음] `TRUST_PROXY`가 켜졌는데 신뢰 헤더가 없으면 **면제**로 떨어진다

**발견**. [index.ts:358](../packages/server/src/index.ts#L358) `clientIpOf`:

```ts
if (TRUST_PROXY === "cloudflare") {
  const cf = headerValue(req.headers["cf-connecting-ip"]);
  return cf !== undefined ? { ip: cf, local: false } : { ip: socketIp, local: true };
  //                                                                   ^^^^^^^^^^^
}
```

`local: true`는 그대로 `conn.exempt`가 되어 **연결 상한 · 메시지 토큰버킷 · 인증 무차별대입
차단 · 방 생성 제한 · 신규 연결 속도 제한이 전부 해제**된다. `xff` 모드도 같은 모양이다.

**왜 문제인가**. `TRUST_PROXY`를 명시적으로 켰다는 것은 "이 서버 앞에는 프록시가 있고, 헤더는
반드시 온다"는 선언이다. 그러므로 **헤더가 없는 요청은 이상 신호**다. 그런데 지금은 그 이상
신호를 "가장 신뢰받는 연결"로 해석한다. 2026-08-05 감사 #1이 고친 것과 정확히 같은 실패
모양이다 — 방어가 조용히, 로그 한 줄 없이 사라진다.

**공격 가능성**. 현재 배포는 `HOST=127.0.0.1` + cloudflared라 소켓 상대가 루프백인 경로에
도달하려면 이미 그 머신 안에 있어야 한다. 그래서 **오늘 당장 원격에서 뚫리지는 않는다.**
문제는 이 안전이 오직 `HOST=127.0.0.1` 한 줄에 걸려 있다는 점이다. `HOST`를 비우는 순간
(포트포워딩 테스트, 프록시 교체, LAN 노출) 헤더 없이 직접 붙는 모든 연결이 면제 대상이 된다.

**조치(제안)**.
```ts
// TRUST_PROXY가 설정돼 있으면, 신뢰 헤더가 없는 연결은 면제하지 않는다.
return cf !== undefined ? { ip: cf, local: false } : { ip: socketIp, local: false };
```
그리고 그 경우 **경고 로그를 남긴다**(프록시 설정이 깨졌다는 유일한 신호다). 로컬 개발은
`TRUST_PROXY`가 비어 있으므로 영향받지 않는다.

## M-1. [중간] 요청 비용이 제각각인데 레이트리밋은 개수만 센다

**발견**. 방어는 연결당 토큰버킷 하나뿐이다 — `MSG_BUCKET_CAPACITY 80` · 초당 40 리필.
그런데 메시지들의 실제 비용은 세 자릿수로 갈린다.

| 메시지 | 1회 비용 |
|---|---|
| `ping` | 무시할 수준 |
| `replayList`(일반) | **동기** SQLite 쿼리 51회 (`listGamesFor` 1 + `hydrate` 50, [SiteDb.ts:655](../packages/server/src/SiteDb.ts#L655)) |
| `replayList`(관리자) | **동기** SQLite 쿼리 201회 (`listAllGames` 200판) |
| `replayGet` | 최대 250KB 파일 `readFile` + 정규식 `split` + 배열 `JSON.stringify` (운영 replays/ 실측: 433개 23MB, 최대 252KB) |
| `adminUsers` | 계정마다 상관 서브쿼리 (`COUNT(DISTINCT game_id)`), 동기 |

`node:sqlite`는 **동기**다. 그리고 `hydrate`는 호출마다 `prepare()`를 새로 한다(구문 컴파일 포함).

**공격**. 계정 하나(가입 코드만 통과하면 된다)로 `replayList`를 초당 40회 보낸다.
일반 계정 기준 초당 약 2,000회, 관리자 계정이면 8,000회의 동기 쿼리가 이벤트 루프에서 돈다.
이벤트 루프가 멈추면 **그 서버에서 진행 중인 모든 대국이 함께 멈춘다** — 봇 판단·타이머·
뷰 브로드캐스트가 전부 같은 루프에 있다. 리더보드는 이미 캐시로 고쳤지만
([RoomManager.ts:1992](../packages/server/src/RoomManager.ts#L1992)), 같은 부류의 나머지는 그대로다.

`MAX_BUFFERED_BYTES`(4MB) 백프레셔 가드는 도움이 되지 않는다 — 공격자가 응답을 정상적으로
읽으면 버퍼가 차지 않고, 비용은 이미 서버가 다 치른 뒤다.

**조치(제안)**.
1. **비싼 메시지에 별도 창**을 둔다: `replayGet`·`replayList`·`adminUsers`는 계정당 5초에 1~2회.
   (게임 진행 메시지 `action`·`handOrder`는 지금 버킷 그대로.)
2. `hydrate`의 `prepare()`를 생성자에서 한 번 만들어 재사용한다.
3. `replayGet` 응답에 줄 수·바이트 상한을 두고, 넘으면 잘라 보내거나 거부한다.

## M-2. [중간] 솔로 대국 무효 투표로 성적을 세탁할 수 있다 — **아직 열림**

2026-08-05 감사 #12가 [보류]로 남긴 항목이 그대로 살아 있다
([RoomManager.ts:2364](../packages/server/src/RoomManager.ts#L2364) `retallyAbortVotes`).
사람 1명 + 봇 3명 방에서 `needed === humans.length === 1` — **혼자서 언제든 판을 무효로 만든다.**
무효 판은 정산·순위·통계·리플레이를 남기지 않으므로, 지고 있을 때만 누르면 리더보드에는
이긴 판만 쌓인다. 창을 닫는 이탈은 순위가 그대로 기록되므로 무효 쪽이 **엄격히 더 유리**하다.

셋 중 무엇을 택할지는 "리더보드가 무엇을 재는 표인가"에 달렸고, 그건 게임 설계 결정이다:
1. 사람 2명 이상일 때만 무효 허용
2. 무효 판도 "참가 기록"은 남긴다 (순위 없음, 판 수만)
3. 솔로(봇 3) 대국을 리더보드 집계에서 분리한다 — 통계적으로도 이게 맞다

**결정해 주면 바로 넣는다.**

## M-3. [중간] 비밀번호 변경·세션 일괄 무효화가 없다 — **아직 열림**

`grep`으로 재확인: `changePassword`·`revokeSession`·`logoutAll` 어느 것도 구현이 없다.
세션 토큰 수명은 30일(`DEFAULT_SESSION_TTL_MS`)이고, 사용자가 스스로 끊을 방법은 없다.
지금 세션을 실제로 무효화하는 유일한 경로는 **관리자의 계정 삭제**(`evictUser`)다.

토큰은 `localStorage`에 있으므로(L-4·클라이언트 구조상 불가피), 기기를 잠깐 빌려주거나
공용 PC에 로그인한 채 두면 30일간 회수 수단이 없다.

**조치(제안)**: 비밀번호 변경 + 변경 시 그 계정의 세션 전부 삭제 + "다른 기기 로그아웃" 버튼.
`sessions` 테이블에 `user_id` 인덱스가 이미 있으므로 삭제 자체는 한 줄이다.

## M-4. [중간] 운영 중인 `SIGNUP_CODE`가 5자

**발견**. `deploy/majak.env`의 실제 값 길이가 **5자**다(값은 확인하지 않았다).
가입 게이트는 이 서비스에서 계정 공간을 지키는 1차 방어선이다 — 통과하면 리더보드·제보
게시판·리플레이 목록·방 생성이 전부 열리고, M-1의 비싼 쿼리도 그때부터 쏠 수 있다.

**공격**. 두 방향이다.
- **추측**: 5자짜리 사람이 정한 코드는 사전 단어일 가능성이 높다. 인증 레이트리밋
  (`/64` 버킷당 30회/분)이 늦추긴 하지만 늦출 뿐이고, 버킷을 갈아 가며 시도할 수 있다.
- **유출**: 초대받은 사람 **전원이 아는 공유 비밀**이라 대화방·스크린샷으로 새기 쉽고,
  샜다는 사실을 알 방법도 회전할 방법도 없다.

**조치(제안)**: 16자 이상 랜덤(`openssl rand -base64 16`)으로 교체. 여유가 되면
1회용 초대 코드(발급·소진·만료)로 옮기는 편이 근본적이다 — 관리자 코드가 이미 그 구조다.

## L-1. `/healthz`가 무인증

`uptimeSec` · `wsClients` · `connections` · `rooms` · `playing` · `waiting`을 누구에게나 돌려준다
([index.ts:238](../packages/server/src/index.ts#L238)). 개인정보는 없지만, H-1 공격자에게
**"내가 슬롯을 몇 개나 먹었는지"를 실시간으로 보여 주는 계기판**이 된다.

**조치**: Cloudflare 쪽에서 `/healthz`를 차단하고 감시자는 `127.0.0.1`로만 부른다
(`watchdog.sh`가 이미 로컬로 부른다). 또는 헤더 토큰 하나.

## L-2. `deploy/majak.env` 권한이 0644

`SIGNUP_CODE`가 든 파일이 `-rw-r--r--`다. 같은 머신의 다른 사용자·프로세스가 읽을 수 있다.

**조치**: `chmod 600 deploy/majak.env`.

## L-3. CSP `connect-src`가 임의 WS 서버를 허용

`connect-src 'self' ws: wss:` — 스크립트 주입에 성공했을 때 자격증명을 외부로 보내는 마지막
경로다(`form-action 'none'`으로 폼 경로는 이미 닫혀 있다). 고급 설정의 "서버 주소 수동 지정"을
살리려고 열어 둔 것이라, 그 기능의 가치와 맞바꾸는 판단이다.

**조치**: 수동 서버 주소를 포기할 수 있으면 `connect-src 'self'`로 좁힌다.

## L-4. 리플레이 `gameId` 존재 여부 열거

`replayGet`이 없는 id에는 `REPLAY_NOT_FOUND`, 남의 판에는 `FORBIDDEN`을 돌려준다
([RoomManager.ts:2256](../packages/server/src/RoomManager.ts#L2256)). 코드가 다르므로 id를 훑으면
"지금까지 몇 판이 치러졌는가"를 알 수 있다. 판 내용은 새지 않는다.

**조치**: 두 경우를 같은 응답으로 합친다(권한 없는 것은 존재하지 않는 것과 구분되지 않게).

## L-5. 게스트 체험 슬롯을 소수의 IP가 독점할 수 있다

`MAX_GUEST_ROOMS` 16 · IP(`/64`)당 3. `/64` 버킷 6개면 전역 손님 자리 전부가 한 사람 것이 된다.
방문자에게는 "체험 게임이 가득 찼습니다"만 보인다. 계정이 필요 없어 진입 장벽이 0이다.
게스트 방은 연결이 끊기면 함께 사라지므로 H-1을 고치면 상당 부분 함께 닫힌다.

## L-6. `abuseKeyOf` — 16진 IPv4-mapped 표기가 한 버킷으로 뭉친다

`::ffff:1.2.3.4`(점 표기)는 IPv4로 정확히 풀리지만, `::ffff:0102:0304`(16진 표기)는 정규식에
걸리지 않아 IPv6 경로로 가고 앞 4그룹이 전부 0이라 **모든 주소가 `0:0:0:0::/64` 한 버킷**이 된다
([RoomManager.ts:522](../packages/server/src/RoomManager.ts#L522)).
Node는 점 표기를 주므로 지금은 영향이 없지만, 프록시 헤더에서 그 표기가 오면 서로 다른
사용자들이 한 버킷을 공유해 **서로를 밀어낸다**(과도 차단 — 뚫리는 쪽이 아니라 막히는 쪽).

**조치**: `::ffff:` 접두사를 16진 형태까지 IPv4로 정규화한다.

## L-7. 클라이언트 `JSON.parse(event.data)`에 try/catch 없음

`ws.addEventListener("message", …)` 안에서 바로 파싱한다. 서버가 정상이면 터지지 않지만,
중간 프록시·확장 프로그램이 프레임을 건드리면 리스너에서 예외가 나고 그 뒤 처리가 멈춘다.

## 조치 결과 (2026-08-12)

### H-2 — 프록시 헤더가 없으면 면제 [완료]

제안보다 한 단계 더 닫았다. "헤더가 없을 때만 면제하지 않는다"가 아니라
**`TRUST_PROXY`가 설정된 서버에서는 아무것도 면제하지 않는다.** 프록시 뒤에서 면제받아야
할 연결은 원래 존재하지 않고, 조건이 하나면 다시 뚫릴 자리도 하나 줄어든다. 면제는
`TRUST_PROXY=""`(프록시를 아예 안 쓰는 로컬·개발)의 루프백 연결에만 남는다.

- 판정을 [`trustProxy.ts`](../packages/server/src/trustProxy.ts)로 **꺼냈다**. 두 번 뚫린
  자리인데 `index.ts` 안에 있어 서버를 띄우지 않고는 검증할 수 없었다.
- **면제(`exempt`)와 "이 머신에서 직접 온 요청(`direct`)"을 분리했다.** 한 값으로 겸하고
  있어서 L-1(`/healthz` 잠그기)을 얹으면 감시자의 로컬 호출까지 막혔다 — 두 판단은
  서로 다른 질문이라 값도 따로 들고 다닌다.
- 헤더가 빠지면 1분에 한 줄로 경고한다(로그 폭주 방지). 프록시 설정이 깨졌다는 유일한 신호다.

### H-1 — 익명 연결이 전역 슬롯을 점유 [완료]

제안 1·2·3을 전부 넣되, **"미인증"이 아니라 "익명"** 으로 세는 것이 핵심 수정이다.
게스트는 `conn.user`에 DB에 없는 임시 신원이 들어가 "인증됨"처럼 보이므로, 제안대로
`conn.user === null`만 셌으면 `guestPlay` 한 번으로 상한을 통째로 빠져나갔다.

- 익명(로그인 전 + 게스트) 상한 = 전역의 40%(120). 나머지 180칸은 언제나 로그인한 사람 몫.
- 익명 자리는 고정석이 아니라 **회전하는 풀**이다 — 넘치면 가장 오래 익명으로 앉아 있던
  연결을 회수한다. 상한만 뒀으면 공격자가 붙들고 있는 동안 새 손님이 로그인 화면에조차
  못 왔을 것이다(손님도 로그인 전에는 익명이다). 단 15초보다 젊은 연결은 건드리지 않고,
  회수 대상이 전부 유예 안이면 새 연결을 거절한다.
- `handleClose`를 **멱등**으로 만들었다. 회수가 소켓을 닫으며 한 번, 소켓의 close 이벤트가
  한 번 더 부르는데, IP별 카운터를 두 번 줄이면 그 값이 음수로 새어 IP당 동시 연결
  상한이 조용히 헐거워진다.
- `/healthz`에 `anonymous`·`anonymousMax`를 실었다.

### M-1 — 비용 가중 레이트리밋 [완료]

- 비싼 조회 7종(`replayList`·`replayGet`·`leaderboard`·`feedbackList`·`adminUsers`·
  `adminAugmentTiers`·`liveGames`)에 **종류별** 창: 10초에 5회.
  **종류별인 것이 중요하다** — 클라이언트는 인증 직후 이것들을 한꺼번에 보낸다. 제안대로
  공용 창 하나로 묶었으면 정상 로그인 한 번이 창을 다 먹어 그 뒤 사람이 누른 조회가
  거부됐을 것이다. 정상 사용은 종류당 1회라 여유가 그대로 남고, 폭주만 40/s → 0.5/s로 접힌다.
- `SiteDb`가 준비문을 재사용한다(`stmt()` 캐시). `hydrate`의 것만이 아니라 전 쿼리에 적용했다.
- `replayGet`에 파일 크기 상한 4MB. 실측 최대 250KB라 정상 리플레이는 근처에도 안 온다.

### M-4 — 약한 가입 코드 [완료, 단 **값 교체는 운영자 몫**]

서버가 비밀을 마음대로 바꾸면 이미 코드를 받아 둔 사람들이 한꺼번에 가입하지 못한다 —
교체 시점은 운영자가 정해야 한다. 그래서 **거부가 아니라 부팅 로그 경고**로 넣었다.

- `SIGNUP_CODE`가 16자 미만이거나 샘플 값 그대로면 경고 + 생성·적용 명령을 함께 찍는다.
- `ADMIN_CODE`도 같은 기준(이 값은 전 계정 조회·삭제 + 모든 리플레이 + 진행 중 대국
  관전이라 마스터 키다).
- `majak.env.example`에 이유와 `openssl rand -base64 24`를 적었다.

⚠ **아직 5자짜리 값이 돌고 있다.** 다음 배포 때 교체할 것.

### L-1 — `/healthz` [완료]

프록시 규칙 대신 **서버가 직접 판정**한다 — Cloudflare 설정은 이 저장소 밖이라 잊히기 쉽다.
이 머신에서 직접 온 요청(`direct`)에만 답하고, 그 외에는 **404**(403은 "여기 뭔가 있다"를
알려 준다). `serve.sh health`·`watchdog.sh`는 127.0.0.1로 부르므로 그대로 작동한다.
외부 감시 도구가 필요하면 `HEALTHZ_PUBLIC=1`.

### L-2 — env 파일 권한 [완료]

`deploy/majak.env`를 0600으로 바꿨고, `serve.sh`가 **부팅할 때마다 확인해 조인다**
(한 번 고치는 것으로는 다음에 복사할 때 다시 0644가 된다).

### L-3 — CSP `connect-src` [완료]

`'self'` 하나로는 못 줄인다(고급 설정의 수동 서버 주소·vite dev가 막힌다). 대신 **실제로
필요한 곳만** 적는다: `ALLOWED_ORIGINS`가 설정된 공개 배포에서는 그 오리진의 http(s)/ws(s)와
`ws://localhost:*`·`ws://127.0.0.1:*`만. `ALLOWED_ORIGINS`가 비어 있는 로컬·개발은 종전대로
열어 둔다(거기서 조이면 개발이 막히고, 로컬 페이지에서 나갈 자격증명도 없다).
원격 수동 지정이 필요하면 `CONNECT_SRC_EXTRA`.

실측(공개 배포 설정):
`connect-src 'self' https://majak.yaho1231.com wss://majak.yaho1231.com ws://localhost:* ws://127.0.0.1:*`

### L-4 — 리플레이 열거 [완료]

"없다"와 "볼 권한이 없다"를 같은 응답(`REPLAY_NOT_FOUND`, 같은 문구)으로 합쳤다.

### L-5 — 게스트 슬롯 독점 [완료 — H-1이 함께 닫았다]

게스트 방은 그 방을 연 연결이 끊기면 함께 사라진다. 즉 게스트 슬롯을 붙들려면 **연결을**
붙들어야 하는데, 그 연결이 이제 익명 상한과 회수의 대상이다. 게스트 자체의 상한
(`MAX_GUEST_ROOMS` 16 · IP당 3)은 그대로 뒀다.

### L-6 — `abuseKeyOf` 16진 IPv4-mapped [완료]

`::ffff:0102:0304` 같은 표기를 IPv4로 푼다. 안 풀면 그 주소들이 전부 `0:0:0:0::/64` 한
버킷으로 뭉쳐 **서로 모르는 사용자들이 IP당 상한을 나눠 쓰며 서로를 밀어냈다**
(뚫리는 쪽이 아니라 과도 차단 쪽 고장).

### L-7 — 클라이언트 파싱 [완료]

`JSON.parse(event.data)`를 try/catch로 감쌌다. 한 프레임을 버리고 다음을 계속 받는다.
