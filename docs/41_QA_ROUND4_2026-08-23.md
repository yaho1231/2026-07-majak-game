## 이번 라운드가 앞선 라운드와 다른 점

1~3라운드(docs/36·37·39·40)는 **크래시 · 룰 정확성 · 증강 시너지의 의미**를 훑었다.
그래서 이번에는 그 축을 일부러 비우고 **완성도**만 봤다:

> 처음 오는 사람이 겪는 마찰 · 손이 미끄러지는 UI · 설명이 없는 화면 ·
> 실패했을 때 아무 말도 안 하는 경로 · 느린 곳 · 모바일에서 깨지는 곳 · 운영 중 조용히 죽는 곳.

각 담당에게 「이미 문서에 적힌 확정건을 다시 보고하면 감점」이라고 못 박았고,
보고서마다 «없다고 확인한 것»을 함께 적게 해서 다음 라운드가 같은 곳을 다시 파지 않게 했다.

# 1. P0 — 공개 불가였던 것 (1건, 해소)

## 초대 카드 라우트 하나로 서버의 모든 대국이 얼어붙는다

`GET /og/room/<코드>.png` 는 인증 · 오리진 · 레이트리밋이 **전부 없이** 열려 있었고,
방 코드 공간이 32⁶ 이라 캐시(256개)도 Cloudflare 캐시도 전부 미스가 난다.
원인은 `ogCard.ts` 의 `deflateSync(..., { level: 9 })` — 요청 1건당 **85 ms 동기 CPU**다.
봇 판단 · 턴 타이머 · 뷰 브로드캐스트가 전부 같은 이벤트 루프에 있으므로,
**노트북 한 대의 8연결이면 서버에 있는 모든 사람의 판이 멈춘다.**

**고친 방법**: 압축 레벨 `9 → 1`, 그리고 HTTP 핸들러 맨 앞에 IP 레이트리밋 2단 창을 뒀다
(일반 300회/10초 · 비싼 것 20회/10초, `/healthz` 는 제외, 루프백 면제 유지).
기존 `clientIpOf` + `abuseKeyOf` 를 그대로 재사용했다.

**재측정** (별도 포트 3199 로 워크트리 코드를 띄우고 그 PID만 종료):

| 지표 | 수정 전 | 수정 후 |
|---|---|---|
| `/og/room/*` 순차 30장 | 85 ms/장 | **1.6 ms/장** (약 50배) |
| `/healthz` 평시 | 18.8 ms | 0.3 ms |
| 8연결 6초 flood 중 `/healthz` | max **915 ms** · avg 702 ms | max **40 ms** · avg 10 ms |

카드 크기는 4.8 → 14.6 KB 로 늘었지만 공유 카드로는 의미 없는 차이다.
회귀 테스트는 zlib FLEVEL 비트를 되읽어 **level 9 복귀를 잡는다**(`OgCard.test.ts`).

# 2. P1 — 공개 전 고쳐야 했던 것 (12건, 전부 해소)

## 2-1. 처음 오는 사람 (onboard)

| 문제 | 고친 방법 |
|---|---|
| **「바로 한 판」에 실전과 같은 30초 드래프트 제한.** 코드 주석이 스스로 "카드 셋을 읽는 데만 30초가 넘게 걸린다"고 적어 놓고 그 판단을 튜토리얼(30분)에만 적용했다. 마작도 증강도 처음인 사람이 정확히 이 문으로 들어와 **첫 드래프트를 랜덤으로 잃는다**. | `FIRST_DRAFT_TIMEOUT_MS` **75초** 신설 — 「이 판의 몇 번째 드래프트인가」(`draftsOffered`)로 가른다. 첫 스테이지만 넉넉하고 둘째부터는 평소대로 30초. 네 좌석 전부에 같은 값이라 유불리가 없다. **보고서가 예로 든 90초는 쓰지 않았다** — 컨트롤러의 90초 최후 그물이 사람 대신 골라 버린다. 테스트가 `30_000 < 값 < 90_000` 을 못 박는다. |
| **튜토리얼이 실전 30초 제한을 한 번도 안 가르친다.** 30개 강의 어디에도 없고, 오히려 "시간 제한이 없습니다"만 두 번 말한다. | `outro` 에 caveat 한 줄 — 시간이 다 되면 **무엇이 일어나는지**까지(자동 패스 / 가져온 패가 그대로 나감 / 증강은 첫 번째만 넉넉). 랜딩 안내문도 두 문에 다르게 걸리도록 갈랐다. |
| **첫 화료의 정산 화면에서만 코치가 통째로 막혀 있다.** 튜토리얼의 목표가 화료인데 그 결과 화면을 아무도 설명하지 않는다. 역 이름·부의 용어 링크도 일부러 떼여 있었다. | 정산 전용 강의 `result-score`(「판 × 부」 풀이) 신설 + `allowedNow` 를 화이트리스트로 교체(통째로 열지 않은 이유: 원래 막아 둔 이유가 옳다). 「N판 M부」 만 `TermText` 로 흘리고 역 이름 줄은 그대로. |
| **뒤로가기·새로고침 방어가 전혀 없다.** `beforeunload`/`popstate` grep 무출력. | `beforeunload` + `pushState`/`popstate` 두 갈래. 판·대기실에서만 걸고 관전자는 뺀다. 되묻는 창은 **`askConfirm`** — `window.confirm` 은 메인 스레드를 멈추는데 서버 결정 타이머는 흐른다(저장소 전역 금지 규약). 비동기라 되묻는 동안 또 눌려도 새지 않게 **먼저** 완충 항목을 다시 쌓고 묻는다. |

> **보고서를 반만 채택한 곳**: "게스트는 복귀 수단이 아예 없다"는 절반만 맞았다.
> `GUEST_TOKEN_KEY → guestResume` 경로가 이미 살아 있어 새로고침으로 판에 다시 붙는다.
> 없던 것은 **그 사실을 알려 주는 것**뿐이라, 새 기계를 만들지 않고 되묻는 창의 문장에 실었다.

## 2-2. 대국 중 (ingame-ux)

| 문제 | 고친 방법 |
|---|---|
| **증강 선택 모달이 제한시간을 가린다.** 등가교환·예지 재배열·영상패·미래교환은 살아 있는 프롬프트인데, `.rinshan-pick-overlay`(z120, blur)가 `PromptTimer` 가 든 `.own-area`(z10)를 통째로 덮었다. 드래프트 창·결과창은 자기 타이머를 갖고 있는데 **이 모달들만 빠졌다**. 초읽기 국(5초)에선 예고 없이 서버 폴백. | `PickTimer` 컴포넌트를 새로 만들어 **`.rinshan-pick-panel` 모달 10곳 전부**에 세웠다. 회귀 테스트가 **개수로** 못을 박아 새 모달이 생겨도 빠뜨릴 수 없다. |
| **리플레이 재생 바가 하단 손패를 48px 덮는다.** 토스트·건너뛰기 알약은 이미 `--own-band-full` 로 이 사고를 수리했는데 이 바만 남았다(safe-area도 없음). | 같은 식으로 통일 + `flex-wrap`. 실측 360px: 바 아래끝 630px / 손패 띠 위끝 640px → **겹침 0**. |

## 2-3. 모바일·접근성 (mobile-a11y)

| 문제 | 고친 방법 |
|---|---|
| **폰 우상단 아이콘 5개가 4px씩 겹친다.** 좁은 화면 블록이 버튼을 **40px 피치**로 배치하는데 뒤의 `@media (pointer: coarse) { .icon-btn { min-width: 44px } }` 가 폭을 44px로 강제한다. `min-width` 는 순서와 무관하게 이기므로 쌍마다 4px 겹침 — DOM 순서상 **「나가기」가 「설정」을 덮는다**. | 폭을 줄이는 대신 **피치를 48px로** 벌렸다(같은 조건의 coarse 블록 안에서만). 실측: 5개 44px 폭 · 48px 피치 · 겹침 0. 비-coarse 는 예전 그대로. |
| **규칙·계산식 설명이 `title=` 에만 있어 터치에서 영영 안 뜬다.** 오름패 계산식 · 티어표 열 정의 · 서든데스 규칙 · 「왜 지금 못 쓰는가」 · 증강 설명 전문. | `InfoNote` 컴포넌트 신설(`tabIndex` + `role=button` + `aria-expanded`, hover · focus-within · **탭 고정** 세 통로) 후 5곳에 적용. `title` 은 데스크톱 보조기술 통로로 남겼다. |
| — 그중 「왜 지금 못 쓰는가」는 **다른 병이었다.** 버튼이 진짜 `disabled` 라 포커스도 클릭도 안 잡혀 **애초에 이유를 물을 방법이 없었다.** | `aria-disabled` 로 바꿔 누를 수는 있게 두고, 누르면 `haptics.reject()` + 사유 토스트. 겉모습은 그대로. |

## 2-4. 다시 시작하게 만드는가 (loop)

| 문제 | 고친 방법 |
|---|---|
| **초대 링크 + 「계정 없이 시작」 = 초대가 조용히 증발.** 랜딩이 "로그인하면 바로 들어갑니다"라 적어 놓고, 바로 옆 큰 버튼을 누르면 친구 방 대신 봇 판이 열린다. | `inviteNeedsAccount()` — 초대 코드가 있으면 게스트 두 문이 **둘 다** 그 자리에서 멈추고 가입 탭으로 보낸다. 서버가 게스트에게 `joinRoom` 을 안 여니(화이트리스트) **누르기 전에 막는 것이 유일한 답**이다. 테스트가 「두 버튼 모두」를 개수로 못 박는다. |
| **시작된 방에 늦게 온 손님은 갈 곳이 없다.** 에러 토스트 하나뿐이고, 관전·`liveGames` 가 둘 다 관리자 전용이라 일반 사용자에게 "진행 중인 판을 본다"는 경로 자체가 없다. | `ROOM_PLAYING` 거절 시 그 코드를 홈 참가 칸에 **채워 두고** 남는 안내 줄로 「끝나면 다시 눌러 보세요 — 반장전이면 30~40분」. 재시도가 6자리 재입력이 되지 않는다. (관전·대기 줄은 서버 일이라 남았다.) |
| **연습 대국 결과 화면에 「한 판 더」도 「다시 보기」도 없다.** 아이러니하게 비계정 게스트에게는 있다 — **가입한 사람이 더 불편했다.** | `GameOverModal` 에 `onPracticeAgain`. 「방금 그 판이 연습이었나」는 서버 응답에 없는 사실이라 보낸 쪽에서 기억한다(`wasPractice`). 「다시 보기」는 **못 붙였다** — 서버가 게스트 방에 `recordedId` 를 안 준다(서버 몫). |

## 2-5. 봇 (bot)

**봇 난이도가 아무 일도 하지 않고 있었다.** `profile.skill` 이 쓰이는 곳은 버림 흔들림 밴드 **한 곳**뿐이라
리치·후로·깡·화료·증강 판단이 난이도와 100% 동일했다. 그런데 대기실 문구는 「쉬움 — 실수를 자주 한다」다.
듀플리케이트 120판 측정에서 easy−hard 평균 순위 차 **0.075 ± 0.057 (1.3σ, 유의하지 않음)**.

**고친 방법**: 난이도를 `bot/skill.ts` 한 파일로 모아 계수 넷으로 냈다 —
`riskSight`(방총 위험을 제값으로 세는 정도) · `placementSight`(점수판을 보는 정도) ·
`looseness`(리치·후로 웃돈) · `blunderFloor`(**점수 단위 실수 폭**).
`skill=1` 에서 계수가 전부 정확히 1이라 **hard 는 종전 봇 그대로**다.

| | 시드 | easy | hard | 차 (±SE) |
|---|---|---|---|---|
| **전** | 4041 | 2.5375 | 2.4625 | 0.075 ± 0.057 **(1.3σ)** |
| **후** | 4041 | 2.7188 | 2.2813 | **0.4375 ± 0.0415 (10.5σ)** |
| **후** | 777 | 2.7646 | 2.2354 | **0.5292 ± 0.0388 (13.6σ)** |
| **후** (normal) | 4041 | 2.5688 | 2.4312 | 0.1376 ± 0.0426 (3.2σ) |

사다리가 easy > normal > hard 로 선다. 판당 방총 easy 0.74 : hard 0.43 · 평균 점수 23,751 : 28,443.

> **도중에 한 번 틀렸고 그 기록을 남긴다.** 처음 붙인 세 계수(위험·순위·헐거움)만으로는
> **시드마다 부호가 뒤집혔다**(4041 −0.108 / 777 **+0.217**). 「위험을 덜 보고 더 민다」는
> 약한 전법이 아니라 **다른 전법**이라서다. 실력을 실제로 깎는 것은 손의 효율이라,
> 성격과 무관한 점수 바닥(`blunderFloor`)을 깔고서야 두 시드가 같은 방향으로 벌어졌다.
> 시드 하나로 채택했으면 아무 일도 안 하는 변경을 「유의미」로 기록할 뻔했다.

# 3. P2 — 고쳐서 좋아진 것 (32건)

## 3-1. 서버·운영

- **방문자 `seen` 집합 무한 증가** → 상한 200,000, 넘으면 `views` 만 센다(방문자 수는 원래 「하한」). 날짜 롤오버 시 초기화.
- **재연결 중 「나가기」가 서버에 닿지 않는다** — 재전송 큐로 새 연결에서 나가는데 서버는 `conn.room !== null` 일 때만 동작했다. 화면만 나가고 좌석이 남아, 재접속하면 「진행하던 방으로 재접속」이 도로 떴다. → 신원 기준으로 좌석 정리(`resumableRoomFor`). **좌석 소켓이 살아 있으면 건드리지 않는다** — 이 가드가 없으면 「예전 탭이 남의 자리를 포기시킬 수 없다」가 깨진다(실제로 처음에 깨져서 잡았다).
- **기다리는 방이 30분 뒤 예고 없이 닫혀 뿌린 초대 링크가 죽는다** → 5분 전 예고 1회, 조작하면 시계와 함께 되돌아감. 닫힘 문구에 초대 링크 만료 사유 추가. 새 메시지 타입 없이 기존 `error` 코드로 전달(클라 수정 불필요).

## 3-2. 인게임·접근성

- 「건너뛰기」 알약이 최신 토스트를 덮음(노치 없는 기기에서 `bottom` 이 완전히 동일) → `body:has()` 로 알약이 떠 있는 동안만 토스트 52px 상승. `.toast-stack` 에 빠져 있던 safe-area 도 보강.
- **죽어 있던 `haptics.turn` / `win` / `reject`** (호출부 0건, 주석은 "초읽기 국에서 특히") → 전부 실제 호출부를 만들었다. 버림 프롬프트의 **소리**는 판단해서 **초읽기 국에서만**(`deadline ≤ 12초`) 붙였다 — 매 순 울리면 한 국에 18번이다. 진동은 소리 설정과 독립이라 상시.
- 리플레이 버튼 4종·판 위 공지 「✕」가 터치 44px 명단에서 통째로 누락 → 편입(공지 ✕는 선택자 특이도 때문에 파일 끝에 배치).
- **색 단독 채널 4건** → 전부 색과 무관한 두 번째 채널을 얹었다: 적5(파선 테두리) · 개인 도라(이중 outline) · 중계 위험도(2px 파선 / 3px 실선) · `prefers-contrast: more` 가 판 위 8개 표식을 실제로 잡게 함.
- `TileImg` 의 `alt` 가 `owner` 누락 → 각인 적도라를 남의 손에서도 「赤」으로 읽어 **화면과 스크린리더가 서로 다른 판을 말하던** 것.

## 3-3. 다시 시작하게 만드는가

- **빈 전적 CTA 모순** — 시키는 대로 한 판 두고 돌아와도 화면이 안 바뀌었다(튜토리얼·연습은 기록에 안 남는다) → 「방 만들기 (전적에 남음)」을 나란히 세우고 이유를 적었다.
- **결과 화면에 증강 성적 없음** — 데이터(`stats.augments`)는 이미 도착해 있었다 → `GameAugmentRow`. 누적용 통계를 그대로 쓰지 않은 이유: 한 판에서는 전부 1과 0이라 헛말이 된다.
- **대기실 전적 칩에 표본이 없어 1국 뒤 「화료 100%」** → 10국 미만이면 %를 접고, 이상이면 표본 칩을 맨 앞에.
- **공유 링크를 내리는 UI 없음** — 서버·프로토콜·토스트가 전부 준비돼 있고 **요청만 아무도 안 보내고 있었다**(`grep revoke` 0건) → 뷰어에 버튼 하나.
- **새로 고침 버튼 4개가 같은 요청을 쏴 10초 6회면 서버 한도** → 쿨다운을 모듈 전역 하나로 모으고 900ms → 2,500ms(10초 4회, 한도 5회 안쪽).

## 3-4. 문구 9건 전부

| 고친 것 |
|---|
| **「오카」·「반환점」 풀이가 실제 정산과 달랐다** — 사전은 "1위가 20,000점을 가져간다"고 가르치는데 실제 `oka: 0`(서버가 덮어쓰지 않음)이고 성적식은 `raw − 25000 + uma`. 다른 마작에서 배워 온 사람이 없는 20,000점을 계산에 넣고 있었다. → 문구를 실제에 맞추고, 항목은 **내리지 않았다**(그 오해를 막는 것이 이제 이 항목의 용도다). |

## 3-5. 봇 나머지

- **오라스 화료에 순위 계산이 없다** — `riskAppetite`(버림·리치·후로·깡·증강이 전부 쓰는 축)가 **화료에만 안 닿았다**. 60판 측정: 오라스 화료 37건 중 19건이 순위를 전혀 안 바꿨고 그중 14건은 1위도 아니었다(4위가 3,000점 론으로 게임 종료 등). → `shouldDeclineRon` — **론 프롬프트에서만**, 조건 여덟이 전부 맞을 때만 흘린다(쯔모는 안 흘린다). 재측정 37.8% → **25.0%**.
- **봇이 거의 울지 않는다**(후로율 16~19% vs 사람 30~40%) → 「전진」의 **정의**를 샹텐 하나 → 샹텐+우케이레로 넓혔다(동률이면 받는 폭 1.35배 이상). 두 시드 A/B: 후로율 18.3→20.4% · 17.8→21.9%, 평균 순위 변화는 두 시드 다 표준오차 안이라 채택.
