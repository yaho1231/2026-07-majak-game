## 확정 1. 🔴 전체 화면 오버레이가 떠 있는 동안 우상단 단추 5개(설정·도감·규칙·기록·나가기)가 **보이는데 죽어 있다**

**증강 드래프트 창과 국 정산 창 둘 다에서 재현된다.**

- 위치: `packages/client/src/styles.css` — `.overlay` `z-index: 50`(드래프트) / `.result-overlay`
  `z-index: 55`(정산) vs `.icon-btn` `z-index: 40`
  (렌더는 `App.tsx:11278` 근처 `.icon-btn.leave-btn` 등)
- 기대: 도감·규칙 단추는 제목부터가 "**게임은 그대로 진행됩니다**"다 — 판 중에 열라고 있는 것이다.
  나가기는 되돌릴 수 없는 동작이라 확인 창을 띄운다.
- 실제: 증강 선택 오버레이(`.overlay.overlay-peekable`)가 **뷰포트 전체(1280×1120)** 를 덮고
  `pointer-events: auto` 라, 네 단추 전부 클릭이 오버레이에 먹힌다. 실측:

  ```
  .settings-btn  visible:true  blockedBy:"overlay overlay-peekable"
  .codex-btn     visible:true  blockedBy:"overlay overlay-peekable"
  .help-btn      visible:true  blockedBy:"overlay overlay-peekable"
  .leave-btn     visible:true  blockedBy:"overlay overlay-peekable"
  ```
  단추는 **흐려지지도 disabled 되지도 않고** 그대로 서 있으며, 접근성 트리에도 그냥 enabled 로
  나온다(`read_page` 가 "나가기" 를 클릭 가능한 버튼으로 보고한다). 눌러도 확인 창이 DOM 에
  **생기지 않는다**(`[class*="confirm"], [role="dialog"]` 조회 결과 없음).
  키보드로 포커스를 줘서 Enter 를 눌러도 마찬가지로 아무 일도 없다.
  **국 정산 창에서도 같다.** 500ms 주기 자동 hit-test 로 잡은 실측(봇2 쯔모 정산):

  ```
  overlay class : "overlay overlay-peekable result-overlay result-outcome-win"  z-index: 55
  .settings-btn / .codex-btn / .help-btn / .leave-btn / .auglog-btn
      → 전부 blocked:"overlay overlay-peekable result-overlay result-outcome-win"
  ```
  정산 창에서는 📜**기록 단추까지 막힌다** — 그 국에 무슨 증강이 터졌는지 되짚기에
  가장 자연스러운 순간이 정확히 그 창이 떠 있는 동안인데, 바로 그때 못 연다.
- 대조: 오버레이가 없을 때 같은 단추를 누르면 `blocked:false` 이고 «게임을 무효 처리하고 나갈까요?»
  확인 창이 정상적으로 뜬다 — 즉 단추 자체는 멀쩡하고 **오버레이가 덮는 동안에만** 죽는다.
- 영향: 증강 선택은 **매 드래프트 국(동1·동3·남1·남3)마다** 뜬다. 그동안 판을 나갈 수 없다.
  튜토리얼은 "시간 제한이 없습니다"라 드래프트가 **스스로 닫히지 않으므로**, 증강을 고르지 않는 한
  탭을 닫는 것 말고는 빠져나올 방법이 없다(아래 확정 2와 겹쳐 실제로 갇혔다).
- 재현: 새 계정 가입 → 자동 진입한 튜토리얼의 증강 선택 화면에서 우상단 ✕ 클릭.

## 오탐으로 배제한 것 (조사했고 문제 아님)

- **백(白) 패가 빈 타일로 보인다** — 정상이다. 白 은 무지 타일로 그리는 것이 맞고 좌상단에 `Wh`
  라벨도 있다.
- **`자리 바꿈` pill 이 "3회"인데 설명은 "국당 1회"** — 정상이다. `seat_swap.ts:73`
  `maxUses = matchUses(state) + 1` = 반장전 3회이고 description 도 "(동풍전 2회 · 반장전 3회,
  국당 1회)" 로 둘 다 적어 둔다. pill 은 **판 전체 남은 횟수**를 센다.
- **`스파이` 를 골랐는데 대상 지정 모드가 안 켜진다** — 처음엔 그렇게 보였으나, 그 사이 내 순이
  타임아웃으로 지나가 무장이 자동 해제된 것이었다. 순 안에서 다시 재면 정상이다:
  `.arm-hint` = «✦ 스파이 지정 — 발동할 손패를 클릭하세요 [취소]», 손패 14장 전부
  `.hand-armable`, 버튼 `.aug-btn-armed`. **[취소] 도 정상 동작**한다(누르면 `armHint:false`,
  `hand-armable:0`, 버튼 class 원복).
- **`천리안` 결과가 화면에 안 보인다** — 보인다. 우상단에 📜(`.auglog-btn`)가 생기고 그 안
  «지금 상태 → [천리안] 텐파이: 봇3 (11순 기준)» 로 뜬다. 다만 아래 의심 1 참고.
- **`안개 덮인 바닥` 을 썼는데 내 화면의 바닥이 안 흐려진다** — 설명대로다("나만 그대로 본다").
  이름표 옆에 «🌫 안개 덮인 바닥 · 내 선언 — 최근 6장만 보인다» 상태 칩이 정상적으로 뜬다.
- **`.quick-toggles` 가 판 위 패를 문다(폰 세로)** — 스크린샷상 그렇게 보였으나 400ms 주기로
  전 구간 실측한 결과 **겹침 최대 0장**이었다. 취소.
- **국이 바뀔 때 배지·게이지 잔류** — 못 찾았다. 이름표 문자열 전체를 주기적으로 기록해
  **149개 표본**을 모았고, 東3 → 東4 → 南1국을 지나는 동안 내 pill 줄은 내내 정확했다:

  ```
  東3국 · 東4국 · 南1국  →  나 💰스파이 🌀자리 바꿈3회 👁천리안1회 🌀안개 덮인 바닥1회
  ```
  - `천리안`(**국** 스코프, 국당 1회): 東1국에 써서 `0회` 가 됐다가 東2국에서 `1회` 로 **정상 초기화**.
  - `안개 덮인 바닥`(**판** 스코프, 반장전 2회): 東2국에 한 번 써서 `2회`→`1회`, 그 뒤 국이 세 번
    바뀌어도 `1회` 유지 — 스코프대로다.
  - `자리 바꿈`(판 스코프 3회): 한 번도 안 써서 계속 `3회`.
  - **효과 표시도 안 남는다.** 東2국에 발동한 «🌫 안개 덮인 바닥 · 내 선언 — 최근 6장만 보인다»
    상태 칩은 국이 바뀐 뒤 사라졌다 — 南1국에서 이름표 줄 전체를 다시 읽어 확인:
    `"나💰스파이🌀자리 바꿈3회👁천리안1회🌀안개 덮인 바닥1회✦ 액티브 증강"`, 칩 없음.
- **문구에 내부 id 노출** — 이름표 pill · 액티브 메뉴 · 기록 패널 · 샌드박스 목록(117종) 어디에도
  raw id 는 없었다. 전부 한국어 이름으로 나온다. 대국 화면 전체를 훑어
  `text`·`title`·`aria-label`·`placeholder` 에서 snake_case 토큰을 찾는 스캔을 돌렸고,
  유일한 히트는 `<style>` 안의 CSS 애니메이션 이름(`time_pressure`) 이었다 — 사람 눈에 안 보인다.
- **잘린 문구** — 대국 화면에서 `overflow` 가 잘린 요소를 전수 계산(`scrollWidth-clientWidth > 2`
  또는 세로 동일)했고 **0건**이었다.
- **정산 창의 «4판30부 0점»** — 버그가 아니다. `.result-points` 는 `CountUpPoints`
  (`App.tsx:18591`)가 **0에서부터 굴리는 카운트업**이고 시작 지연이 400ms 다(`startDelay = 400`).
  내 기록기가 창이 뜬 첫 프레임을 찍어서 `0점` 으로 보였을 뿐이다. 뒤에 같은 창을 연속

### 막힌 지점 (환경 문제 — 제품 결함 아님)

세션 도중 브라우저 창(Browser pane)이 접힌 채로 굳었다. `document.visibilityState === "hidden"`
이 되어:

1. **입력 주입이 안 된다** — `computer` 의 클릭·스크롤이 전부 30초 타임아웃을 낸다.
   스크린샷 렌더와 JS 실행은 계속 되므로 **관찰은 되지만 조작이 안 된다.** 탭을 새로 열어도
   (`tabs_create foreground:true`) 여전히 hidden 이라 도구 쪽에서 되살릴 방법을 못 찾았다.
2. 그래서 판이 매우 느리다 — 탭이 숨겨져 타이머가 throttle 되고, 내 좌석의 매 결정이
   서버의 30초 폴백(`응답 없음 30000ms — 안전 폴백으로 진행`)으로 처리된다.
   한 국에 3~5분이 걸린다.
3. 컷인 기록기(150ms 주기)도 throttle 탓에 아무것도 못 잡았다 — 의심 1을 확증하지 못한 이유다.

판 자체는 서버가 계속 돌려 **남2국까지 진행**했고, 그 상태에서도 국 정산 창·오버레이 차단
(확정 1의 정산 창 근거)·카운트업·점수 이동은 계속 관찰·기록할 수 있었다.
