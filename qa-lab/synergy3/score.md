# 타점 · 정산 · 뱅크 (han / bank / payout / loss_gain / dealer) — score

## 요약

검증한 조합 **56개**(2중 47 · 3중 9) / **확정 6건**(🔴 3 · 🟠 3) · **의심 3건** / 음성 확인 **21건**

전부 유닛 재현(`craft` + `installAugment` + 강제 화료)으로 4칸 대조군을 찍었다.
스크립트는 `qa-lab/synergy3/score/*.ts`, 실행은
`~/majak/node_modules/.bin/tsx qa-lab/synergy3/score/<파일>.ts`.

이미 판정된 것(배율 연쇄 `let_it_ride×jackpot×blood_contract` · `devils_advance` 드리프트 ·
`seat_swap` 정산 순서 · conflicts↔synergy 표 모순)은 **한 건도 다시 적지 않았다.**
아래는 전부 `grep -ri` 로 `qa-lab/`·`docs/` 를 훑어 겹치지 않음을 확인한 것이다.

한 줄로 요약하면 이번 라운드가 찾은 것은 **"단계는 나눠 놨는데 같은 단계 안에서
서로를 못 보는" 세 가지 구멍**이다 —
① 같은 `Redistribute` 안의 두 재배선(책임전가·눈먼 총알)이 서로의 결과를 무시한다,
② `Transfer`(스파이)가 **뱅크가 발행한 돈**까지 훔치는데 `Reassert`가 있는 쪽(큰손)은
뱅크가 두 번 발행하고 없는 쪽(모 아니면 도)은 약속이 조용히 사라진다,
③ `Transfer`(뚫린 천장)의 이동이 앞서 끝난 `Redistribute`(책임전가)의 분담을 빠져나간다.

## 확정 1. 🔴 `blame_shift` × `blind_ron` — **방총한 사람이 16,000점을 번다**

- 위치: `packages/content/src/augments/blind_ron.ts:124` (`SETTLE_STAGE.Redistribute`) ×
  `packages/content/src/augments/blame_shift.ts:67` (같은 `Redistribute`)
- 설명이 약속한 것:
  - 책임전가 — "내가 받는 총액은 변하지 않고 **지불자만 분산된다**", "그 지불이 쏜 사람
    혼자가 아니라 세 명에게 쯔모처럼 분담된다"
  - 눈먼 총알 — "이 국의 **모든 론이** 네 명 중 무작위 한 명에게 청구된다"
- 기대(먼저 적었다): 어느 쪽이 먼저 돌든 **지불자는 정확히 한 벌**이어야 한다.
  3분할이 그대로 남아 그중 1/3만 총알을 타고 옮겨 가거나(p1 0 · p2 −16,000 · p3 −8,000),
  아니면 통째로 한 명이 24,000을 물거나. **쏜 사람이 흑자가 되는 경우는 있을 수 없다.**
- 실제 (p0 오야 8판 청일색 24,000 론, 쏜 사람 = p1, seed=2):

  | 조합 | p0 | p1(쏜 사람) | p2 | p3 | 합 |
  |---|---|---|---|---|---|
  | 없음 | 24000 | **−24000** | 0 | 0 | 0 |
  | A = `blame_shift`(p0) | 24000 | −8000 | −8000 | −8000 | 0 |
  | B = `blind_ron`(p2) | 24000 | 0 | −24000 | 0 | 0 |
  | **A+B** | 24000 | **＋16000** | **−32000** | −8000 | 0 |

  방총한 p1이 **16,000점을 벌고**, 총알을 맞은 p2가 **손값(24,000)보다 많은 32,000**을 문다.
  총합만 0이라 기존 라운드의 "총합 드리프트" 검사에는 전혀 걸리지 않는다.
- 원인: 두 인터셉터가 같은 `Redistribute` 단계에 있고, 실행 순서는
  `settlePriority(stage, seat, id)` 의 좌석 자리로 갈린다(p0 < p2 → 책임전가 먼저).
  뒤에 도는 눈먼 총알은 `deltas` 가 아니라 **`winInfos[].points` 원본**에서 `owed` 를
  다시 계산해(`blind_ron.ts:141`) 쏜 사람에게 **전액 24,000을 환급**한다 —
  책임전가가 이미 8,000으로 줄여 놓은 것을 못 본다.
- 재현: `tsx qa-lab/synergy3/score/b2_blindron.ts` (표 B9) ·
  `tsx qa-lab/synergy3/score/h_confirm.ts` (표 H1 — 시드·보유 좌석 15조합)
  시드 5개 × 총알 보유 좌석 3개 = 15판 중 **12판**에서 쏜 사람이 +16,000.
  (나머지 3판은 총알이 쏜 사람 자신에게 뽑혀 `victim === shooter` 로 걸러진 경우다.)
  seed=13 에서는 총알이 화료자 p0에게 꽂혀 **p0 수령 0 · p1 +16,000** 이 된다.
- 영향: 두 증강은 `synergy.ts` 에서 **같은 `payout` 축**이다(`blame_shift: e(["payout"])`,
  `blind_ron: e(["payout","disrupt"])`) — 드래프트가 둘을 **적극적으로 함께 밀어 준다.**
  둘 다 패시브라 플레이어가 피할 방법도 없다.
- 제안 수정: 눈먼 총알이 `owed` 를 `winInfos` 가 아니라 **현재 `deltas` 의 음수분**에서
  읽게 한다(일확천금 0.5배 환급이 이미 같은 이유로 "현재 음수 델타"를 쓴다 —
  `jackpot.ts` 주석 참조). 또는 책임전가에도 덤터기와 같은 `Reassert` 재확인을 단다.

## 확정 2. 🔴 `big_hand` × `spy` — **뱅크가 만관 하한을 두 번 발행한다** (3,900 손에 20,100 발행)

- 위치: `packages/content/src/augments/big_hand.ts:180-181`
  (`floorAt(BankFloor)` + `floorAt(Reassert)`) × `packages/content/src/augments/spy.ts:134`
  (`SETTLE_STAGE.Transfer`, `deltas[hit.winner] = 0`)
- 설명이 약속한 것:
  - 큰손 — "그 국에 화료했을 때 내가 받는 **총액**이 최소 만관(오야 12,000 · 자 8,000)"
  - 스파이 — "그 점수가 **전부** 나에게 온다 … 화료 자체는 성립하고 **지불자들이 내는
    액수도 그대로다** — 돈의 도착지만 바뀐다"
- 기대: 둘 다 참일 수는 없으므로 한쪽이 이겨야 한다. 어느 쪽이 이기든
  **뱅크 발행은 한 번**(8,100)이고, 지불자 p1은 여전히 3,900을 낸다.
- 실제 (p0 오야 2판 40부 = 3,900 론, 쏜 사람 = p1, 큰손 선언 상태):

  | 조합 | p0 | p1(쏜 사람) | p2 | p3 | 합(=뱅크 발행) |
  |---|---|---|---|---|---|
  | 없음 | 3900 | −3900 | 0 | 0 | 0 |
  | A = `big_hand`(p0) | 12000 | −3900 | 0 | 0 | 8100 |
  | B = `spy`(p1, 9s 지정) | 0 | 0 | 0 | 0 | 0 |
  | **A+B** | **12000** | **＋8100** | 0 | 0 | **20100** |
  | A + `spy`(p2) | 12000 | −3900 | **12000** | 0 | **20100** |
  | A + `spy`(p3) | 12000 | −3900 | 0 | **12000** | **20100** |

  화료자는 12,000을 받고 **스파이도 12,000을 받는다.** 3,900짜리 손 하나가 테이블에
  **20,100점을 새로 찍어 낸다**(100,000점 판의 20%). 스파이 좌석과 무관하게 재현된다.
  스파이가 쏜 사람일 때는 **방총자가 +8,100 흑자**가 된다.
- 원인: `BankFloor`(350)에서 하한을 채워 12,000을 만들고 → `Transfer`(400)에서 스파이가
  그 12,000을 통째로 가져가 `deltas[p0] = 0` 으로 만들고 → `Reassert`(450)에서 큰손이
  "약속이 깨졌다"고 판단해 **다시 12,000을 발행한다.** `big_hand.ts` 의 주석은
  `Reassert` 가 "이미 하한 이상이면 아무것도 하지 않으므로 이중으로 채워지지 않는다"고
  적혀 있는데, **탈취형 이동이 끼면 정확히 이중으로 채워진다.**
- 재현: `tsx qa-lab/synergy3/score/c_transfer.ts` (표 C4-C5) ·
  `tsx qa-lab/synergy3/score/h_confirm.ts` (표 H2 — 스파이 좌석 3종, H3 — 기생충까지 3중)
- 영향: 큰손은 프리즘 상시 카드(2국에 1회 선언), 스파이도 프리즘 상시(매 국 1회 지정)다.
  스파이가 "저 사람이 큰손을 선언한 국"을 노려 찍으면 **손해 없이** 만관을 복사할 수 있고,
  자기가 쏜 패로도 성립한다. 천하통일(45,000)이 같이 있으면 그대로 매치 종료 사유가 된다.
- 제안 수정: `Reassert` 의 큰손 재확인이 **자기 몫이 남에게 옮겨간 경우는 제외**하도록
  한다 — 예컨대 `BankFloor` 에서 실제로 발행한 금액을 payload에 표식으로 남기고
  `Reassert` 는 "그 표식이 없을 때만" 채우게 한다. 또는 스파이가 훔치는 상한을
  **지불자들이 실제로 낸 금액(음수 델타의 합)** 으로 자른다 — 카드 문구
  ("지불자들이 내는 액수도 그대로다")가 이미 그 상한을 말하고 있다.

## 확정 3. 🔴 `scapegoat` × `die_hard` — **지목당한 사람이 뱅크에서 226,000점을 받고 매치를 이긴다**

- 위치: `packages/content/src/augments/scapegoat.ts:82-119`(`Redistribute`+`Reassert`) ×
  `packages/content/src/augments/die_hard.ts:89`(`Shield`)
- 설명이 약속한 것:
  - 덤터기 — "전액을 문 사람은 점수가 모자라면 **마이너스로 떨어져 탈락할 수 있다**"
  - 죽기살기 — "국 정산 결과 점수가 0 아래로 떨어지면, 내려간 만큼이 그대로 플러스로
    뒤집힌다 — −8,000점이 되면 즉시 +8,000점"
  - 두 카드 어디에도 "지목당하는 것이 이득이 된다"는 말은 없다.
- 기대: 덤터기는 지불자를 한 명에게 몰 뿐 총액을 만들지 않는다. 죽기살기의 발행은
  "0 아래로 내려간 깊이"에 비례하므로 커 봐야 그 사람의 소지점 언저리여야 자연스럽다.
- 실제 (p0 스안커단기 오야 쯔모 96,000 + 뚫린 천장 → 138,000, 전원 25,000 시작):

  | 조합 | p0 | p1(지목) | p2 | p3 | 테이블 총점 | 뱅크 발행 |
  |---|---|---|---|---|---|---|
  | 없음 | 121000 | −7000 | −7000 | −7000 | 100000 | 0 |
  | `aotenjou`(p0) | 163000 | −21000 | −21000 | −21000 | 100000 | 0 |
  | + `scapegoat`(p0→p1) | 163000 | **−113000** | 25000 | 25000 | 100000 | 0 |
  | **+ `die_hard`(p1)** | 163000 | **＋113000** | 25000 | 25000 | **326000** | **226000** |
  | + `sign_flip`(p1) 대신 | 163000 | 163000 | 25000 | 25000 | 376000 | 276000 |

  (표는 정산 후 **소지점**. 25,000점 4명 = 100,000이 한 국에 326,000이 된다.)
  작은 손으로도 같은 방향이다 — 24,000 쯔모 · p1 소지 5,000이면
  `scapegoat` 단독 p1 −24,000 → `+die_hard` 로 **p1 ＋14,000**(소지 19,000).
- 재현: `tsx qa-lab/synergy3/score/i_unification.ts` ·
  `tsx qa-lab/synergy3/score/f_bank.ts` (표 F4)
- 영향: 덤터기는 **상대가 고르는** 지목이다. 죽기살기 보유자는 지목당하기만 하면
  그 자리에서 매치 1위가 되고, 반대로 덤터기 보유자는 "죽기살기 보유자만 피하면"
  되지만 죽기살기의 잔량 뱃지는 공개라 그 정보전이 곧 카드 하나를 죽인다.
  `die_hard.conflicts` 는 방어 4종만 막고 있고(docs/21 C-3), **손실을 한 명에게
  몰아 주는 계열**은 열려 있다. `blind_ron` 도 같은 경로다(아래 의심 2).
  천하통일(45,000)이 함께 있으면 **첫 국에 매치가 끝난다.**
- 제안 수정: 죽기살기의 발행에 상한을 건다 — "0 아래로 내려간 깊이" 대신
  **그 국 시작 시점의 소지점** 또는 고정 상한(예: 만관)까지만 되돌리게 한다.
  카드 문구도 "−8,000이면 +8,000"이 아니라 "0으로 되돌아난다"로 바꾸면
  이 조합 전체가 자연스럽게 닫힌다.

## 확정 4. 🟠 `blame_shift` × `aotenjou_ceiling` — 상한 해제분이 3분할을 빠져나가 **쏜 사람만 더 낸다**

- 위치: `packages/content/src/augments/blame_shift.ts:67`(`Redistribute` 100) ×
  `packages/content/src/util.ts` `addWinPointTransfer`(`Transfer` 400,
  `aotenjou_ceiling.ts:80` 에서 호출)
- 설명이 약속한 것: 책임전가 — "내가 론으로 화료하면 **그 지불이** 쏜 사람 혼자가 아니라
  세 명에게 쯔모처럼 분담된다 … 지불자만 분산된다."
  뚫린 천장 — "늘어난 몫은 **론이면 쏜 사람이 전부**".
  두 카드가 정면으로 부딪히는데 어느 쪽에도 상대 이야기가 없다.
- 기대: 책임전가가 "그 지불"을 나눈다고 했으므로 30,000 전부가 10,000씩 3분할되거나,
  적어도 어느 쪽 규칙이 이기는지 한쪽 카드에 적혀 있어야 한다.
- 실제 (p0 오야 8판 청일색 론):

  | 조합 | p0 | p1(쏜 사람) | p2 | p3 | 합 |
  |---|---|---|---|---|---|
  | 없음 | 24000 | −24000 | 0 | 0 | 0 |
  | A = `blame_shift` | 24000 | −8000 | −8000 | −8000 | 0 |
  | B = `aotenjou` | 30000 | −30000 | 0 | 0 | 0 |
  | **A+B** | 30000 | **−14000** | −8000 | −8000 | 0 |

  표준 24,000은 3분할되는데 상한 해제분 6,000은 **쏜 사람 혼자**가 문다.
- 원인: 책임전가는 `Redistribute`(100)에서 한 번 나누고 끝난다. 뚫린 천장의 이동은
  `Transfer`(400)라 그 뒤에 온다. **덤터기(`scapegoat`)는 정확히 이 문제 때문에
  `Reassert`(450) 재확인을 갖고 있는데**(`settleStages.ts` — "덤터기의 '나머지 둘은
  한 푼도 내지 않는다'는 뚫린 천장·가불 인생이 끼면 깨졌다"), **같은 계열인 책임전가에는
  그 재확인이 없다.** 실제로 덤터기 쪽은 깨끗했다(음성 확인 표 C8 — 초과분까지 지목자가 전액).
- 재현: `tsx qa-lab/synergy3/score/g_mix.ts` (표 G1) ·
  `tsx qa-lab/synergy3/score/h_confirm.ts` (표 H4)
- 영향: 만관 미만 손에서는 뚫린 천장의 이동액이 0이라 안 보이고(H4 2판 삼색 = 편차 0),
  **판이 오를수록 편차가 커진다** — 역만이면 상한 해제분만 42,000이라 쏜 사람이
  나머지보다 42,000을 더 낸다. 두 증강 다 프리즘 상시라 조합 자체가 흔하다.
- 제안 수정: 책임전가에도 덤터기와 같은 `Reassert` 재확인을 붙인다
  (`sweep(Redistribute)` + `sweep(Reassert)` 패턴을 그대로).

## 확정 5. 🟠 `all_or_nothing` × `spy` — **판돈이 통째로 스파이에게 가고 쏜 사람이 +12,000**

- 위치: `packages/content/src/augments/all_or_nothing.ts:191`(`BankTopUp` 300) ×
  `packages/content/src/augments/spy.ts:134`(`Transfer` 400)
- 설명이 약속한 것: 모 아니면 도 — "그 리치로 화료하면 **판돈과 같은 금액을 뱅크에서
  추가로 받는다**". 스파이 — "지불자들이 내는 액수도 그대로다 — 돈의 도착지만 바뀐다".
- 기대: 스파이가 가져가는 것은 "화료로 생긴 점수"여야 한다. 뱅크가 올인 보유자에게
  따로 발행한 판돈까지 훔치면 모 아니면 도의 약속은 **한 글자도 안 남는다.**
  최소한 카드 어딘가에 그 말이 있어야 한다.
- 실제 (p0 오야 3,900 론 + 리치 유지, 판돈 12,000, 쏜 사람 = p1):

  | 조합 | p0 | p1(쏜 사람) | p2 | p3 | 합(뱅크 발행) |
  |---|---|---|---|---|---|
  | 없음 | 7700 | −7700 | 0 | 0 | 0 |

## 확정 6. 🟠 `aotenjou_ceiling` × 뱅크 환산 "+N판" — **상한이 그대로 남아 실판 계열보다 6,000점 적다**

- 위치: `packages/content/src/util.ts` `winPointsWithExtraHan`
  (`calculateScore` 를 그대로 써서 만관·역만 상한을 **다시 씌운다**) ×
  `packages/content/src/augments/aotenjou_ceiling.ts:80`
- 설명이 약속한 것: 뚫린 천장 — "내 화료에는 **점수 상한이 없다** … 판이 오르는 만큼
  점수가 계속 커진다". 해저의 지배자 — "**+3판**이 붙는다".
- 기대: 같은 "+3판"이면 어느 증강이 준 것이든 뚫린 천장 아래에서는 같은 값이어야 한다.
  8판 손 + 3판 = 11판 → 상한 없는 base 2000+6×1000 = 8000 → 오야 론 **48,000**.
- 실제 (p0 오야 8판 청일색 24,000 론):

  | 조합 | p0 | p1 | 합 | 비고 |
  |---|---|---|---|---|
  | 없음 | 24000 | −24000 | 0 | 8판 = 배만 |
  | A = `aotenjou` | 30000 | −30000 | 0 | 상한 해제 +6,000 |
  | B = `haitei_lord`(+3판, 뱅크 환산) | 36000 | −24000 | 12000 | 표준 11판 = 삼배만 |
  | **A+B** | **42000** | −30000 | 12000 | ← 48,000이 아니다 |
  | B′ = `bottom_yaku`(+3판, **실판**) | 36000 | −36000 | 0 | |
  | **A+B′** | **48000** | −48000 | 0 | ← 이쪽은 상한이 풀린다 |

  **같은 "+3판"인데 6,000점이 갈린다.** 실판(`score.extraHan`/역 등록)으로 주는 계열
  (바닥의 족보 · 복수자)은 `info.han` 에 들어가 뚫린 천장이 그대로 세지만,

  `calculateScore` 로 계산돼 **만관·역만 상한을 다시 맞는다.**
- 더 극단적인 구간 — 실판 13판(청일색8 + 바닥3 + 복수자2)이 되면 표준이 이미
  계수역만이라 해저의 +3판이 **통째로 0**이 된다:

  | 조합 | p0 | p1 | 합 |
  |---|---|---|---|
  | `bottom_yaku` + `avenger` (13판) | 48000 | −48000 | 0 |
  | + `haitei_lord`(+3판) | 48000 | −48000 | **0** ← 한 푼도 안 붙었다 |

  (`avenger` 는 반대 방향으로도 눈에 띈다 — 8판 손에서 **단독으로는 +2판이 0원**이고
  뚫린 천장이 있을 때만 12,000이 된다. 실판이라 상한에 잘리기 때문이다. 이건
  뚫린 천장 쪽이 옳게 동작하는 예다.)
- 재현: `tsx qa-lab/synergy3/score/a_aotenjou.ts` (표 A1-A3, A5) ·
  `tsx qa-lab/synergy3/score/g_mix.ts` (표 G6, G8)
- 영향: 뚫린 천장은 프리즘이고 "+N판" 계열은 12종이 넘는다(`addWinHanBonus` 사용처).
  카드는 "상한이 없다"고 단언하는데 실제로는 **어느 증강이 판을 줬느냐로** 상한이
  살았다 죽었다 한다 — 플레이어가 예측할 방법이 없다.

  (예: `score.uncapped` 같은 규칙을 뚫린 천장이 켜고, 헬퍼가 그때는 `aotenjouBase`
  곡선을 쓰게). 최소한 카드에 "다른 증강이 얹어 주는 판에는 상한이 남는다"를 적는다.

## 의심 1. 🟡 `spy` × `parasite` — **좌석 번호 하나로 12,000점이 갈리고 한쪽이 통째로 삼켜진다**

- 위치: `spy.ts:134` · `parasite.ts:104` — 둘 다 `SETTLE_STAGE.Transfer`(400)
- 실제 (p0 오야 24,000 론, 둘 다 p0을 노린다):

  | 좌석 배치 | p0 | p1 | p2 | p3 | 스파이 수령 | 기생충 수령 |
  |---|---|---|---|---|---|---|
  | spy=p1 · parasite=p2 | 0 | 0 | 0 | 0 | **24000** | **0** |
  | spy=p3 · parasite=p1 | 0 | −12000 | 0 | 12000 | **12000** | **12000** |

  앞 자리 사람이 먼저 돈다(`settlePriority` 의 좌석 축). 스파이가 먼저면 기생충은
  `d <= 0` 으로 조용히 아무 일도 안 하고, 기생충이 먼저면 스파이가 절반만 가져간다.
  스파이 카드는 "그 점수가 **전부** 나에게 온다", 기생충 카드는 "숙주가 얻는 점수의
  **절반**을 대신 가져온다" — **어느 배치에서도 둘 중 하나는 거짓이 된다.**
- 왜 "의심"인가: `settleStages.ts` 는 같은 단계 안의 좌석·id 순서가 "*결정론*만 보장할 뿐
  *의미*는 없다"고 명시하고 있고, 좌석 축 자체의 결함은 `qa-lab/round2/synergy.md`
  확정 2(자리 바꿈 후 재구성)가 이미 다른 각도에서 잡았다. 이 건은 **재구성 없이
  평범한 판에서도** 결과가 좌석으로 갈린다는 점이 새롭지만, "어느 쪽이 옳은가"에
  대한 설계 답이 문서에 없어 버그로 확정하지 못했다.
- 재현: `tsx qa-lab/synergy3/score/c_transfer.ts` (표 C1-C3, C3b)
- 제안: `settleStages.ts` 가 자기 규칙대로 **단계를 나눠야** 하는 경우다 —
  전액 탈취(스파이)와 지분 탈취(기생충)의 앞뒤를 의미로 정하고 별도 단계를 준다.
