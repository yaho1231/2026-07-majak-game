## 확정 1. 🟠 «샹퐁이 서면 단기 변형을 버린다» 필터가 **증강 없는 표준 손**에서도 발동해 부수가 깎인다

- 위치: `packages/core/src/mahjong/scoring/WinContext.ts:392-420` (2026-08-20 추가된 `shanponWinKeys` 필터)
- 기대: 이 필터의 도입 근거(`qa-lab/fixlog/shape-system-bot.md:89`, `docs/37_AUGMENT_FIX_LOG_2026-08-20.md:1536`)는
  **"표준 마작에서는 두 해석이 함께 설 수 없어 표준 채점은 안 바뀐다"** 이다.
  표준 룰은 여러 해석 중 **가장 비싼 것**을 채택한다.
- 실제: 전제가 거짓이다. 화료패가 손에 **3장** 있고 그 중 하나가 슌쯔로도 읽히면
  «머리 XX + 슌쯔 안의 X»(단기)와 «커쯔 XXX»(샹퐁)가 **같은 3장으로 동시에 성립**한다
  (필터 주석은 "같은 패 5장이 필요하다"고 적었지만 3장이면 된다).
  이때 단기 변형이 통째로 지워져 단기 2부가 사라진다.

  손: `3m3m3m 4m5m6m 6m6m 7p7p7p 2s3s4s`, 화료 `6m` 쯔모, 멘젠·자
  - 단기 해석: 333m(안커4) + 456m + 777p(안커4) + 234s + 머리 66m + 단기2 + 쯔모2 = 32 → **40부**
  - 샹퐁 해석: 666m(안커4) + 345m + 777p(안커4) + 234s + 머리 33m + 쯔모2 = **30부**
  - 엔진은 단기 변형을 아예 만들지 않고 30부로 정산한다.
- 재현: `~/majak/node_modules/.bin/tsx qa-lab/round2/rules/repro_tanki_filter.ts`
  ```
  ■ 333m 456m 66m 777p 234s — 6m 쯔모 (자)
    변형 2개: shanpon, ryanmen  (단기 포함? false)
    엔진   : 2판 30부 wait=shanpon → 합계 2000
    표준기대: 2판 40부 → 합계 2700
    MISMATCH ***
  ```
- 영향: 증강을 하나도 안 켠 순수 리치마작에서 **화료 점수가 표준보다 낮게 지불된다**
  (위 예: 2000 → 2700, -26%). 4판 이하 화료에서만 나타나므로 대량 손실은 아니지만,
  "표준 채점은 안 바뀐다"는 문서의 약속이 깨져 있다.
  (⚠ 문서에 "고쳤다"고 적힌 변경이 실제 코드에서 부작용을 남긴 경우다.)
- 광역 확인: `tsx qa-lab/round2/rules/probe.ts` (무작위 화료손 20,000개 전수 대조) → 이 버그만 5건,
  그 밖의 부·판·역 불일치는 **0건**. 점수까지 벌어진 예:
  ```
  engine=30fu/6000점 ref=40fu/7800점 han=3 wait=shanpon/tanki
  hand=[m5 m6 m7 m4 m4 m4 m7 m7] melds=[chi:m2m3m4 pon:z6z6z6] win=m7 tsumo
  ```
  (실전 대량 플레이 5,700국에서는 자연 발생하지 않았다 — 화료패가 손에 3장 + 슌쯔 겸용이라는 조건이 드물다.)
- 제안 수정: 필터 조건을 «같은 손 서명 + 같은 화료패»가 아니라
  **«같은 분해(decomp) 안에서 단기와 샹퐁이 동시에 성립할 때»** 로 좁힌다.
  원래 잡으려던 mixed_triplet·polar_ends는 *한 분해 안에서* 커쯔가 머리로 재해석되는 경우이므로
  그 조건으로도 그대로 잡힌다.

## 확정 2. 🟠 쿠이카에(먹고 바꾸기) 금지가 아예 구현돼 있지 않다 — 현물·스지·펑 전부 허용

- 위치: `packages/core/src/mahjong/flow/standardActions.ts:166-190` (`discardAction.validate`)
- 기대: 일본 리치마작 표준 룰은 후로 직후 **울어서 만든 몸통과 같은 패를 버리는 것**을 금지한다.
  - 현물 쿠이카에: 4m5m으로 3m을 치 → 손의 3m 버리기 금지
  - 스지 쿠이카에: 4m5m으로 3m을 치 → 손의 6m 버리기 금지
  - 펑 쿠이카에: 5m 펑 → 손의 5m 버리기 금지
  `docs/01_GAME_RULES.md` 는 후로 절(53-60행)에도 다른 어디에도 쿠이카에를 **면제한다고 적지 않았다**
  → 문서 기준으로 표준 룰이 적용된다.
- 실제: `discardAction.validate` 는 (1) 턴/페이즈 (2) 손에 있는 패인지 (3) 리치 중이면 쯔모패인지
  (4) 증강이 봉인한 패인지 — 이 넷만 본다. 직전 후로 몸통은 **한 번도 참조하지 않는다.**
  `state.round.lastCall`/직전 Meld를 보는 코드가 없다.
- 재현: `~/majak/node_modules/.bin/tsx qa-lab/round2/rules/flow.ts`
  ```
  FAIL 쿠이카에(현물) 금지 — validate=null
  FAIL 쿠이카에(스지) 금지 — validate=null
  FAIL 펑 쿠이카에 금지 — validate=null
  ```
  (`validate=null` = 허용. 나머지 17개 흐름 검사는 통과.)
- 영향: 후로가 **공짜 손패 교환**이 된다. 4m5m을 들고 3m을 치한 뒤 6m을 버리면
  손패 장수·텐파이 형태를 유지한 채 필요 없는 패 하나를 버릴 수 있다.
  같은 수를 반복하면 후로 한 번마다 무료 패 교체가 되므로, 사람 상대로는 **명백한 어드밴티지**다.
  봇은 이 수를 쓰지 않으므로 대인전에서만 드러난다 → 배포 위험.
- 제안 수정: `discardAction.validate` 에 «직전 이벤트가 이 플레이어의 chi/pon 이고, 버리려는 패의 kind가
  (a) 울린 패와 같거나 (b) 치로 만든 슌쯔의 양끝 스지면 거부» 를 추가.
  (증강으로 몸통 모양이 달라질 수 있으므로 룰 스위치 `call.kuikae` 로 두는 편이 안전하다.)

## 확정 3. 🟠 오라스 **도중유국**이 아가리야메로 취급돼 게임이 끝난다 — 1위 오야가 구종구패로 종국을 살 수 있다

- 위치: `packages/core/src/match/HanchanController.ts` — `agariYameTriggers()` / `HanchanController.isAgariYame()`
  (렌짱 판정을 «정산 후 장풍·국번이 그대로인가» 로만 한다) + `packages/core/src/mahjong/flow/standardActions.ts`

- 기대: 아가리야메(+텐파이야메)는 **오야 화료** 또는 **황패유국 오야 텐파이** 에만 붙는 오야의 특권이다.

  OK   대조군: 오야 화료 → 아가리야메 종국 — reason=agariYame  (정상)

- 영향: 오라스에서 1위 오야가 배패에 요구패 9종이 오면 **한 순도 두지 않고 우승을 확정**한다

- 제안 수정: 렌짱 판정에 **국 결과**를 넣는다 — `runLoop` 이 이미 `outcome`("win"|"draw"|"abort")을

## 의심 1. 🟡 유국만관에 본장 지불(300×본장)이 붙지 않는다

- 위치: `packages/core/src/mahjong/flow/standardActions.ts` `sysSettleDraw` 의 유국만관 가산부
- 관측: 본장 2인 상태에서 유국만관이 나면 지불이 정확히 8000(자)이다. 쯔모 화료로 취급하면 8600이어야 한다.
  재현: `tsx qa-lab/round2/rules/nagashi.ts` → `⑤ 본장 2 → 유국만관에 600 가산 — deltas=-4000/8000/-2000/-2000`
- 왜 의심인가: 룰셋마다 갈리는 대목이고 `docs/01_GAME_RULES.md §6` 은 "쯔모 만관 지불"만 적었지
  본장을 언급하지 않았다. 노텐 벌부 정산에는 본장이 붙지 않는 것이 맞으므로 «유국의 일부» 로 보면 현재 동작도
  일관적이다. 결정이 필요하면 문서에 한 줄 못 박는 편이 낫다.
