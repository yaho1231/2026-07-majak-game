# QA 4라운드 — loop (판이 끝난 뒤 다시 시작하게 만드는가)

담당 관점: 대국 종료 → 다음 행동까지의 마찰, 결과 화면의 정보, 전적·리플레이,
친구·초대·재입장, 빈 로비, 이탈 지점. 코드는 전부 읽고 인용했다. 파일은 고치지 않았다.

읽은 것: `packages/client/src/App.tsx`(21,964줄), `packages/server/src/`(RoomManager,
StatsStore, SiteDb, ogMeta, pruneReplays, index, analytics), `packages/core/src/network/protocol.ts`,
`packages/core/src/stats/PlayerStats.ts`, docs/14·15·36.

### [P1] 초대 링크로 온 사람이 «계정 없이 시작»을 누르면 초대가 조용히 버려진다

- 위치: packages/client/src/App.tsx:3990-3994, 4015-4028, 5805-5821, 7375-7378
- 증상: 친구가 보낸 `?room=AB3XK7` 링크를 열면 랜딩에 «**AB3XK7** 방에 초대받았습니다 —
  로그인하면 바로 들어갑니다»가 뜬다. 그 문장 바로 옆(같은 상자 안, `landing-side`)에
  가장 큰 버튼인 «계정 없이 시작»이 있다. 계정이 없는 사람이 그걸 누르면 **친구 방이
  아니라 봇 3명짜리 체험 판**이 시작된다. 초대 코드는 아무 말 없이 버려지고, 체험이
  끝난 뒤(GuestOutro)에도 그 방으로 가는 길은 없다. 부른 사람은 대기실에서 계속 기다린다.
- 재현/근거: `authOk` 처리에서 게스트는 초대 분기보다 **먼저** 반환한다.
  ```ts
  if (guest) {
    // 홈·통계·리플레이·제보는 게스트에게 전부 막혀 있다 …
    return;                       // ← pendingInviteRef 를 보지도 않는다
  }
  …
  const invited = pendingInviteRef.current;   // 4015 — 계정 사용자만 도달
  ```
  서버도 게스트에게 `joinRoom`을 열지 않는다(RoomManager.ts:1952 화이트리스트).
  즉 게스트 경로로는 구조적으로 초대를 살릴 수 없는데, 화면은 그 사실을 말하지 않는다.
- 판정: 확정
- 제안: 초대 코드가 있는 동안에는 (a) «계정 없이 시작»을 «초대받은 방에 들어가려면
  계정이 필요합니다»로 눌러도 가입 탭으로 보내거나, (b) 최소한 게스트로 시작할 때
  «초대받은 방(AB3XK7)에는 계정으로만 들어갈 수 있습니다 — 코드를 적어 두세요» 토스트를
  띄운다. 지금은 사람이 잘못 눌렀다는 사실조차 모른다.

### [P1] 판이 시작된 뒤 도착한 초대 손님은 갈 곳이 하나도 없다

- 위치: packages/server/src/RoomManager.ts:2930-2950, 4184-4219
- 증상: 친구가 링크를 30초 늦게 열면 «이미 게임이 시작된 방입니다» 에러 토스트 하나가
  전부다. 관전도, 「다음 판까지 대기실에서 기다리기」도, 「끝나면 알려 주기」도 없다.
  30~40분짜리 반장전이면 그 사람은 그대로 이탈한다 — 부른 사람은 판 중이라 설명도 못 한다.
- 재현/근거:
  ```ts
  return this.fail(
    conn,
    "ROOM_PLAYING",
    left ? "이 방에서 이미 나갔습니다 …" : "이미 게임이 시작된 방입니다",
  );
  ```
  관전은 관리자 전용으로 막혀 있다: `private spectate(...) { if (!user.isAdmin) return
  this.fail(conn, "FORBIDDEN", "관리자 전용입니다"); }` (4185). `liveGames`도 관리자
  전용(2265). 따라서 일반 사용자에게 「진행 중인 판을 본다」는 경로가 존재하지 않는다.
- 판정: 확정
- 제안: 방에 «대기 줄»을 두거나(다음 판 자동 착석), 최소한 에러 문구에 방 코드와
  «이 방은 지금 대국 중입니다 — 끝나면 다시 눌러 보세요»를 넣고 홈의 코드 입력칸에
  그 코드를 남겨 둔다. 재시도가 6자리 재입력이 되지 않게.

### [P1] 연습 대국은 결과 화면에 «한 판 더»도 «다시 보기»도 없다 — 계정 사용자만 그렇다

- 위치: packages/server/src/RoomManager.ts:4989-5002(`guest: true`), 5893-5898(`canContinue: !room.guest`),
  5922-5931(방 즉시 삭제), packages/client/src/App.tsx:6336-6348, 21625-21645
- 증상: 공개 첫날 로비가 비어 있으면 사람이 할 수 있는 것은 «연습 대국»뿐이다. 그런데
  그 판이 끝나면 결과 화면 버튼은 «로비로» **하나**다. 한 판 더 두려면 로비로 → 홈 렌더 →
  «연습 대국» 다시 누르기. 방금 둔 판을 되돌려 볼 수도 없다(`gameId`가 없어 «이 판 다시
  보기» 자체가 안 붙는다).
  아이러니: **계정이 없는 게스트에게는** 있다 — `GuestOutro`에 «한 판 더»(App.tsx:6014).
  가입한 사람이 더 불편하다.
- 재현/근거: `practicePlay`는 `newRoom({ guest: true, … })`로 방을 만든다(4989).
  종국에서 `canContinue: !room.guest` → false, `recordedId`는 `room.sandbox || room.guest`면
  `undefined`(5893), 그리고 `room.guest`면 통계 전송 후 `this.rooms.delete(room.code)`(5930).
  클라이언트는 `canContinue`가 false면 `onContinue`를 안 넘기고(6344), `lastGameId === null`이면
  `onOpenReplay`도 안 넘긴다(6337) → 버튼은 «로비로» 하나만 남는다.
- 판정: 확정
- 제안: 결과 화면에 «연습 한 판 더»(= `practicePlay` 재전송)를 붙인다. 방을 유지할
  필요도 없다 — 새 방을 즉시 만들면 된다(게스트 경로가 이미 그렇게 한다).

### [P2] «전적이 비었으니 튜토리얼로 한 판» → 그 판은 전적에 남지 않는다 (빈 상태가 그대로)

- 위치: packages/client/src/App.tsx:10816-10829
- 증상: 내 통계 카드의 빈 상태가 «한 판 두고 나면 승률·평균 순위가 여기에 쌓입니다»라고
  적어 두고, 바로 아래 CTA로 «튜토리얼로 한 판»을 준다. 그 버튼이 여는 판은 `practicePlay`
  = 게스트 방이라 **어떤 기록도 남기지 않는다**. 시키는 대로 한 판을 두고 돌아오면 화면은
  글자 하나 안 바뀐 채 같은 문장으로 다시 맞이한다. 리플레이 카드도 마찬가지
  («한 판 두고 나면 여기에 쌓입니다» → 연습 판은 안 쌓인다).
- 재현/근거: 위 CTA는 `props.onPractice(true)`(10826) → `practicePlay` → `guest: true` 방 →
  `recordGame`·`finishStats(persist=false)` 경로로 아무것도 안 남는다(RoomManager 5893, 5922).
- 판정: 확정
- 제안: 빈 상태 CTA를 «방 만들기(봇 3명 채우고 시작)»처럼 **실제로 전적이 남는** 경로로
  바꾸거나, 문구를 «튜토리얼은 기록에 남지 않습니다 — 익힌 뒤 방을 만들어 보세요»로 잇는다.

### [P2] 결과 화면에 증강 성적이 없다 — 데이터는 이미 와 있는데 안 그린다

- 위치: packages/client/src/App.tsx:11123-11146(StatsGrid), 21600-21625(통계 탭),
  packages/core/src/stats/PlayerStats.ts:154-170(`augments`, `augmentTierPicks`)
- 증상: 이 게임의 정체성은 증강 117종인데, 판이 끝난 뒤 «내 증강이 이번 판에 뭘 했나»를
  알 방법이 결과 화면에 없다. 통계 탭이 보여 주는 것은 화료율·방총률·리치율·후로율·쯔모율·
  평균화료·평균방총·평균순위·1위율 — 전부 순수 마작 지표다. 무엇을 잘하고 못했는지가
  «화료율 25%»로만 요약된다. 증강 성적은 홈 → 전적 탭 → «내 증강 통계»(누적)로 가야 하고,
  그것도 **이번 판이 아니라 누적**이다. 게다가 연습·게스트 판은 누적에도 안 들어가므로
  그 판의 증강 성과는 어디에도 남지 않는다.
- 재현/근거: `StatsGrid`의 `rows` 배열이 열 개 지표로 고정돼 있고 `s.augments`를 한 번도
  읽지 않는다. 반면 서버가 보내는 `StatsEntry.stats`는 `PlayerStatsView extends PlayerStatsRaw`라
  `augments`·`augmentTierPicks`를 **이미 담고 있다**(PlayerStats.ts:131, 154-170).
  홈의 `PersonalAugmentStats`는 같은 필드를 쓴다(App.tsx:10852).
- 판정: 확정
- 제안: 통계 탭에 «이번 판 증강» 줄을 하나 더 붙인다 — 이미 있는 `PersonalAugmentStats`에
  `e.stats`를 그대로 넘기면 새 데이터도 새 메시지도 필요 없다.

### [P2] 대기실 전적 칩이 표본을 숨긴다 — 1국 치른 사람이 «화료 100% · 방총 0%»

- 위치: packages/client/src/App.tsx:11100-11116(StatsChips), 11647-11649(좌석에 붙는 자리)
- 증상: 대기실 좌석 이름표에 상대의 누적 전적이 «화료 33% · 방총 12% · 리치 20% · 후로 40% ·
  평순 2.50»으로 붙는다. **판수·국수가 없다.** 어제 가입해 1국을 이긴 사람은 «화료 100% ·
  방총 0%»로 서고, 같이 앉은 사람은 고수와 마주앉았다고 읽는다. 공개 첫 주는 전원이
  표본 1~3판이라 이 표시가 사실상 전부 거짓말이 된다.
- 재현/근거:
  ```tsx
  if (s.roundsPlayed === 0) return <span …>전적 없음</span>;   // 0판만 거른다
  <span className="stat-chip" title="화료율">화료 {pct(s.winRate)}</span>
  {s.games > 0 ? <span …>평순 {s.avgPlacement.toFixed(2)}</span> : null}
  ```
  같은 값을 쓰는 리더보드 표는 표본을 함께 보여 주고(«판수» 열), 결과 화면 `StatsGrid`도
  첫 칸이 판수/국수다 — 유독 사람이 서로를 재는 자리에서만 표본이 빠져 있다.
- 판정: 확정
- 제안: 칩 줄 맨 앞에 «N판» 칩을 넣거나, 표본이 적으면(예: 10국 미만) 칩 대신
  «전적 N국 — 아직 적음»으로 접는다.

### [P2] 친구를 기다리는 방은 30분 뒤 조용히 닫히고, 이미 뿌린 초대 링크가 그 순간 죽는다

- 위치: packages/server/src/RoomManager.ts:648-651, 1246-1250, 3295-3296
- 증상: 방을 만들어 링크를 보내 놓고 기다리는 동안 아무것도 누르지 않으면 30분 뒤
  «오래 비어 있어 방이 닫혔습니다»로 튕긴다. 그동안 예고가 없다. 더 나쁜 건 친구 쪽이다 —
  40분 뒤 링크를 열면 «존재하지 않는 방 코드입니다»만 본다. 카톡에 남은 링크는 계속
  그럴듯해 보이므로 다시 눌러도 같은 문장이 나온다.
- 재현/근거: `roomIdleTtlMs()`의 기본값은 `30 * 60_000`. 시계를 되돌리는 `touch(room)`는
  «대기실에서 무엇이든 눌렸다면»(3295) 등 조작이 있을 때만 불린다 — 앉아서 기다리는 것은
  조작이 아니다. 유휴 판정은 `now - room.lastActivityAt < ttl`(1247) 하나뿐이라, 사람이
  화면을 보고 있는지 여부는 계산에 들어가지 않는다.
- 판정: 확정
- 제안: (a) 남은 시간을 대기실에 적고(«25분 뒤 자동으로 닫힙니다 — 아무 버튼이나 누르면
  연장»), (b) 사람이 앉아 있는 대기실은 하트비트로 `touch`한다. 최소한 닫히기 전에 한 번
  «곧 닫힙니다»를 띄운다.

### [P2] 홈의 «새로 고침»을 몇 번 누르면 «조회가 너무 잦습니다»가 뜬다

- 위치: packages/server/src/RoomManager.ts:592-605, 2439-2450; packages/client/src/App.tsx:3862-3876, 9794-9817
- 증상: 홈에는 새로 고침 버튼이 네 개(내 통계·리플레이·전체 통계·증강 메타) 있고 **전부
  같은 `refreshHome`을 부른다**. 친구를 기다리며 «들어왔나?» 하고 10초 안에 여섯 번 누르면
  여섯 번째부터 빨간 토스트가 뜬다. 사람 입장에서는 «가만히 있는데 서버가 화를 낸다».
- 재현/근거:
  ```ts
  function refreshHome() { … send statsRequest / replayList / leaderboard / feedbackList /
                               friendList / activeGameRequest }
  const HEAVY_WINDOW_MS = 10_000; const HEAVY_MAX_PER_WINDOW = 5;   // 종류별
  if (hits.length >= HEAVY_MAX_PER_WINDOW) { … "조회가 너무 잦습니다. 잠시 후 다시 시도하세요" }
  ```
  `RefreshButton`의 쿨다운은 900ms라 한 버튼만으로도 10초에 11번까지 보낼 수 있고,
  버튼 넷은 각자 쿨다운을 따로 센다. 계정 단위 버킷이라 탭을 여러 개 열면 더 빨리 찬다.
  홈 진입(`returnHome`)도 같은 창을 먹는다 — 판을 끝내고 홈에 들어와 두어 번 누르면 바로다.
- 판정: 확정
- 제안: 새로 고침 버튼들의 쿨다운을 2.5초 이상으로 올리고 네 버튼이 **하나의** 쿨다운을
  공유하게 한다(같은 요청을 보내므로). 혹은 한도에 걸렸을 때는 에러 대신 조용히 무시한다 —
  사람이 고칠 수 있는 것이 아무것도 없는 에러다.

### [P2] 빈 로비: 혼자 들어온 사람에게 «지금 여기 사람이 있나»를 말해 주는 것이 하나도 없다

- 위치: packages/core/src/network/protocol.ts:1185-1212(ServerInfoMessage), RoomManager.ts:2264-2266, 4185
- 증상: 공개 첫날 가장 흔한 상태다. 홈에는 방 만들기 / 코드 입력 / 튜토리얼 / 연습 대국,
  그리고 «친구» 카드가 있다. 친구가 0명인 새 사용자에게는 접속자 수도, 공개 방 목록도,
  진행 중인 판 관전도 없다. 이 사람이 «지금 아무도 없구나»를 알 방법은 **방을 만들어
  놓고 아무도 안 오는 것을 5분간 확인하는 것**뿐이고, 그마저 30분 뒤 방이 닫힌다(위 항목).
- 재현/근거: `ServerInfoMessage`의 필드는 `signupGate`·`guestPlay`·`augmentKinds`·`notice`
  넷뿐 — 온라인 수가 없다. 공개 방 목록 메시지는 프로토콜에 존재하지 않는다
  (`grep -n "roomList\|publicRoom\|quickMatch"` → 0건). `liveGames`·`spectate`는 둘 다
  `if (!user.isAdmin) return this.fail(… "관리자 전용입니다")`.
- 판정: 확정
- 제안: 최소 한 줄 — 홈 상단에 «지금 접속 N명 · 진행 중 M판». 숫자가 0이면 0이라고 적는
  편이 «아무 정보 없음»보다 훨씬 낫다(그때 «연습 대국»이 자연스러운 다음 걸음이 된다).
  여유가 있으면 진행 중인 판의 **관전을 일반에게 열거나**(docs/36의 송출 지연 설비가 이미
  있다) 대기 중인 공개 방 목록을 준다.

### [P3] 1판 뒤 «1위율 100% · 평균순위 1.00» — 결과·홈 어디에도 표본 경고가 없다

  그래도 큰 숫자는 100%다. 리더보드 표는 `games > 0`·`roundsPlayed > 0`만 거를 뿐 표본이
  1이어도 그대로 %를 찍는다(10890-10896).
- 판정: 확정(경미)
- 제안: 표본이 임계(예: 20판/50국) 미만이면 값 옆에 «(표본 적음)» 표시나 회색 처리.

### [P3] 리더보드가 «판수 순»이고 비관리자에게는 아예 보이지 않는다 — 돌아올 이유가 없다

- 위치: packages/server/src/RoomManager.ts:3778-3785, packages/client/src/App.tsx:10855-10899
- 증상: 서버는 비관리자에게 닉네임을 지운 사본을 주고, 클라이언트는 `props.auth.isAdmin`일

  정렬도 `b.stats.games - a.stats.games`(활동량)이라, 관리자에게조차 실력 순위가 아니다.
  「다시 시작하게 만드는 것」의 고전적 장치 하나가 통째로 비어 있다.
- 판정: 확정 (설계 결정일 수 있음 — 기록만)
- 제안: 공개 여부는 운영 판단이지만, 최소한 **본인 기준**의 진행 표시(«최근 30일 평균순위가
  2.6 → 2.3»)는 이미 `PeriodStatsRow`가 데이터를 갖고 있다. 지금은 나열만 하고 «나아졌다»를

### [P3] 리플레이 목록 한 줄에 «어느 판이었는지»를 떠올릴 단서가 날짜뿐

- 판정: 확정
- 제안: 최종 점수(±)와 모드, 가능하면 그 판의 대표 증강 1~2개를 행에 싣는다.

### [P3·의심] «이어하기» 직후 짧은 창 동안 대기실이 낡은 상태로 그려져 «시작»이 먹지 않는다

- 위치: packages/client/src/App.tsx:3784-3815(`continueInRoom`), packages/server/src/RoomManager.ts:5936-5944, 3402-3407
- 증상(추정): «이어하기»를 누르면 클라이언트는 `view`만 비우고 곧바로 대기실을 그린다.
  그런데 서버의 `resetRoomAfterGame`(→ `broadcastLobby`)은 `finishStats(...)`의 `.finally`에서
  돌기 때문에 통계 파일 저장이 끝난 뒤에야 실행된다. 그 사이 화면은 **판 시작 전의 lobby
  스냅샷**(준비 완료 표시가 켜진 채)을 그대로 쓰므로, 방장이 «시작»을 누르면 서버는 아직
  `phase === "playing"`이라 그 메시지를 대기실 처리기로 보내지 않는다 → **아무 일도
  일어나지 않고 에러도 없다.**
- 재현/근거: `continueInRoom`은 `lobby` 상태를 건드리지 않는다(setView(null)만).
  서버 `handleLobbyMessage`의 `startGame`은 `if (room.phase !== "waiting" || …) return;`
  — 조용한 반환이다. 창의 길이는 `statsStore.record`의 파일 쓰기 시간(보통 수 ms)이라
  평소에는 안 보일 수 있다. 디스크가 느리거나 통계 파일이 커지면 길어진다.
- 판정: 의심 (코드 경로는 확인했으나 실측하지 않았다)
- 제안: `continueInRoom`에서 `lobby`를 `null`로 비워 «대기실 준비 중…»을 그리게 하거나,
  서버가 `gameOver` 직후 즉시 대기 상태 lobby를 한 번 보낸다.

### [P3] 연습 대국은 동풍전 고정 — 반장전을 연습할 방법이 없다

  익힌 감각이 실전과 어긋난다.
- 판정: 확정
- 제안: 연습 버튼 옆에 모드 토글 하나. 서버는 이미 `mode` 인자를 받는다.

의심 1건: «이어하기» 직후 낡은 대기실에서 «시작»이 무반응(App.tsx:3784 / RoomManager.ts:3403).

없다고 적어 두는 것: 대국 종료 → 같은 사람과 한 판 더(방 유지)의 **클릭 수 자체는**
문제가 아니다 — «이어하기» 1회 + (방장 아닌 사람) «준비» 1회 + 방장 «시작» 1회이고,
봇은 자동으로 준비 상태이며 지난 판 좌석·봇이 그대로 남는다(`resetRoomAfterGame`).
재접속 흐름(`activeGameRequest` 재질의, 닉네임 기준 좌석 복귀)도 이번 관점에서
끊긴 데를 찾지 못했다.
