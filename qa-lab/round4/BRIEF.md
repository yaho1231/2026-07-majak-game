# QA 4라운드 브리핑 (2026-08-23) — 공개 직전 "완성도" 감사

사용자 지시: 게임 완성도 QA. 불편한 점·문제점을 다양한 관점에서 날카롭게 공격해 찾아라.
공개(클라이언트 전달) 직전 마지막 점검이다.

## 앞선 라운드와 다르게 볼 것
- 1~3라운드(docs/36·37·39·40)는 **크래시·룰 정확성·증강 시너지 의미**를 이미 훑었다.
  같은 것을 또 찾지 마라. 이미 문서에 적힌 확정건을 다시 보고하면 감점이다.
- 이번 축은 **완성도**다: 처음 오는 사람이 겪는 마찰, 손이 미끄러지는 UI, 설명이 없는 화면,
  실패했을 때 아무 말도 안 하는 경로, 느린 곳, 모바일에서 깨지는 곳, 운영 중 조용히 죽는 곳.

## 보고 형식 (엄수)
`qa-lab/round4/<담당>.md` 에 쓴다. 각 항목:

```
### [심각도] 한 줄 제목
- 위치: packages/x/src/y.ts:123
- 증상: 사용자가 실제로 겪는 것 (추상적 "개선 여지" 금지)
- 재현/근거: 코드 인용 또는 실행한 스크립트와 그 출력
- 판정: 확정 / 의심
- 제안: 구체적 수정 방향
```

심각도: P0(공개 불가) P1(공개 전 고쳐야) P2(고치면 좋음) P3(기록만).

## 규칙
- **추측 금지.** 코드를 읽고 인용하거나 실제로 돌려 본 것만 "확정"으로 올린다.
- 파일을 고치지 마라. 이번 단계는 조사와 보고만이다.
- 마지막에 확정건을 심각도순으로 요약 표로 정리한다.
- 없으면 없다고 써라. 억지로 채우지 마라.
