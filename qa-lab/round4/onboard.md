# QA 4라운드 — onboard (처음 온 사람이 첫 판을 끝낼 때까지)

관점: 마작을 모르는 사람이 랜딩 → 가입/게스트 → 로비 → 방 → 튜토리얼 → 첫 대국 →
증강 드래프트 → 결과 화면까지 가는 길. 코드를 읽고 인용한 것만 «확정»으로 올린다.

전제: 이 경로는 이미 여러 번 손을 봤다(감사 2026-08-17 · QA 2차 onboard · docs/35).
그래서 아래는 **아직 남아 있는 구멍**만 적는다. 이미 고쳐진 것(대기실 규칙 버튼,
게스트 종료 화면 튜토리얼 버튼, 폼 안에 남는 인증 오류, 드래프트 «랜덤으로 결정된다»
문구 …)은 다시 올리지 않는다.

---

### [P1] «바로 한 판»(게스트 체험)은 실전과 같은 30초 제한을 받는다 — 코드가 스스로 "30초로는 못 읽는다"고 적어 놓은 그 자리
- 위치: packages/server/src/HumanAgent.ts:1040-1048, packages/server/src/HumanAgent.ts:20,65 / packages/client/src/App.tsx:5807-5821
- 증상: 랜딩의 두 문 중 하나인 «바로 한 판»(계정 없이 봇 3명)은 코치가 붙지 않는
  일반 판이다. 그런데 판이 시작하자마자 증강 드래프트가 뜨고(첫 스테이지가 «대국
  개시 동1국», App.tsx:8179), 처음 보는 증강 카드 3장을 **30초** 안에 읽고 골라야
  한다. 못 고르면 서버가 무작위로 집는다. 마작도 증강도 처음인 사람이 정확히
  이 문으로 들어온다.
- 재현/근거: 제한 시간을 정하는 자리의 주석이 문제를 그대로 적고 있다.
  ```ts
  // HumanAgent.ts:1040-1048
  /**
   * 증강 선택의 제한 시간(ms).
   *
   * 튜토리얼에서 이 값이 가장 중요하다 — 시간이 다 되면 서버가 후보 중 하나를
   * **무작위로** 집는데(`armDraft`), 카드 셋을 읽는 데만 30초가 넘게 걸린다.
   */
  private draftTimeoutMs(): number {
    return this.tutorial ? TUTORIAL_DECISION_TIMEOUT_MS : DECISION_TIMEOUT_MS;
  }
  ```
  `DECISION_TIMEOUT_MS = 30_000` (:20), `TUTORIAL_DECISION_TIMEOUT_MS = 30 * 60_000` (:65).
  게스트 체험은 `tutorial=false`다 — App.tsx:5821 `send({ type: "guestPlay" })`
  (같은 화면의 «튜토리얼» 버튼만 `tutorial: true`를 보낸다, :5827).
  결론: **"카드 셋을 읽는 데만 30초가 넘게 걸린다"는 판단이 튜토리얼에만 적용되고,
  똑같이 처음 온 사람인 게스트에게는 적용되지 않았다.**
- 판정: 확정
- 제안: 처음 온 사람이 들어오는 판(게스트 체험 · `practicePlay` 연습 대국)의 **첫
  드래프트 한 번만** 넉넉히 준다(예: 90초). 판 전체를 늘릴 필요는 없다 — 두 번째
  스테이지부터는 이미 카드를 한 벌 읽어 본 뒤다.

### [P1] 처음 화료한 그 화면에서만 코치가 입을 다문다 — 점수를 아무도 설명하지 않는다
- 위치: packages/client/src/tutorial.ts:884-893, packages/client/src/App.tsx:21053-21054
- 증상: 튜토리얼의 목표는 «리치 → 화료»다(tutorial.ts:853). 그런데 화료하는 순간
  뜨는 정산 화면에서는 마무리 강의 말고 **어떤 강의도 뜨지 못하게 막혀 있다.**
  화면에는 「핑후 1판 · 탕야오 1판 … 3판 30부」와 「우마 +15 · 오카 +20」이 뜨는데,
  역 이름에는 용어 링크조차 걸려 있지 않다. 처음 온 사람이 자기가 왜 이겼고 왜
  8700점인지 물어볼 곳이 그 자리에 하나도 없다.
- 재현/근거:
  ```ts
  // tutorial.ts:884-893
  function allowedNow(c: CoachCtx, lesson: Lesson): boolean {
    return !c.roundOver || lesson.id === "outro";
  }
  ```
  `roundOver`는 정산 화면이 떠 있는 동안 참이다(App.tsx:6162 `roundOver: roundResult !== null`).
  그리고 역 이름은 일부러 용어집에서 뗐다:
  ```tsx
  // App.tsx:21053-21054
  {/* 역 이름은 그냥 이름으로 둔다 — 결과 화면은 점수를 읽는 자리다.
      줄줄이 밑줄이 그어지면 어느 역이 큰지가 안 보인다. */}
  ```
  「부(符)」는 정산 패널 어디에서도 풀이되지 않는다(용어집에는 있다).
  대조: 판 끝 화면(GameOverModal)의 우마·오카는 `TermText`를 통과한다(App.tsx:21556-21565) —
  같은 판단이 정산 화면에는 적용되지 않았다.
- 판정: 확정
- 제안: 둘 중 하나. (a) `allowedNow`에 정산 화면 전용 강의 하나를 더 허용해
  "판 = 역의 크기, 부 = 손 모양의 잔점수, 아래 숫자가 실제로 오간 점수"를 짚어
  준다. (b) 최소한 「N판 M부」 원과 「우마·오카」 줄만이라도 용어 링크를 건다
  (역 이름 줄줄이 밑줄 긋는 것과 달리 여기는 한 자리뿐이라 위 주석의 이유가 안 걸린다).

### [P1] 뒤로가기·새로고침에 대한 방어가 클라이언트 전체에 하나도 없다 — 게스트는 판이 통째로 사라진다
